# "详见第8条""见附件3"指的到底在不在,「交叉引用核对」帮你查

长文件里到处是"详见第 X 条""见附件 Y""如图 3 所示"。改着改着,被引的那一条删了、附件没附上、图表编号错位,引用就成了死链。读者按图索骥找不到,文件就露怯了。「交叉引用核对」是察元AI文档助手里专查这种死链的助手。

**它核什么**
"详见第 X 条/章/款"——被引的条章款在不在;"见附件 X/附录 Y"——对应附件有没有出现或列明;"如图 X/见表 N"——图表编号在不在、对不对得上;"上文/下文所述"——所指内容是否真实存在。

**谁用得上**
写合同、标书、制度文件、技术文档、论文这类条款多、引用多的长文件的人。

**用起来**
WPS 装"察元AI文档助手",打开文件,在"文档核对"分类或搜"引用"找到它,点运行读全文。失效或可疑的引用处贴批注,标明问题(被引对象不存在/编号不对应/指代不明)。

**为什么它读全文**
引用在前、被引在后,常常隔很远。这个助手运行时把整篇当一块读,就是为了能把"第 8 条在哪"这种跨段的事查准,不因分块漏掉。

**结合知识库**
引用的是外部标准/附件库的,把那些放进知识库,用"引文知识库核验"助手去核外部出处在不在。

**改它**
默认通用。你的文件有特殊引用格式(如"参见 §3.2"),可在提示词里告诉它。

**模型**
中档以上对话模型,长文选上下文大的。

**和超级智能体配合**
单篇查死链在 WPS 里做;要体检整套制度文件的交叉引用,交给桌面端察元AI超级智能体。

定稿前查一遍,别让一个"详见第 X 条"指向一个已经被删掉的地方。
