# 助手教程网文 — 写作规范

为每个内置助手写一篇独立教程网文。统一规范如下。

## 命名(对外一律用统称)
- 察元AI文档助手 = WPS 加载项(本仓库 chayuan-wps)
- 察元AI超级智能体 = 桌面端(chayuan-desktop)
- 不出现内部 repo 名、不出现"大模型/LLM"等黑话(说"模型"即可)。

## 每篇必须覆盖的信息点(顺序可调、按助手自然编排,不要一个模子)
1. 这个助手是干什么的、替谁解决什么具体问题
2. 适应的场景(具体岗位 + 具体痛点,给一个真实例子)
3. 下载与安装(装"察元AI文档助手"WPS 加载项)
4. 在哪找到它(领域分类 / 搜索关键词 / 收藏置顶)
5. 怎么用、怎么运行(选区还是全文、点运行,结果怎么呈现——批注/插入/JSON)
6. 一次真实的输入→输出示例
7. 结合知识库能多做什么
8. 怎么修改这个助手(改提示词 / 默认动作 / 适配自己场景)
9. 大模型的选择(该配什么档位、为什么)
10. 与察元AI超级智能体的结合使用
11. 能达到的效果 / 收尾(一句话,不喊口号)

## 反"AI 味"硬规则
- 开头禁止"随着…的发展""在当今…时代""值得一提的是""总而言之"。直接说事。
- 不堆排比、不凑四字短语、不无意义加粗、不滥用破折号。
- 每个卖点要落到具体动作/具体例子/具体数字,不要空泛形容词。
- 句子长短交错,允许口语,像懂行的人跟同行讲话。
- 同一批文章开头/小标题要换花样,别千篇一律。

## 按助手类型的侧重
- 生成类(文案/起草):重点写"输入什么→产出什么成稿""怎么改立场/风格"。
- 核查类(审查/对照):重点写"挑出什么坑→批注贴在哪→怎么按知识库挑"。
- 抽取类(JSON):重点写"喂什么→得到什么结构化结果→下游怎么用"。
- KB 对比类:重点写"绑定知识库后能做什么单文档做不到的事"。

## 模型选择通用口径(各篇据此具体化)
- 判断/推理重(合同审查、逻辑核对):中高档对话模型。
- 文案/创意:中档对话模型即可,温度偏高已内置。
- 抽取/格式化:轻量到中档,稳定优先。
- 长文档:选上下文窗口大的模型。模型在察元"模型设置"统一配置。

## 与察元AI超级智能体的结合(通用框架,各篇据此具体化)
文档助手在 WPS 里做"当下这一篇"的精细活;超级智能体在桌面端做"成批、跨文档、
导出台账、接知识库做更重检索"的活。两端共用同一套授权与知识库。

## 文件组织
`docs/assistant-tutorials/<domain>/<助手短ID>.md`,每篇一个文件,独立成文。
