## 三级生图端到端实证（真实网络）

1. **Tier1 模型生图**（新增接线）：agent 循环的 `generate_image` 先走设置页启用的图像生成模型（`mediaApi.generateImageAsset` 逐个尝试，百炼原生/OpenAI 兼容双通道）→ 产物经 sidecar `/tmp-image` 落盘 WPS 容器可读路径；未配置/全败 → 回落 sidecar 原生 `image-gen.json` 通道 → 仍败返回 `ok:false`。
2. **Tier2 网络搜图**（本次升级）：`image_search` 按 `web-resources.json` 的启用清单顺序走 keyed 资源（Serper/Tavily/SearXNG/Pexels/Pixabay/Unsplash，各按协议实现）→ 免 Key 兜底（必应 → Openverse）。
   **真实链路实证**：MCP `tools/call image_search {"query":"黄山 云海 风景"}` → serper(假key) 403 → 必应真搜命中 → 下载 **948KB / 2560×1920 真实 JPEG** 落盘，`origin:"bing"`。
3. **Tier3 SVG**：既有 `svg_add` 矢量兜底 + 配图策略提示词铁律（上级 ok:false 才降级、禁止跳级）。

## 已知边界

- 内嵌浏览器（ZCode IAB）宿主在本轮验收中多次 webview 崩溃（"guest not attached"），V1–V5 通过单单元流程完成截图；V6 与 Tier2 真实链路走 API 层实证（同一代码路径，curl + MCP 协议直调）。
- DuckDuckGo 测活显示 NETWORK_ERROR：其 HTML 端点对本机数据中心的 fetch 拒绝，属预期（它只做网页搜索兜底，不参与搜图）；Openverse 依赖海外网络。
- SearXNG 的「API Key」位填实例地址（服务地址栏），设计如此（对齐 chayuan-office）。

## 布局返工（2026-10-12 用户反馈：窄设置窗口卡片内容全部换行）

问题：原双列卡片在 WPS 设置窗宽度（第三列 ~600px）下每卡仅 ~280px，头部「名称+标签+测活点+开关」全部堆叠换行，末行结果文字溢出。

修复（V07/V08 截图）：
1. 卡片默认**单列宽行**（`grid-template-columns: 1fr`，视口 ≥1500px 才两列）——对齐 KB 设置面板的行式布局；
2. 头部强制单行：`flex-wrap: nowrap`，窄卡时**名称截断省略**（标签/测活点/开关永不换行不收缩）；
3. 说明单行省略；keyed 卡的配置区**仅启用或已填过时展开**（Key/地址双列并排，省纵向空间）；
4. 末行「申请 Key |←弹簧→| 测试 结果」：结果右对齐、46% 宽省略，全文入 title 悬浮；
5. 错误短文案映射：`The operation was aborted`→「超时」、`401/403`→「Key 无效」、网络错误→「网络不可达」。

窄窗口（1000px，第三列 ~620px）实测：头部行高恒 26px、单列 574px 宽卡片、结果右对齐省略。
