# 一台内网 GPU，全科室共用：察元 + Ollama 校对引擎怎么搭，密钥不出科室

> 本文是"三发组合拳"的**第二发，主打实用价值**：一台内网 GPU 机器，变成全科室共享的校对引擎。情绪与故事那一发见《周五送审，稿子却不能上公网：机关内网里的国产 WPS 自动审查》；纯操作教程（本机 MCP 全链路、一周试点）见《内网离线用 Ollama 审 WPS：本机 MCP 与察元 v4.0 全链路》。本专栏其他文章可在 CSDN 搜标题找到。

一句话：**不要让每个科员都在自己电脑上跑一遍 Ollama。** 把推理集中到一台内网 GPU 机器，办公机只填一个内网地址——密钥不出科室，文档不出本机。

## 一、信息中心小张的下午：五个科室，五份 Ollama

小张被叫去给五个科室"装 AI"。跑了一圈，他看到的是这样的画面：

- 每台办公机都在本机跑 Ollama，CPU 风扇狂转，校对慢得像排队；
- 机房那台带 GPU 的机器，闲着；
- 有人把个人云模型密钥写在便签上贴显示器边，有人填在科室共享文档里；
- 五个科室五种配置，模型名都不一样，审出来的结果没法横向比。

小张的问题不是"AI 不好用"，是"**部署方式不对**"。机关里真正稳的形态，从来不是人手一个本地模型各自为战，而是**一台共享推理机 + N 台办公机填同一个内网地址**。这篇就讲怎么搭这条线，以及为什么搭完，密钥自然就不出科室了。

## 二、先分清两件事：共享的是模型，不是文档

这是全文最容易踩的坑，先讲清楚，后面所有步骤都围着它转。

机关里**能共享**的，是**模型推理端点**——Ollama 的 `11434`：一台 GPU 机器跑模型，所有办公机都来调它做校对。

机关里**不能共享**的，是**文档 MCP**——察元的 `62588`：它始终绑在每台办公机的 `127.0.0.1`，只负责读写**那台机器上 WPS 里正打开的稿**。

> 一句话记住：**模型走内网共享，文档在本机闭环。推理可以集中，稿件不能集中。**

谁要是把 62588 也映射到局域网，"方便大家连同一份稿"——那是把"本机助手"变成"未鉴权文档接口"，方向彻底错了。边界详见《confirmed 确认策略与 localhost 信任边界》。记住这条区分，下面的配置就不会搞反。

## 三、架构：一台推理机 + N 台办公机

三块，关系很简单：

- **推理机**（机房那台 GPU 机器）：跑 Ollama，加载中文对话模型，监听内网网卡。
- **办公机**（科员用的电脑）：WPS + 察元加载项 + 本机 MCP（`127.0.0.1:62588`）。模型设置里填推理机的内网地址。
- **客户端**（可选，如 Claude Code）：连本机 `62588`，指挥当前文档，不连推理机。

模型流量走向：办公机 → 内网 → 推理机，再原路返回。文档正文走向：始终在办公机的 WPS 里，哪儿也不去。

## 四、推理机：让 Ollama 监听内网（最小步骤）

1. 装好 Ollama，拉取单位批准的中文对话模型：`ollama pull <model>`。
2. 让它监听内网网卡，而不是只听本机。设环境变量重启服务：

   ```bash
   OLLAMA_HOST=0.0.0.0:11434
   ```

   更可控的写法是绑具体内网 IP：`OLLAMA_HOST=10.x.x.x:11434`，按单位网络规范选。
3. 防火墙只放行内网网段，**绝不对公网开放**；内网 ACL 按最小授权。
4. **在办公机上**（不是在推理机上）测连通：

   ```bash
   curl http://<推理机内网IP>:11434/v1/chat/completions \
     -H "Content-Type: application/json" \
     -d '{"model":"<模型名>","messages":[{"role":"user","content":"测试"}]}'
   ```

   返回非空回复，算推理机就绪。**这一步在办公机上失败，不要进入察元设置**——先打通网络，再谈模型。

完全离线（连内网都没有）的单位，参考《内网离线用 Ollama 审 WPS：本机 MCP 与察元 v4.0 全链路》的模型导入法，把权重搬进推理机，最终 `ollama list` 能看到模型、能推理即可。

## 五、推理机上跑什么模型：选型四条

Ollama 配通了、能推理了，不等于校对好用。"配通了却审不出错"是仅次于 `MODEL_NOT_CONFIGURED` 的第二大坑，多半是模型选错了。下面四条是小张跑完五个科室总结出来的：

**1. 选对话模型，不要嵌入模型。** Ollama 里既有对话（chat/instruct）模型，也有嵌入（embedding）模型。嵌入模型是把文字变成向量、给检索和 RAG 用的，**它根本不会"校对"**。察元默认对话模型那一栏，必须选对话类。选成嵌入模型，能跑、不报错，但审稿永远空——这是最隐蔽的错配，排查时往往怀疑端口，其实坏在选型。

**2. 中文能力优先，别用纯英文模型。** "的地得"、同音别字、姓名职务前后一致、公文序号——这些是中文校对的主战场。纯英文或中文语料不足的模型，对这些基本无感。选在中文上训练充分的对话模型，比选参数最大的模型更重要。

**3. 体量够用就行，别追最大。** 太小（个位数 B 以下的小模型）容易漏错、还爱凭空乱改；太大则占显存、多人排队慢。中文校对的甜点，常落在中量级中文对话模型上，一台机房 GPU 量化跑（Q4 左右）就能稳定服务一个科室。机关要的是**稳定、可复现、不乱改**，不是 benchmark 第一——一个能稳定挑出同音别字的中量级模型，比一个偶尔幻觉改写的大模型更合用。

**4. 换模型必回归。** 不管是换体量、换量化精度，还是从云端切到本地，都用**同一份故意造错的测试稿**回归：看它能不能召回你埋下的错别字、同音字、表格错字。回归失败先查模型，再查提示词——别先怀疑端口或 MCP。

> 一个判断标准：客户端模型广场筛"对话"能力能列出一批候选；本地 Ollama 则以单位已批准的中文对话模型为准。两者都遵循上面四条。选型定下来后冻结配置，禁止每人私自改基础 URL 和模型名——这是小张跑完五个科室后写进规范的第一条。

## 六、办公机：察元模型设置填一个内网地址

1. 打开察元设置 → 模型与供应商。
2. 新增或启用一家 OpenAI 兼容供应商。
3. 基础 URL 填：`http://<推理机内网IP>:11434/v1`。
4. 密钥：纯 Ollama 常可留空或填占位（以界面校验为准）。**用内网网关（OneAPI/Xinference）时，密钥由信息中心统一发，不进便签、不进共享文档、不进截图。**
5. 模型名填推理机上 `ollama list` 看到的名字；默认对话模型必须选**对话类**（见上一节），别误选纯嵌入模型——嵌入模型能跑却审不出问题。
6. 保存后，加载项内跑一次「拼写与语法检查」，能出问题列表，才算配通。

配通的表现是"能审稿"。配不通的典型报错是 `MODEL_NOT_CONFIGURED`：**注意，这时 MCP 是好的，坏的是模型链路**。别去重装客户端，回模型设置查 URL、模型名、默认对话模型这三项。

## 七、验收五步（每台办公机都过一遍）

```text
1. 浏览器开 http://127.0.0.1:62588/healthz        → online
2. 加载项内「拼写与语法检查」                       → 出问题列表
3. 客户端连 127.0.0.1:62588/mcp，下只读冒烟          → 能读不报错
4. 下预览指令，只要问题列表，不改正文                → 出分级列表
5. 回「确认写批注」                                  → 批注钉在具体字上
```

五步全绿，才交给业务用户。**顺序反了，会把"模型没配"和"MCP 没起"搅成一团**——这是小张跑五个科室那天，最常踩的坑。

## 八、密钥不出科室：四条纪律（建议写进信息中心规范）

这四条是"敢推广"的前提，也是这篇能被转的社交货币——转发它的人，显得既懂部署又懂合规：

1. **优先内网 Ollama，零密钥。** 纯本地 Ollama 不需要任何云密钥，从根上消除密钥泄露面。这是选 Ollama 最被低估的好处。
2. **网关密钥信息中心统管。** 用 OneAPI/Xinference 做统一网关时，密钥按人按岗发，办公机用完即清，**不常驻公共机**。
3. **密钥不进聊天、不进截图、不进工单。** 脱密还原密码同理；丢失密码等于还原失败，是预期行为，不是故障。
4. **公共演示机当日清场。** 用毕清理模型密钥与对话历史，下一个人接手前是干净状态。

守住这四条，"全科室共享一个校对引擎"才不会变成"全科室共享一个泄露口"。

## 十、常见故障快查

- **`MODEL_NOT_CONFIGURED`**：能读文档，一审就失败。回模型设置查 URL、模型名、默认对话模型；用加载项内检查验证。这是模型链路问题。
- **"配通了却审不出错"**：多半选了嵌入模型，或中文能力不足。回第五节核对选型四条。
- **`WPS_AGENT_OFFLINE`**：列不出工具。这是 **Agent 通道**问题（WPS 没开 / 加载项没加载），**与模型无关**，别去查 Ollama。
- **`CONFIRMATION_REQUIRED`**：预览成功，写批注被拒。补一句「确认写批注」，让客户端带 `confirmed=true`。这是设计，不是故障。
- **连不上推理机**：办公机 curl 超时。查推理机 `OLLAMA_HOST`、防火墙、内网 ACL；先确认是网络问题，再查模型。
