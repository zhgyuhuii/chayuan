# 察元 AI 文档助手 v4.0 全生命周期：从安装到 Claude 自动审查

要用 Claude Code 审查本机 WPS 里的公文、制度或合同，链路只有三段：装好察元加载项并真正打开 WPS；在加载项里配好校对用的对话模型并自测通过；把 Claude Code 接到本机 MCP 服务 chayuan-wps-mcp，按「先预览、再确认写批注」跑完整闭环。本文按安装当天的真实顺序写，命令可复制，失败现象按层排查。

![全链路示意：WPS察元、本机62588、Claude Code](images/csdn-01-1.png)

## 先把预期说清楚

Claude Code 负责听指令、拆步骤、调用工具。察元负责在 WPS 里读段落、定位原文、写批注、在确认后替换。本机 MCP 地址固定为：

```
http://127.0.0.1:62588/mcp
```

健康检查：

```
http://127.0.0.1:62588/healthz
```

服务名统一写成 chayuan-wps-mcp。默认只监听本机回环地址，不需要 Token。文档审查不是「一句话改完美」：稳妥顺序始终是预览问题列表、人工确认、再写批注或改正文。涉密与定稿以人工和单位制度为准。

MCP 协议背景可对照官方说明：[Claude Code MCP 文档](https://code.claude.com/docs/en/mcp)。端口、sidecar 与无 Token 设计见本系列专文：[本机 MCP 端口 62588 与 chayuan-wps-mcp](./02-mcp-localhost-chayuan-wps-mcp.md)。模型配置失败时见：[模型与供应商配置](./03-model-provider-setup-proofread.md)。

## 下载安装包

发行渠道以项目说明为准，常见入口：

- 官网：[https://aidooo.com](https://aidooo.com)
- GitHub 发布仓：[https://github.com/zhgyuhuii/chayuan-wps-releases](https://github.com/zhgyuhuii/chayuan-wps-releases)
- 源码仓：[https://github.com/zhgyuhuii/chayuan.git](https://github.com/zhgyuhuii/chayuan.git)

按操作系统下载对应安装包。v4.0 起常见文件名形态为：

- Windows：`chayuan-4.0.0-windows-x64.exe`（自解压安装器）
- macOS：`chayuan-4.0.0-macos-arm64.pkg`（或对应架构）
- Linux：`chayuan-4.0.0-linux-x64.deb`（或对应架构）

版本号以你下载到的为准。安装包会安装 WPS 文字加载项，并带上本机 MCP sidecar 二进制，一般注册开机自启，日常使用不必再单独装 Node.js。

![发布页三平台安装包列表](images/csdn-01-2.png)

### Windows 安装注意点

双击 exe，按向导完成。装完打开 WPS 文字，看功能区或任务窗格是否出现察元相关入口。若没有，到 WPS 的加载项管理中确认已启用。只装包从不打开 WPS，Agent 往往未注册，后面 Claude 会报 WPS 离线一类错误。

### macOS 与 Linux 安装注意点

macOS 打开 pkg 完成安装，按系统提示处理权限。Linux 用 deb 安装后打开 WPS 文字，确认加载项在线。桌面环境差异较大，以实际能打开任务窗格为准。旧版本残留路径与当前版本混用时，表现为 healthz 通但工具调用失败：关掉 WPS，确认 sidecar 只有一份在跑，再重新打开文档。

![WPS中察元入口首次出现](images/csdn-01-3.png)

## 确认本机 MCP 已起来

浏览器访问 [http://127.0.0.1:62588/healthz](http://127.0.0.1:62588/healthz)，期望看到在线或 online。再记住 MCP 入口 [http://127.0.0.1:62588/mcp](http://127.0.0.1:62588/mcp)。

打开察元设置里的 MCP 服务页，刷新状态。若显示未启动，按界面提示启动本机服务。有 Spike 或自检的版本，可跑一遍，确认 sidecar、Agent、活动文档相关状态正常。

连不上时按顺序查：WPS 是否打开；察元是否加载；62588 是否被占用；是否误把地址写成了局域网 IP 却未做代理。默认安装只绑 127.0.0.1。

![浏览器healthz返回在线](images/csdn-01-4.png)

## 配置模型：卡在这一步的人很多

MCP 通了，不等于校对一定成功。拼写与语法检查、结构化自动审查依赖察元设置里的对话模型。可走两类路：

- 离线或内网：Ollama、LM Studio、Xinference、OneAPI、New API 等 OpenAI 兼容端点。在设置中填基础 URL、密钥（若有）、选用对话模型。
- 云端：按单位合规要求配置可用供应商与 API 密钥。密钥按人按岗最小授权，公共电脑慎用个人密钥。

操作建议：打开察元设置进入模型与供应商相关页；启用至少一家供应商并保存；选定默认对话模型，类型必须是对话，不要误选纯嵌入或图像模型；用一小段测试文字，在加载项内先跑「拼写与语法检查」，确认能出问题列表或批注。

这一步通过后，再让 Claude Code 调校对，排错时才能分清是「模型没配」还是「MCP 没连上」。

![模型与供应商设置页密钥打码](images/csdn-01-5.png)

### 加载项内先做一次检查

新建或打开一份测试稿，故意留下两三个错别字、一处中英文标点混用。在察元入口执行拼写与语法检查。观察是否出现问题列表、批注是否钉在错字附近、表格里的错字是否挂到具体文字而不是整格。也可以只用加载项完成日常审查，不必强行上 Claude。Claude 的价值在于多步编排、多文档、边聊边审。

## 给 Claude Code 安装 MCP

确认 WPS 已打开、healthz 在线后，在终端执行：

```
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

也可在项目根或用户级 `.mcp.json` 写入服务名 chayuan-wps-mcp，url 填上面的地址。说明：transport 用 http；不要配成 stdio；不需要 Token。保存后重启 Claude Code，或按客户端方式刷新 MCP 列表。

![终端执行claude mcp add完整输出](images/csdn-01-6.png)

## 四级验收：列表、工具、只读、校对

### 第一级：列表可见

在 Claude Code 的 MCP 列表中能看到 chayuan-wps-mcp，状态为已连接或可用。

### 第二级：工具可见

展开后应能看到与文档相关的工具，例如状态查询、打开文档、读段落或分块、定位、替换、批注、校对预览、写成批注等（具体名称以当前版本工具列表为准）。

### 第三级：只读冒烟

WPS 中打开测试稿，对 Claude Code 说：通过 chayuan-wps-mcp 告诉我当前活动文档的文件名和大概字数，不要改正文，不要写批注。若回报与标题栏一致，说明读写桥通了。

### 第四级：审查预览冒烟

再说：对当前文档做校对预览，列出错别字和标点问题，不要写批注，不要改正文。若返回问题列表，说明校对链路通了。若报模型未配置，回到模型配置节。若报 WPS 离线，回到安装与 healthz 节。

![校对预览返回的问题列表](images/csdn-01-7.png)

## 日常自动审查流程

1. 在 WPS 打开待审文件，重要稿先另存副本。
2. 确认 healthz 在线、Claude Code 已挂上 chayuan-wps-mcp。
3. 粘贴开场白，先只要预览。开场白全集见：[自动审查提示词库](./05-prompts-for-auto-review.md)。
4. 人工看问题列表，标出误报与必须改。
5. 回复「确认写批注」。
6. 打开 WPS 批注窗格，抽查锚点，尤其是表格。
7. 需要改字的条目，再「确认替换」或按条确认。
8. 另存为「原名-已校对」一类文件名。

不要跳过预览直接「全部改完美」。写批注、替换类写操作在未确认时，通常会要求确认或只返回预览，这是设计，不是故障。三态工作流细节见：[预览、批注与替换工作流](./04-preview-comment-replace-workflow.md)。

推荐固定开场白：你通过 chayuan-wps-mcp 对当前 WPS 文件做自动审查。先做校对预览，列出错别字、标点和明显病句。等我回复确认写批注后，再写批注，且尽量钉在具体文字上，尤其是表格。没有我说确认替换，不要改正文。最后按严重、一般、建议三级给我摘要。

![预览列表与WPS批注窗格对照](images/csdn-01-8.png)

## 结果怎么算成功

成功的预览结果：对话里出现条目化问题，含原文片段与建议，而不是一句「已检查完毕」却无细节。成功的批注结果：WPS 批注窗格有多条批注，点开后高亮落在具体错字或词组上；表格内不整格误挂。成功的替换结果：仅你确认过的条目正文变化，其余不动；可用另存对比。

常见失败信号：healthz 不在线；Claude 看不到 chayuan-wps-mcp；回报 WPS_AGENT_OFFLINE 或类似离线；MODEL_NOT_CONFIGURED；CONFIRMATION_REQUIRED；DOCUMENT_TOO_LARGE；批注落点漂到邻句或整格。

验收标准建议写成：严重问题已处理或已批注、抽查不少于三处锚点正确、未发生未经确认的大段替换。

## 排错速查

现象：MCP 列表没有服务。处理：检查配置或重新执行 claude mcp add，核对服务名与 URL。

现象：有服务但 Agent 离线。处理：打开 WPS，确认加载项加载，刷新 healthz。

现象：能读文档，校对报模型未配置。处理：回察元设置配对话模型，并用加载项自测一次。

现象：只要预览却被改了正文。处理：开场白写死禁止未确认替换；重要稿先另存。

现象：表格批注不准。处理：指令写死钉在单元格具体错字上；不通过则先不要确认替换。

现象：长文超时或过大。处理：让 Claude 按块审查，不要一次拉全文。

## 安全边界与核对清单

默认端口不面向公网。不要随手把 62588 映射到互联网。公共电脑注意模型密钥残留。自动审查是初筛，不是司法鉴定，不是定密结论。扫描件、纯图文字、复杂文本框能力会下降。Claude Code 侧的对话内容是否出境，取决于 Claude 账号与网络策略；WPS 正文经 MCP 留在本机工具调用链路，但仍要按单位数据规定使用。

一页核对清单：下载并安装察元并打开 WPS；healthz 返回在线；配置模型且加载项内检查能出批注；安装 Claude Code；注册 chayuan-wps-mcp；MCP 列表可见且工具可展开；只读冒烟通过；校对预览冒烟通过；确认写批注并抽查锚点；需要时确认替换并另存已校对副本。

按本文做完，你得到的是 Claude Code 能直接审本机 WPS 文件的闭环。结果以 WPS 里的批注和可控替换为准，不以智能体口头保证为准。适用读者：需要对本机 WPS 公文、制度、合同做自动审查，并希望步骤可复核的人。

## 安装当天常见时间线

第一次装齐整条链路，多数人会在模型配置或 MCP 列表这两处停顿。建议按时钟切块，而不是一气装完再统一排错。前三十分钟只做安装包与 WPS 入口；接下来十五分钟只做 healthz 与设置页状态；再花二十分钟配模型并在加载项内自测；最后十分钟执行 `claude mcp add` 与只读冒烟。每一步有独立通过标准，失败时不必推倒重来。

科室培训时可以把这份时间线印成附页。教员先演示一份带故意错字的短稿，学员各自在本机复现四级验收。公共机房要注意：模型密钥不要写进共享账号，装完用加载项自测后清一下剪贴板里的密钥片段。若单位禁止云端模型，培训机只预装 Ollama 或 LM Studio，并事先写好基础 URL，减少现场填错。

## 与加载项自检、Claude 审查如何分工

短文、单次检查：加载项内拼写与语法检查更快，不必开 Claude。长文分块、多文档串行、要边讨论边改：用 Claude Code。两者共用本机 sidecar 与当前文档，不是两套互相打架的引擎。助手页若开启文档智能体，也可能走同一 MCP。排错时先问「加载项自检能不能出批注」：能出，说明模型与 WPS 侧健康，问题多半在客户端 MCP 配置；不能出，先别怪 Claude。

## 版本升级与残留路径

从 v3.x 升到 v4.0 一般是全量替换安装包，本机 MCP 端口仍为 62588，外部客户端配置通常不用改。升级后若工具调用异常，优先检查是否同时跑着旧 sidecar。Windows 看开机启动项与进程列表；macOS 看 LaunchAgent；Linux 看用户级 systemd 单元。确认只有一份服务占用 62588 后，再打开 WPS 做 healthz。发布说明与安装包以官网和发布仓页面为准，不要混用网盘里过期的测试包文件名。
