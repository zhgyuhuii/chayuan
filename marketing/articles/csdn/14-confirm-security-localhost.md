# confirmed 确认策略与 localhost 信任边界

察元 AI 文档助手 v4.0 把文档工具暴露给本机 MCP 客户端时，安全模型可以概括成两句话。第一，会改文档的操作默认要你确认（`confirmed=true`），脱密还要你本人提供的密码。第二，MCP 默认只监听 `127.0.0.1:62588`，信任边界是「这台电脑上的本地用户」，不是「局域网里任何人」，更不是公网。

搞清这两点，才能解释为什么有时会看到 `CONFIRMATION_REQUIRED`，以及为什么「给同事一个 IP 就能审你打开的稿」不是默认能力。客户端对接见 [./12-claude-codex-openclaw-hermes.md](./12-claude-codex-openclaw-hermes.md)；错误码处理见 [./15-errors-troubleshooting-handbook.md](./15-errors-troubleshooting-handbook.md)；内网模型链路见 [./11-offline-ollama-intranet-review.md](./11-offline-ollama-intranet-review.md)。

## 确认策略：预览是默认，写回是授权

### confirmed 在协议里的含义

对提供 `confirmed` 参数的工具：

- 省略或 `false`：预览或 dryRun，不把变更提交到文档（或明确只返回预览结果）。  
- `true`：在参数合法的前提下执行写批注、替换、脱密等变更。  

智能体不应在用户未明示时擅自把 `confirmed` 设为 `true`。产品侧的编排提示也要求：需要确认的写回交给用户，不要编造确认。你在对话里说「确认写批注」「确认替换」，客户端才应发起带 `confirmed=true` 的调用。

### 哪些操作通常要确认

- 写批注（例如校对结果落盘为 WPS 批注）。  
- 替换或批量 apply 类改正文操作。  
- 插入段落等会改变正文结构的操作。  
- 脱密 apply 与脱密 restore。  

只读类：读标题、列段落、分块读取、dryRun 校对预览——不应要求你为了「看一眼问题」而确认。若只读也失败，优先查 `WPS_AGENT_OFFLINE` 或参数错误，而不是先甩确认策略。

![同一工具 confirmed=false 预览与 true 写回的对比](images/csdn-14-confirmed-false-true.png)

### CONFIRMATION_REQUIRED 不是异常风暴

当写路径缺少 `confirmed=true` 时，服务返回 `CONFIRMATION_REQUIRED`（文案常见为必须传 `confirmed: true`，或建议先 dryRun 再 apply）。正确补救：

1. 看完预览列表。  
2. 明确回复确认范围（全部或按条）。  
3. 让客户端重试并带上 `confirmed=true`。  

错误补救：

- 在系统提示里写「永远自动 confirmed=true」。  
- 让模型把确认参数写死在每次调用里。  
- 把预览失败和确认失败当成同一类网络故障反复重启。  

## 脱密：确认之外还要密码

### 为什么多一道密码

脱密会改变文中敏感片段的可见形式，并与后续还原绑定。工具要求：

- `declassify_apply`：`confirmed=true` + 用户提供的 `password` + `keywords` 等必要参数。  
- `declassify_restore`：`confirmed=true` + 当初设置的密码。  

模型不得编造密码，也不得暴力试密。密码不应写入日志、不应贴进会签群、不应进截图。丢失密码意味着还原失败，这是预期行为。

### 推荐对话顺序

```text
先 declassify_preview，列出将处理的关键词与位置，不要 apply。
```

你核对后：

```text
确认脱密。还原密码使用我下面这条（仅本次会话使用）：（在此粘贴密码，勿截图外传）
```

然后由客户端调用 apply。还原时同样由你提供密码并确认。公文与合同场景若只需「标出敏感信息」而不是真正脱密，用检查加批注即可，不必走 apply。场景提示词见 [./13-official-doc-contract-scenarios.md](./13-official-doc-contract-scenarios.md)。

## localhost 信任边界：62588 默认绑在哪

### 默认监听

本机 MCP：

```
http://127.0.0.1:62588/mcp
```

健康检查：

```
GET http://127.0.0.1:62588/healthz
```

鉴权关闭；仅监听 `127.0.0.1`。含义是：同一台机器上能访问回环地址的进程，可以调用已暴露的文档工具。不要求 Token，是因为攻击面被收在「本机」——这与「对局域网开放且无鉴权」完全不是同一安全级别。

说明文档见仓库 [docs/mcp-connection.md](https://github.com/zhgyuhuii/chayuan/blob/main/docs/mcp-connection.md)。协议本身见 [Model Context Protocol](https://modelcontextprotocol.io/)。

### 信任边界内假设了什么

- 操作系统用户已经能操作你的桌面和文件。  
- WPS 里打开的文档，本来就能被本机用户阅读。  
- 外部 Agent（Claude Code 等）若在本机运行，相当于你授权它通过 MCP 操作当前文档工具集。  

因此，本机恶意软件或不受控脚本一旦能访问 `127.0.0.1:62588`，风险与「本机已失陷」同级。MCP 不是跨用户隔离方案，也不替代磁盘加密与终端管控。

![仅 127.0.0.1 可访问 62588 的示意](images/csdn-14-bind-localhost.png)

## 不该暴露什么

### 不要做的事

1. 把 62588 改成监听 `0.0.0.0` 并在防火墙放行，却不设任何鉴权与 ACL。  
2. 用路由器端口映射把 MCP 打到公网「方便在家连单位电脑」。  
3. 在截图、工单、聊天里粘贴含明文密码的脱密请求体。  
4. 给共享账号电脑常驻登录云模型密钥，又同时开着可写 MCP。  
5. 在未确认活动文档的情况下，允许无人值守批量 `confirmed=true` 替换。  

### 内网远程使用时的最小可控做法

若确实需要「人在 A 机器、WPS 在 B 机器」：

- 优先在 B 本机跑客户端，经远程桌面操作，MCP 仍走 B 的 127.0.0.1。  
- 若必须端口转发，使用带鉴权的 SSH 本地转发等受控通道，绑定到操作者本机回环，并在不用时关闭。  
- 评估单位制度是否允许文档工具被远程进程调用；不允许就停止，而不是「先打通再补秩序」。  
- 环境变量改端口（如 `CHAYUAN_MCP_PORT`）时，同步更新所有客户端配置，避免旧端口误连到别的进程。

![SSH 本地转发把远端 62588 映到本机回环的示意](images/csdn-14-ssh-tunnel.png)

## 与模型密钥、日志、审计的关系

### 模型配置

云端密钥存在察元设置中，按人按岗最小授权。公共机器用完清密钥或改用内网 Ollama。MCP 无 Token 不意味着模型密钥可以随便贴进提示词。

### 预览内容外传

预览列表可能含公文与合同原文片段。复制到外部聊天、邮件、公有云 Agent 时，等于主动扩大知悉范围。内网合规场景应使用本机或内网模型，并限制对话同步到外部。

### 审计习惯

对替换与脱密，保留「谁在什么时间确认」的工作记录：可以是会签意见、本地操作记录或你们自己的工单号。`confirmed=true` 解决的是工具链上的门闩，不是单位档案意义上的签字。

## 把确认写进开场白（可直接粘贴）

```text
你通过 chayuan-wps-mcp 连接本机 WPS。
规则：
1）默认只预览；任何写批注、改正文、脱密 apply/restore 必须等我明示确认；
2）确认写回时工具参数使用 confirmed=true；未确认不得重试刷写；
3）脱密必须使用我提供的密码，禁止编造或省略密码；
4）不要建议我把 62588 暴露到局域网或公网；
5）活动文档不确定时先询问，不要对错误文件 confirmed。
```

四个客户端共用这段即可。配置方式见第 12 篇；Claude 的 MCP 说明见 [Claude Code MCP 文档](https://code.claude.com/docs/en/mcp)。

## 与错误码的交叉点

- `CONFIRMATION_REQUIRED`：补确认，不要改监听地址。  
- `WPS_AGENT_OFFLINE`：本机 WPS/加载项问题，与是否暴露端口无关。  
- `MODEL_NOT_CONFIGURED`：模型设置问题。  
- `DOCUMENT_TOO_LARGE`：改分块读取。  
- `LOCATE_*`：原文定位失败，先重读再写，仍需确认策略。  

排错步骤汇编见 [./15-errors-troubleshooting-handbook.md](./15-errors-troubleshooting-handbook.md)。

## 安全验收清单（上线前勾选）

1. healthz 仅在本机访问成功；从另一台电脑访问默认失败。  
2. 未确认时写批注被拒，返回 `CONFIRMATION_REQUIRED`。  
3. 脱密 apply 无密码失败；无 confirmed 失败。  
4. 客户端配置中无假 Token、无把 URL 写成公网 IP。  
5. 培训材料明确：自动审查初筛 ≠ 定稿批准。  
6. 公共电脑模型密钥与会话退出策略已写明。

## 威胁模型：你在防什么

### 本机误操作

最大量的真实风险不是黑客，而是：对话里随口说「都改了吧」，客户端批量 `confirmed=true`，把尚在讨论的合同价款改掉。门闩与开场白就是为这类误操作准备的。培训时应故意演示一次未确认被拒绝，再演示一次确认后写回，让肌肉记忆形成。

### 本机恶意软件

若恶意进程已能以当前用户身份访问回环端口，它可以调用与 Agent 相同的工具集。缓解靠终端安全、最小权限账号、不随便运行未知脚本，而不是给 MCP 加一个写在聊天里的假 Token 自我安慰。假 Token 在当前默认模式并不构成有效认证。

### 网络暴露

一旦 62588 对局域网或公网开放且无额外控制，任何能打到该端口的人，都可能在你打开 WPS 文档时操作文档工具。这是从「本机助手」变成「未鉴权文档 API」。单位安全检查若扫到此类端口，应按高风险处置：立即收回监听范围、切断映射、复查期间文档是否被改。

### 数据外带

即使 MCP 仍在本机，若客户端把段落原文同步到公有云模型，知悉范围已经扩大。内网稿件应搭配内网或本机模型（见第 11 篇），并在制度上禁止把预览列表贴到外部聊天。

## 管理员配置基线（建议写入内部规范）

1. 安装包来源仅限官网或单位软件仓库，核对版本 v4.0。  
2. 禁止修改 MCP 监听为 `0.0.0.0`，除非另有已审批的鉴权方案（当前默认文档路径不提供公网 Token 方案）。  
3. 客户端配置模板统一分发，URL 固定为 `http://127.0.0.1:62588/mcp`。  
4. 写回类能力默认培训为「批注优先」；替换需双人复核的合同类型名单另附。  
5. 脱密密码按口令规范管理，禁止默认密码、禁止共享密码。  
6. 公共电脑当日用毕清理模型密钥与对话历史（按客户端能力操作）。  
7. 发现端口暴露时的应急：断网隔离该机、保留日志与文档副本、重置相关口令。  

基线不替代等保或保密测评，只是把产品默认设计翻译成可执行的行政要求。

## 开发与测试环境注意

开发者在仓库里用 `npm run mcp:sidecar` 起服务时，同样默认本机端口。不要为了手机调试把 MCP 挂到 Wi-Fi IP。自动化测试若需要模拟确认，应在受控测试文档上进行，并与生产稿隔离。自测脚本里出现的 `CONFIRMATION_REQUIRED` 是预期断言，不是要消除的噪声。

联调时若使用 MCP Inspector，请把它当作「带手的本机用户」：Inspector 能做的事，本机其他进程也可能做。演示脱密时改用假数据与一次性密码，演示结束即作废，勿用生产还原口令。

桌面共享或远程协助时，注意对方是否能看到你的本机回环服务；协助结束后关闭不必要的共享与转发。会签大屏投屏演示审查流程时，用脱敏样例，避免把真实合同价款与密码投到会议室屏幕。这些都不是产品开关能单独解决的问题，要靠现场纪律。若演示必须使用近真实稿件，会后立即关闭文档、清理客户端会话，并确认没有人把预览列表转发到外部邮箱或个人网盘。会议室如有录像，按单位会议录像规定处理含屏幕画面的片段，默认不要外发。口令类信息出现在画面中时，应视为一次口令暴露事件并按规范轮换。

## 小结

`confirmed` 把「模型建议」和「文档变更」切开；密码把脱密从普通校对里切开；`127.0.0.1:62588` 把「本机助手」和「网络服务」切开。三道界线都守住，察元 v4.0 的本机 MCP 才能在真实办公环境里用。威胁模型按误操作、本机失陷、网络暴露、数据外带分别设防，管理员基线写进规范后，培训与审计才有据可查。下一步若要按错误码逐项修，打开第 15 篇手册即可。
