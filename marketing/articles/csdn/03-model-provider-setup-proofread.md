# 察元模型与供应商配置：从 Ollama 到 MODEL_NOT_CONFIGURED

自动审查链路里，MCP 连通和模型可用是两件独立的事。chayuan-wps-mcp 能列出工具、能读到当前文档，只说明本机桥通了；拼写与语法检查、校对预览要能跑出问题列表，还必须在察元设置里配好对话模型。现场最常见的混谈是：Claude 报错，有人去重装 MCP，其实是 MODEL_NOT_CONFIGURED。本文把供应商、离线与云端、验收顺序和该错误码拆开写。

![察元模型与供应商设置页](images/csdn-03-1.png)

## 先确认 MCP 层是绿的

配模型之前，用两分钟排除桥接故障：浏览器打开 [http://127.0.0.1:62588/healthz](http://127.0.0.1:62588/healthz) 应为在线；MCP 入口是 [http://127.0.0.1:62588/mcp](http://127.0.0.1:62588/mcp)。WPS 已打开且察元加载项可见。MCP 细节见：[本机 MCP 专文](./02-mcp-localhost-chayuan-wps-mcp.md)。全流程入口见：[生命周期总览](./01-lifecycle-claude-wps-review.md)。

下载与版本以 [https://aidooo.com](https://aidooo.com) 与 [https://github.com/zhgyuhuii/chayuan-wps-releases](https://github.com/zhgyuhuii/chayuan-wps-releases) 为准。

## 支持哪些接入方式

察元侧按「供应商 + 模型」组织配置，常见两类：

### 离线或内网 OpenAI 兼容

Ollama、LM Studio、Xinference、OneAPI、New API 等。填写基础 URL、可选密钥、拉取或手选对话模型。适合稿件不能出内网、或单位只允许内网推理的环境。

### 云端供应商

按合规要求配置可用供应商与 API 密钥。密钥按人按岗最小授权。公共电脑慎用个人密钥，用完检查是否残留在设置页或剪贴板。

无论哪一类，默认对话模型必须是对话类型，不要把纯嵌入模型、图像模型误设为校对默认。

![已选中的默认对话模型](images/csdn-03-2.png)

## 推荐配置步骤

1. 打开察元设置，进入模型与供应商相关页。
2. 启用至少一家供应商，保存基础 URL 与密钥（若有）。
3. 刷新模型列表，选定默认对话模型。
4. 用一小段含故意错字的测试稿，在加载项内执行拼写与语法检查。
5. 确认能出问题列表或批注后，再让 Claude Code 调用校对预览。

加载项自测通过，是区分「模型问题」与「客户端问题」的分水岭。自测失败时，先不要改 Claude 的 MCP 配置。

### Ollama 示例排查顺序

确认 Ollama 服务在本机或内网可达；确认模型已 pull；在察元填写的基础 URL 与 Ollama 实际监听一致；保存后重新选择对话模型；加载项内再跑一次短检。LM Studio 同理：先在 LM Studio 里确认本地服务器已启动，再把该地址填进察元。

![加载项内拼写检查跑出问题列表](images/csdn-03-3.png)

## 为什么会出现 MODEL_NOT_CONFIGURED

含义：校对相关工具被调用时，察元侧找不到可用的对话或校对模型配置。它不是 MCP URL 写错，也不是 healthz 失败。典型触发：

- 从未配置过供应商。
- 配置了供应商但未选默认对话模型。
- 选中的模型已下线或列表刷新后 ID 失效。
- 只配了嵌入模型，对话模型为空。
- 密钥无效导致运行时等价于无可用模型。

处理：回到设置页把对话模型配到「加载项自测能出结果」，再重试 Claude 侧校对预览。不要在未自测前反复 `claude mcp add`。

## 离线与云端怎么选

### 离线优先的场景

公文内网、合同谈判稿、不允许正文经公网推理的岗位。选 Ollama 或 LM Studio 一类，把基础 URL 指到内网。验收时断开外网再跑一遍加载项检查，确认没有静默走到云端。

### 云端可接受的场景

外网可用、单位已批准的供应商、个人学习用非涉密样例。仍要最小权限密钥，并避免在演示投屏时露出完整密钥。

同一台机器可以同时配置多家供应商，但默认对话模型只能有一个清晰选择，避免客户端调用时落到空配置。

## 从加载项自测到 Claude 校对

加载项自测通过后，在 Claude Code 中确认已注册：

```
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

然后只跑预览：对当前文档做校对预览，不要写批注，不要改正文。若此处仍报 MODEL_NOT_CONFIGURED，回到察元设置看默认模型是否被清空，或是否存在多配置文件档位切换后未保存。若预览正常，再进入确认写批注流程，见：[预览批注替换工作流](./04-preview-comment-replace-workflow.md)。提示词见：[提示词库](./05-prompts-for-auto-review.md)。

### 仍失败时的信号分离

| 信号 | 更可能的层 |
| --- | --- |
| healthz 不通 | sidecar / 端口 |
| 工具调用 WPS 离线 | WPS 未开或加载项未加载 |
| MODEL_NOT_CONFIGURED | 模型与供应商 |
| 有列表但条目空洞 | 模型能力或提示词 |
| CONFIRMATION_REQUIRED | 写操作未确认，属正常门禁 |

## 配置验收清单

- 供应商已启用，基础 URL 可访问。
- 默认模型类型为对话。
- 加载项内短稿检查能出问题列表或批注。
- 断网或按策略验证离线路径（若你声明走离线）。
- Claude 校对预览能返回条目化问题。
- 密钥无明文出现在截图与共享文档中。

模型层通过后，自动审查的上限才取决于提示词与确认纪律，而不是随机报错。源码与进阶字段需要时对照 [https://github.com/zhgyuhuii/chayuan.git](https://github.com/zhgyuhuii/chayuan.git)，MCP 概念对照 [https://code.claude.com/docs/en/mcp](https://code.claude.com/docs/en/mcp)。

## 密钥与基础 URL 的填写习惯

云端供应商通常要 API 密钥；内网 OpenAI 兼容网关有的要密钥、有的只靠内网访问控制。密钥保存后不要在培训投影上停留。基础 URL 末尾是否带 `/v1`，以该网关文档为准，察元侧按 OpenAI 兼容客户端习惯拼接路径。填错时常见现象是：供应商保存成功，但一测对话就超时或 404。此时用同一基础 URL 在终端或网关自带的试连工具验证，比在 Claude 里反复点校对更快。

模型列表刷新失败时，先看网关是否要求额外请求头，再看本机是否被代理软件把内网地址错误地送出外网。公司代理白名单要放行你的内网推理地址。公共 DNS 污染一般不是主因，但笔记本连错 VPN 分区时，会出现「昨天还通、今天全超时」——先查网络分区，再查密钥是否过期。

## 对话模型与校对任务的匹配

校对任务需要模型能稳定输出结构化问题列表：原文片段、建议改法、理由。参数过小的本地模型可能只会说「有问题」而不给定位文本，导致批注锚点失败。遇到这种情况，不要急着改 MCP；先在加载项内换一个更大的对话模型重跑同一段测试稿。若加载项内列表完整、Claude 侧却很短，再查提示词是否把「只要摘要不要条目」写进了开场白。

嵌入模型、重排序模型、图像模型不要设成默认对话模型。设置页若同时存在「对话」「校对」相关下拉框，以当前版本界面文案为准，原则是：真正发起拼写语法检查的那条链路，必须指向可用的对话类模型。

## 配置页面上的字段怎么理解

不同版本界面文案可能略有差别，但字段含义稳定。供应商：表示一类推理后端，例如某云厂商或某内网网关。基础 URL：OpenAI 兼容接口的根地址，是否包含版本路径以网关文档为准。密钥：云端几乎总需要；内网可能为空。模型列表：从供应商拉取或手工填写的可选模型。默认对话模型：校对与多数文档智能体调用实际使用的那一个。只要默认对话模型为空或不存在，校对就可能在运行时报 MODEL_NOT_CONFIGURED。

保存按钮要真正点到。有人只选中下拉框却忘记保存，加载项界面看着「好像选了」，进程内配置仍是空。改完配置后，建议关闭再打开一次任务窗格，或按版本说明重新加载，再跑短稿自测。

## 用短稿做模型验收的写法

测试稿不要太长，八到十五句足够。故意设置三类错误：明显错别字、的地得混用、中英文逗号混用。若有表格，再在单元格里放一个错字。跑拼写与语法检查后，期望看到条目而不是一句「未发现问题」；期望批注能点进原文。若模型只会返回空泛建议，换更大的对话模型，或检查温度与最大输出长度是否被设得过小导致截断。

把同一份短稿固定下来，作为科室「模型冒烟稿」。以后每次更换供应商、升级 Ollama 模型、轮换云端密钥，都先跑这篇，再开放给业务人员使用。

## 云端失败与离线失败的不同表情

云端常见失败：密钥 401、额度用尽、模型名下线、公司出口防火墙拦截。表现是供应商试连失败或校对超时。离线常见失败：本机推理服务没启动、模型未下载、基础 URL 指错端口、显存不足导致服务崩溃。表现同样是超时或连接拒绝，但此时外网可能完全正常，容易误判成「要换云端」。

排错口诀：先在供应商自己的试连或命令行访问基础 URL，再进察元，最后才进 Claude。跳过前两步直接在 Claude 里点校对，日志链路太长，定位变慢。

## MODEL_NOT_CONFIGURED 与其他错误的边界

WPS 离线类错误：先开 WPS 与加载项。MCP 连不上：先看 healthz 与客户端 URL。CONFIRMATION_REQUIRED：写操作门禁，补确认口令。DOCUMENT_TOO_LARGE：改分块，不要一次拉全文。MODEL_NOT_CONFIGURED：只处理模型与供应商。把错误码当成分层标签，培训时少讲形容词，多讲「回到哪一页设置」。

若加载项自测成功、仅 Claude 失败，检查是否存在多个察元配置档、是否在不同用户目录安装了两份、是否 Claude 实际连到另一台机器的空配置环境。远程桌面多会话时，会话 A 配了模型，会话 B 的 WPS 未必读到同一份设置。

## 内网网关与兼容字段

OneAPI、New API、自建兼容层经常提供统一密钥与模型路由。把网关当供应商接入时，模型名必须是网关已路由的名字，而不是你在本地 Ollama 里看的小名。网关改路由后，察元侧要重新刷新模型列表并保存默认项。网关开启了 IP 白名单时，要把办公网段加进去，笔记本换 Wi-Fi 后突然全失败，优先查白名单。

有的网关要求额外请求头。若察元当前版本设置页没有对应字段，就不要指望「只填密钥」能过；改用网关提供的标准 OpenAI 兼容入口，或升级到支持该字段的版本。以你安装包的说明为准，不要假设所有网关特性都已映射进界面。

## 安全与合规检查表

密钥是否只存在本机设置中，是否被写进共享文档。公共账号是否禁用了云端供应商。声明走离线的机器是否真的断网复测过。截图外发前是否打码。培训投影是否避开密钥页。模型供应商合同是否覆盖公文数据场景。这些检查与「能不能跑出批注」同等重要。跑得通但不合规，仍然不能上业务。

## 配完模型之后做什么

加载项自测通过后，用 Claude 做校对预览冒烟，不要写批注。通过后再进入确认写批注。提示词用系列第五篇的固定开场白，避免一上来就要求改正文。若预览条目质量差，先换模型或收紧提示词，不要立刻放开替换门禁。模型层稳定，是预览批注替换三态可靠运转的前提。
