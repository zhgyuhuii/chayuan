# 用了两周这个开源 WPS 插件：AI 直接在正文里改稿写回，还能全程断网

> 全文约 3000 字，写给每天在 WPS 里写公文、合同、报表，被"复制粘贴式 AI"消耗着的人。

## 先说三个熟悉的日常

第一个：你在 WPS 里写材料，想让 AI 帮忙，得切到浏览器、打开某个网页对话框，把正文粘过去——AI 回完，再粘回来，格式自己调。文档在办公软件里，AI 在另一个世界，来回横跳。

第二个：好不容易用上了带 AI 助手的办公软件，点开一看，是个停在侧边的聊天框。你问它答，它不知道你写到第几段，它的结果也进不了你的正文——最后一步永远是复制、粘贴、重新排版。

第三个：真正想交给 AI 处理的，往往是那份不方便外传的材料——合同、公文、内部报告。传到云端对话框走一圈，心里总归不踏实。

这三个别扭指向同一件事：**大多数办公 AI 是"外挂的聊天框"——不认识你的文档，写不进你的文档，还总想把文件带走。**

今天介绍的 [察元 AI 文档助手](https://github.com/zhgyuhuii/chayuan)走的是另一条路。它是运行在 **WPS 文字、WPS 表格、WPS 演示**三个组件内部的第三方开源加载项（Apache-2.0，Vue 3 + Vite，北京智灵鸟科技中心研发），当前版本 6.1.2。对话、校对、翻译、改写、摘要、生图、保密检查、模板编制、知识库检索，全部**不离开编辑器**完成；结果可以按 **9 种写回动作**直接落进正文——插入、替换、批注、链接批注、追加到文末等等，按单位的留痕制度选最合适的一种。

## 惊喜一：AI 不是聊天框，是会干活的智能体

打开「察元AI助理」的对话窗，你面对的不是一问一答，而是一个完整的智能体循环：它先列任务清单，然后逐项执行、边做边勾（能看到 N/M 实时进度），连续调用工具完成多步操作——单回合上限 100 步，长任务一口气做完。

举例说，你说"检查全文错别字，用批注标出来"，它做的事情是：调用校对工具扫全文 → 汇总问题清单 → 把每处问题写成 WPS 批注，**批注钉在具体的错字上**，表格单元格里的错字同样钉得住。你逐条看、逐条接受，跟审同事的稿子一样审 AI 的活。

写回这件事它做得比较谨慎，有四重保险：

- **文档写锁**：多个任务排队写，不互相覆盖；
- **写前快照**：首次写回前自动存快照，改坏了随时一键撤销；
- **冲突校验**：写之前再核对一遍文档状态，发现冲突会显式提示，而不是静默覆盖；
- **权限三档**：变更前确认 / 自动执行 / 完全访问，默认最保守的一档。

对话框还支持浮窗 / 左右停靠一键切换——停靠时面板正好占半屏，左边写稿右边盯 AI，谁也不挡谁。多会话页签各自独立，会话按文档隔离，切窗口回来现场还在。

## 惊喜二：4,526 个行业助手，不用你自己写提示词

这是它最有辨识度的一块：**文字端内置 4,526 个领域助手，覆盖 228 个行业领域**——财务函证、党务材料、招标文件、医疗文书、政务公文……都是预先调校好的提示词模板。你要写一份请示，不用自己琢磨怎么向 AI 描述"请示的格式和语气"，按领域找到对应助手点一下就执行。

表格端另有 **66 个配方**（排序汇总、多表合并、两表对比差异、敏感信息脱敏、智能分列……），六大主按钮（数据洞察、一键图表、公式助手、数据清洗、报表结论、一键美化）常驻功能区；演示端 **81 个配方**（含政务汇报、党务学习、科研学术专场），一句话生成整份 PPT 也在这端。翻译支持 **52 种语言**，动态菜单直接选。

都不合用还可以自定义助手：自写提示词、选输入来源（选区 / 全文）、定输出格式和写回动作，支持导入导出分享。高频功能另有"文本分析九件套"——换种方式重写、扩写、缩写、AI 痕迹检查、提炼关键词等，都在功能区菜单里。

## 惊喜三：断网也能干活

离线优先是这个产品写在介绍第一行的设计底线：

- **本地模型直连**：Ollama、LM Studio、Xinference 装在本机或内网服务器上就行，安装检测自动识别常用端口（11434 / 1234 / 9997 / 8000），国内网络还会自动择优下载源；
- **密钥只存本机**：云端模型的 API Key 保存在本地设置里，文档内容只发给你自己配置的模型端点，察元自身不设云端转发；
- **知识库也分两路**：装了察元 AI OS 的机器零配置自动发现本机知识库；团队场景连远程知识库服务（JWT / HMAC / 免鉴权三模认证），制度对照、条款引用、术语统一这类任务可以"对照知识库检查本文是否违规，引用条文批注"。

对内网和涉密单位来说，这意味着整套 AI 流程可以完全跑在网闸里面。再配上保密检查（密级标识、涉军涉装、联系方式、商业秘密等分级风险提示）、文档脱密（敏感内容占位符替换、密码保护、可逆复原，仅本机可信通道可用），发材料前先自检一遍，是这套产品瞄准的主场景。

要说清楚：保密检查、脱密、AI 痕迹检查都定位为**辅助参考**，不构成保密定密结论——这个边界它在文档里反复强调，是加分的态度。

## 一句话，出整套文档

v6.1 之后还有个值得单独说的能力：把公司的模板文件（.pptx / .docx / .xlsx）拖进首页对话，加一句要求，它按模板的形状逐页对位生成整套文档——封面吃文档标题、目录按序号对位、字体母版原样保留，打开前还有多轮机器审计。这部分细节值得单独写一篇，这里先按下不表。

## 模型和平台

模型接入走 OpenAI 兼容路线：DeepSeek、通义千问、智谱 GLM、Kimi、OpenAI、Gemini，或任意兼容网关（OneAPI、New API）都能配；对话、生图、语音、视频按用途分别指定默认模型，模型卡还能填上下文窗口大小，面板自动按窗口定 token 预算——小模型少给、大模型多给。

Windows / macOS（含 Apple Silicon）/ Linux 三平台有官方安装包，装完即用，无需 Node.js。作为 Apache-2.0 开源项目，你也可以直接从源码构建。

## 适合谁，不适合谁

适合：已用 WPS 的政企与事业单位（公文助手、保密检查、内网部署这一套组合拳明显是冲这个场景练的）；对数据不出域有硬要求的用户；需要批量校对几十份文档的岗位（校对、法务、办公室）；想让 Claude Code、Cursor 这类编程智能体直接操作 WPS 文档的进阶玩家——它内置 53 个工具的 MCP 服务，这是另一个大故事。

直说不适合的场景：如果你主要用 Microsoft Office，它帮不上——宿主是 WPS；如果重度依赖多人实时云协同编辑，它的主战场在本地与私有化；另外部分进阶能力有能力门禁（本地验签激活 + 免费额度），不是所有功能都无条件敞开。
