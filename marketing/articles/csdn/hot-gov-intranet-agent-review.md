# 周五送审，稿子却不能上公网：机关内网里的国产 WPS 自动审查

> 本文面向政务/政企办公读者，不是操作手册。命令、端口、错误码均来自察元 AI 文档助手 v4.0 的真实实现；可复现步骤见《内网离线用 Ollama 审 WPS：本机 MCP 与察元 v4.0 全链路》。本专栏其他文章可在 CSDN 搜标题找到。

**模型可以在机房，批注必须在稿子上。** 先记住这句话。下面讲，一个材料岗的人，怎么在内网里用上文档智能体，又不踩任何一条红线。

## 一、周五下午三点，那个不敢按下回车的瞬间

材料科小李的故事，全国每一个办文岗都发生过。

周五下午三点，处长递来一份三十页的专项工作汇报，下周一上会，今天下班前要把错别字和序号问题过一遍。稿子带密级。

小李打开某个网页大模型，把正文粘进输入框，光标停在「发送」上。

她停了大概五秒钟。然后把内容全删了。

不是不会用。是四件事同时卡住了她：

- **带密级的稿，贴公网就是扩大知悉范围。** 事后被问到「谁允许上传的」，她写不出那份情况说明。
- **这台机器根本打不开那个网页。** 涉密网、业务专网，公网流量进不来，代理也不让走。
- **就算前两关都过了**，大模型吐回来的是一段「润色后」的文字，没有定位、没有痕迹。领导问「你凭什么改的这句」，她答不上来。
- **真要逐字逐句人工通读三十页**，今天回不了家，周末也悬。

小李的委屈，从来不是「我不懂 AI」。是**「我被要求提效，可我的环境不让我用那些 AI；用了，还可能违纪」**。

这种委屈被压着、没人替它说话。所以这篇文章值得转发——因为每一个读到这里的核稿岗、文书岗、信息中心，心里都有一个自己的小李。如果你也是，往下看，有一条不踩红线的路。

## 二、为什么公网那套 AI，在机关里处处别扭

把市面上常见的「网页大模型」搬进办公流程，会撞上五道墙。一道比一道硬。

**第一道墙：不联网。** 涉密网、隔离网、业务专网，公网流量进不来。这不是网管小气，是制度要求。你在那台机器上，连一个外网域名都解析不了。给科室发一个「去网上试试」的链接，第二天文书同事仍会回到手工通读。

**第二道墙：内网隔离。** 内网允许访问单位自建的服务，但默认不允许把工作材料外送。能装软件，不能随便出网。

**第三道墙：国产化、信创。** 文字处理是 WPS，不是某国外套件；操作系统、CPU、数据库都在往国产栈迁。智能体若只在浏览器里生成一段新文本，最后还得复制回 WPS，格式、批注、留痕全断。机关要的是**「在正写的那页稿上干活」**，不是另起一套。

**第四道墙：不敢上传。** 一次上传，就是一次数据出境事件的前置动作。哪怕只是「试试看」，事后追溯也说不清。所以宁可不用，不可用错。

**第五道墙：要留痕、要问责。** 领导看的不是「AI 帮我校过了」，而是「谁、在什么时间、改了什么、依据是什么」。一段无来源的「AI 润色」，在留痕和问责体系里等于零。

五道墙合起来，指向同一个结论：**机关要的不是更聪明的聊天框，而是「长在国产 WPS 里、跑在内网、改动可核对、人来点头」的东西。** 这正是文档智能体（Agent）和聊天机器人的分水岭——智能体能执行、能定位、能写批注，而不是只吐一段文字让你自己搬回 WPS。

## 三、一句话解法：四块拼在同一台电脑上

察元 AI 文档助手 v4.0 的做法，可以缩成一句话：**把 WPS、内网模型、本机 MCP、人工确认这四块，拼在同一台办公机上，材料默认不出域。**

- **WPS**：稿件始终在国产办公软件里打开，是唯一的「活动文档」。智能体读它、定位它、往它上面写批注，而不是把正文搬到别处。
- **内网模型**：推理用 Ollama、Xinference、OneAPI 这类 OpenAI 兼容的内网端点，或纯本机模型。模型可以放在机房那台 GPU 机器上，也可以就在本机。**模型流量走内网，不走公网。**
- **本机 MCP**：察元起一个本机服务，固定监听 `http://127.0.0.1:62588/mcp`，服务名 `chayuan-wps-mcp`。Claude Code、Codex、OpenClaw、Hermes 这些客户端只连这个**本机回环地址**，不连外网，不要 Token。端口只绑 `127.0.0.1`，从设计上就没打算被互联网碰到。
- **人工确认**：任何会改文档的动作（写批注、替换、脱密），默认要你点头（协议层叫 `confirmed=true`）；你没说「确认」，一个字都改不了。

四块拼完，就形成了机关最在意的那条线——**模型可以在机房，批注必须在稿子上。** 这句话，建议截图保存。

端口与协议细节见《本机 MCP：端口 62588、chayuan-wps-mcp 与 Streamable HTTP》；安装全流程见《察元 AI 文档助手 v4.0 全生命周期：从安装到 Claude 自动审查》。

## 四、最小闭环：装、配、验、审

给信息中心或科室里「第一个吃螃蟹的人」。全部跑通，大约半天。

**第一步：装到 WPS 里，而不是装到浏览器里。** 从官网 [https://aidooo.com](https://aidooo.com) 或发布仓 [https://github.com/zhgyuhuii/chayuan-wps-releases](https://github.com/zhgyuhuii/chayuan-wps-releases) 取安装包，按 Windows / macOS / Linux 选择。**装完必须真正打开一次 WPS 文字**，确认加载项出现。只装包不启动，加载项不注册，后面客户端一律报 `WPS_AGENT_OFFLINE`——这个错误码后面会反复出现，先记住它。

**第二步：模型放内网或本机。** 在察元设置里配置对话模型，基础 URL 指向内网 Ollama 的兼容接口（本机常见端口 `11434`，或内网 GPU 机的 IP）。外网模型不是不能配，而是要先过本单位数据与采购规定。配完先在加载项内跑一次「拼写与语法检查」——**这一步出不了问题列表，先别谈任何外部智能体**。模型配置见《察元模型与供应商配置：从 Ollama 到 MODEL_NOT_CONFIGURED》。

**第三步：先预览，再确认写批注。** 以 Claude Code 为例，一行命令挂上本机端点：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

再把这段开场白贴进客户端——它就是人机分工的契约：

```text
你通过 chayuan-wps-mcp 操作当前 WPS 文档。
1）先校对预览，检查错别字、标点、明显病句；
2）汇总问题列表给我，不要改正文；
3）我回复「确认写批注」后，再写成 WPS 批注，钉在具体文字上；
4）没有「确认替换」，禁止改正文；
5）脱密相关工具禁止擅自调用。
```

然后下一句「对当前文档做错别字与标点审查，先给问题列表」——智能体返回列表，你核对，再回「确认写批注」。批注就钉在了稿面上，每处都带原文、问题、建议。

整套流程的妙处在于：**它没让你信任 AI，它让你信任流程。** 预览是默认，写回是授权，确认一次改一次。这条契约，比任何「我们绝对安全」的承诺都更适合写进科室操作规范。写回三路见《校对预览、批注与替换：dryRun 到确认写回》。

**第四步：需要时再接客户端，而不是反过来。** 若单位还没试点 Claude Code 等外部客户端，加载项内检查已经能覆盖大量错别字初筛。不要为了「用上智能体」先引入未批准的外网对话通道。等政策允许再挂上 `chayuan-wps-mcp`，端点与工具集已经在 v4.0 里，不会因为晚接而作废。

## 五、回到小李的周五：那条有痕迹的路

把上面的闭环，落回小李那个周五下午——这就是故事的另一半：

1. 另存副本，文件名带日期——**原始稿不动**。  
2. 下一句预览指令，只要问题列表，不改正文。  
3. 自己删掉误报，保留硬伤——**人在回路，她才是把关人**。  
4. 回「确认写批注」，批注钉在具体错字上，退给起草人；无争议条目按条「确认替换」。  
5. 表格抽查三处锚点，确认批注没飘到表外。  
6. 另存「已校对」稿送审。批注窗格就是会签的讨论抓手。

两小时不够「全自动完美」，但够做一轮**有痕迹、可追溯、能交差**的初筛。临下班，小李不用再纠结「要不要粘进网页」——因为那条路，从一开始就不在她的选项里。智能体压缩的是通读时间，不是取消核稿岗。

三种岗位的分工也写清楚，免得出了错三方甩锅：

- **起草人**：负责事实与口径，收到批注改字，不负责解释模型原理。
- **核稿或文书**：下预览指令、删误报、决定哪些条目确认写批注。
- **信息中心**：内网模型端点、安装包来源、端口是否只绑本机、密钥是否进公共机房。

讲话稿临场修改，指令收窄为「只查同音别字与姓名前后一致，先预览」；合同会签前，主体、金额、期限、违约责任用批注列风险，**法务仍终审，不要让模型直接改条款数字**。更多提示词见《公文与合同自动审查场景：提示词、批注与确认写回》《Claude 自动审查提示词库：可复制开场白与场景口令》。

## 六、三条不能让步的界线（写进科室公约反而更敢用）

工具再好，进机关就得守规矩。这三条写出来，反而比藏着掖着更让人放心——**立场站住了，转发的人才没有后顾之忧**。

**界线一：不替代定密，不替代终审。** 自动审查是初筛，把明显错别字、标点、常见缺项提前钉出来。密级、份号、是否印发，仍然是人说了算。「模型已检查完毕」永远不能单独作为印发依据。扫描件、纯图文字、复杂文本框能力会下降，模型会误报——这些也写在培训第一页，比上线后扯皮便宜。

**界线二：62588 不出本机。** MCP 默认只绑 `127.0.0.1`，信任边界是「这台电脑上的本地用户」，不是局域网，更不是公网。**绝不要为了「方便同事连你的 WPS」把端口映射到 `0.0.0.0` 或做无鉴权转发**——那等于把「本机助手」变成「未鉴权文档接口」，安全检查扫到会按高风险处置。需要远程用时，走带鉴权的 SSH 本地转发，用完即关。详见《confirmed 确认策略与 localhost 信任边界》。

**界线三：脱密要密码，预览内容别外贴。** 脱密会改变敏感片段的可见形式，必须你本人提供还原密码，客户端不得编造、不得暴力试密。预览列表里可能含公文合同原文片段，复制到外部聊天、邮件、公有云，就等于主动扩大知悉范围——**内网稿件配内网模型，列表别外传**。

## 七、十步核对清单（建议截图发工作群）

这一段单独成块，就是为了被截图、被转发——没读完全文的人，也能照着做。

1. 安装包只从官网 aidooo.com 或单位软件仓库取，核对 v4.0。  
2. 装完**先打开 WPS 文字**，确认加载项出现，否则一切 `WPS_AGENT_OFFLINE`。  
3. 浏览器开 `http://127.0.0.1:62588/healthz`，看到在线（online）算第一关。  
4. 加载项内跑「拼写与语法检查」，能出问题列表算模型配通，否则 `MODEL_NOT_CONFIGURED`。  
5. 客户端连 `http://127.0.0.1:62588/mcp`，先下一句**只读**冒烟（读标题和前两段，不改不批注）。  
6. 贴开场白，下预览指令，**只要列表，不改正文**。  
7. 人工删误报，保留硬伤——你是把关人。  
8. 回「确认写批注」，钉在具体文字上；表格钉单元格。  
9. 另存「已校对」副本送审，原始稿不动。  
10. 涉密定稿、印发终审，**仍然是人**。

## 八、一周试点怎么排，避免一上来全员铺开

- **第 1 天**：信息中心装包，打开 WPS，healthz 确认在线，模型只接内网端点。
- **第 2 天**：选两名文书，用故意造错的测试稿跑预览与写批注，不碰正式红头。
- **第 3 天**：引入一份真实但非涉密的旧制度稿，只出批注，不改正文。
- **第 4 天**：把开场白写进科室备忘录，统一「确认写批注 / 确认替换」口径。
- **第 5 天**：复盘误报与锚点问题，决定是否扩大到更多处室。

试点期正式涉密稿一律不进；公共演示机不存个人云密钥。这两条写进纪要，后面的推广阻力会小很多。长文与多文档是进阶能力，试点成功后再读《长文档怎么审：meta、chunks，而不是一次读完全文》《多文档交叉校对：先打开谁、怎么切换、如何避免串稿》。

## 九、信息中心常见三问（先答完再推广到业务科）

**问：断网能不能用？**  
答：能。前提是模型推理也在本机或内网。加载项与 MCP 不依赖公网即可完成文档读写。

**问：和 WPS 自带 AI 什么关系？**  
答：不是同一个产品。察元是独立加载项，强调自管模型与本机工具暴露。并行与否看单位加载项管理策略。

**问：出了错谁负责？**  
答：流程上应是「确认人」负责放行。所以默认禁止未确认改正文，培训里反复练「确认写批注」这句口令。

## 十、为什么这篇会被转，而不是又一篇参数评测

同事转发时，需要显得**既懂热点又懂规矩**。内网、不出域、批注留痕，三样齐了，才有社交上的「站得住」。纯参数对比在机关群里不好转：领导看不懂，文书用不上，保密员还要皱眉。

如果你只记三句，建议截图：

- **材料不出域，不是口号，是默认值。** MCP 只绑本机回环，模型走内网，正文不离开 WPS。
- **先预览，再点头；没有确认，一个字都改不了。** `CONFIRMATION_REQUIRED` 是设计，不是故障。
- **它替你挑错，不替你担责。** 终审、定密、印发，仍然是人。

如果你要向领导汇报一句话：「我们在国产 WPS 里接上了文档智能体，模型走内网，改动留批注、人来确认，材料不出单位。」

机关要的不是更会聊天的网页，而是国产 WPS 里**可复核的审查痕迹**。智能体进机关，最先打通的不该是热闹的演示环境，而是内网、国产 WPS、不上传、可确认写回这条冷板凳。按本文闭环做完，再去追更细的端口、分块、多文档文章不迟。
