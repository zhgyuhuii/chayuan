# 察元AI文档助手替代聊天框：稿子不出电脑的校对方式

今天说个老话题，但天天还在发生。办公室里最常见的 AI 用法，是打开网页大模型，把文档正文整段复制进去，问帮我校对一下。

先说安全。正文一离开你的电脑，去了哪里、存没存、会不会变成训练语料，你说了不算。合同、报告、内部材料，这一粘风险就出去了。再说效率，模型回你一段话，说第二段的得字用错了，然后你在浏览器和文档之间来回切换，人工找第二段在哪，改到一半发现它把对的数字读错了，两小时过去还得自己通读一遍才敢交。

问题的根子是聊天框里没有你的文档。正常的做法是让智能体直接进文档干活，察元AI文档助手就是这么一套。

下载安装。官网 aidooo.com 下载安装器，双击装完重启 WPS。或者用官网那行 PowerShell 一行命令，自动装完还跑一遍自检。

配置。终端执行 claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp，智能体接入。服务只监听本机回环地址，不要 token，外网碰不到。

验证。浏览器打开 http://127.0.0.1:62588/healthz，返回 ok 即通，WPS 加载项右上角也有连接状态。

测试。说一句：读当前文档第一段。返回的内容和原文一致，链路就是好的。

使用。之后你对智能体说的就都是人话了。它自己读原文、自己定位、意见挂批注，正文不动，谁确认谁修改全程留痕。两条路的差别一句话说清，粘过去是文档迁就模型，连上去是模型进了你的文档。

提示词给三条。
一、把当前文档校对一遍，意见挂成批注，先给我清单确认。
二、只查错别字和序号问题，其他不用管。
三、校对完把问题按类型汇总成一份清单，我先看再定哪些写回。

今天 4.1.2 版本刚更新，服务后台安静运行，连窗口都不弹。你交出去的只有指令，稿子始终在你电脑里。
