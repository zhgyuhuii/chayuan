# Claude 自动审查提示词库：可复制开场白与场景口令

下面提示词面向察元 AI 文档助手 v4.0 与本机 MCP 服务 chayuan-wps-mcp，可直接粘贴到 Claude Code。默认假设：WPS 已打开目标文档，healthz 在线，模型已配置。未装好链路先看：[生命周期总览](./01-lifecycle-claude-wps-review.md)、[本机 MCP](./02-mcp-localhost-chayuan-wps-mcp.md)、[模型配置](./03-model-provider-setup-proofread.md)、[预览批注替换工作流](./04-preview-comment-replace-workflow.md)。

## 固定开场白（推荐每次审查先贴）

```
你通过 chayuan-wps-mcp 对当前 WPS 文件做自动审查。先做校对预览，列出错别字、标点和明显病句。等我回复确认写批注后，再写批注，且尽量钉在具体文字上，尤其是表格。没有我说确认替换，不要改正文。最后按严重、一般、建议三级给我摘要。
```

短版：

```
你通过 chayuan-wps-mcp 操作当前 WPS 文档。先预览，不要改正文。列出问题后等我确认。我回复确认写批注后才写批注，钉在具体文字上。没有确认替换，禁止改正文。
```

## 只读冒烟与预览冒烟

### 只读冒烟

```
通过 chayuan-wps-mcp 告诉我当前活动文档的文件名和大概字数，不要改正文，不要写批注。
```

### 校对预览冒烟

```
对当前文档做校对预览，列出错别字和标点问题，不要写批注，不要改正文。
```

![只读冒烟对话回报文件名与字数](images/csdn-05-2.png)

## 错别字与同音字

```
帮我检查文档中的错别字，用批注标出原文和建议改法。
```

```
只检查当前选区的错别字，先预览不要写批注。
```

```
排查同音别字，例如的地得、象像、做作，批注说明理由。
```

```
检查成语是否写错或误用，批注纠正。
```

注意：上面含「用批注」的句子，仍建议先预览再口头确认写批注，避免一上来就写回。

## 标点与公文体例

```
帮我检查标点符号是否正确，包括中英文标点混用、引号和书名号配对，用批注标出。
```

```
按公文习惯检查标题、主送、落款、附件说明是否缺项，只批注不改字。
```

```
检查标题和条款序号层级是否混乱，批注指出。
```

## 表格锚点

```
重点检查表格单元格里的错别字，批注必须钉在具体错字上，不要挂到整格。
```

```
对表格做校对预览，每条问题注明行列或单元格上下文，不要写批注，不要改正文。
```

![表格校对预览条目示例](images/csdn-05-3.png)

## 正确性总检

```
帮我核对这篇文章的正确性：错别字、标点、语法、前后矛盾一并查，先预览列表，我确认后再写批注。
```

```
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注。
```

## 多文档

```
打开路径某某.docx，确认它是当前活动文档后，做错别字校对预览；我确认写批注后再写批注，并另存为某某-已校对.docx。
```

把「某某」换成真实路径。路径含空格时，按客户端习惯加引号。打开失败先在 WPS 里手动打开再检。

按第 2、4、6 条确认替换，其余只保留批注。

## 场景组合示例

### 公文快审

先贴固定开场白，再追加：按公文习惯检查标题、主送、落款、附件说明是否缺项，只预览。确认后再写批注，不替换。

### 合同数字敏感

先贴固定开场白，再追加：涉及金额、日期、比例的条目只批注不替换，必须我逐条确认替换。

### 表格密集制度稿

先贴固定开场白，再追加：表格批注必须钉在单元格具体错字上；预览阶段注明单元格上下文。

## 常见误用与纠正

误用：直接说「把全文改到没有错别字」。纠正：改回预览口令，并声明禁止未确认替换。

误用：预览后只回「嗯」。纠正：使用「确认写批注」等明确口令。

误用：模型未配置就贴长提示词。纠正：先在加载项自测模型，见模型配置文。

误用：healthz 不通仍贴审查词。纠正：先打开 WPS 与 sidecar，访问 healthz。

## 保存与复用

把固定开场白存进 Claude Code 项目说明或片段库。科室培训印发一页「口令卡」：预览、确认写批注、确认替换、按条确认替换。源码与更多工具说明见 [https://github.com/zhgyuhuii/chayuan.git](https://github.com/zhgyuhuii/chayuan.git)。

提示词不替代门禁。真正写回仍以 WPS 批注窗格与另存文件为准。把口令用稳，自动审查才可复核。

## 把提示词放进客户端的方式

Claude Code 可以把固定开场白放进项目说明或常用片段，避免每次手打。放的时候保留「先预览」「确认写批注」「没有确认替换禁止改正文」三句硬约束，不要为了省字删掉。若团队同时使用 Cursor 或 Codex，同一套中文口令可以共用，差别只在 MCP 配置文件格式。不要在开场白里塞入密钥、内网网关地址或文档绝对路径中的个人目录名，那些应放在本机配置或当次对话。

## 提示词失效时怎么收束

若模型开始直接改字，立刻停止并另存当前文件，用只读冒烟指令重新校准。若模型只给摘要不给条目，追加一句：「按条输出，每条包含原文片段、建议、理由，不要只给段落大意。」若表格锚点漂移，追加：「批注必须钉在单元格内具体错字，禁止挂整格。」同一轮对话里约束被稀释时，新开对话并重新粘贴开场白，通常比继续争辩更省时间。

## 开场白为什么要写三句硬约束

第一句指定经 chayuan-wps-mcp 操作当前 WPS 文档，避免模型改去聊天里的粘贴文本。第二句锁定先预览，防止一上来写回。第三句把确认写批注与确认替换拆开，防止「确认」被理解成可以改字。删掉任何一句，都会在某次长对话里出现越权写回。省字不是优化，是在拆门禁。

若客户端已有项目级系统说明，仍建议在每次重要审查的首条用户消息粘贴短版开场白。系统说明负责长期习惯，首条消息负责当次生效。

## 按严重级别要摘要时怎么补一句

在开场白末尾保留「按严重、一般、建议三级给我摘要」即可。若模型把摘要写成空话，追加：摘要必须引用条目编号，每级至少列出编号列表。不要为了摘要取消条目化输出。条目是确认写批注的依据，摘要只是给人看的目录。

## 选区审查提示词

```
只对当前选区做校对预览，列出错别字和标点问题，不要写批注，不要改正文。选区以外的正文一律忽略。
```

```
只对当前选区确认写批注，钉在具体文字上，不要改正文，不要处理选区以外内容。
```

选区路径适合局部返工，例如只改表格某一部分。使用前在 WPS 里确认选区正确，口令里写明「当前选区」。

## 禁止写回的强化句

当模型在对话中表现出想直接改字时，立即发送：

```
停止改正文。本次只允许校对预览。没有我发送确认写批注，禁止写批注。没有我发送确认替换，禁止替换。
```

然后要求它重新输出预览列表。必要时新开对话，重新粘贴固定开场白。不要和模型在同一线程里反复争论「你刚才是不是已经改了」，以 WPS 文件内容为准做核对。

## 给培训学员的最小口令集

学员第一天只练四句：只读冒烟句；校对预览冒烟句；确认写批注；确认替换。全部练顺，再开放同音字、公文缺项、表格锚点等加长提示词。口令集打印成一页，比发长文更管用。教员演示时故意触发一次 CONFIRMATION_REQUIRED，让学员看见门禁长什么样，避免以后误以为系统坏了。

## 提示词与模型能力的分工

提示词不能补齐「模型太小不会给原文片段」的能力缺口。若加载项自测已显示条目空洞，先换模型，再谈提示词技巧。提示词能做的是约束流程与输出形状：先预览、要条目、要锚点、要确认。把两者分工讲清，学员才不会迷信「再写一段更长的提示词就能修好一切」。

## 多人文档的口令策略

多人轮流改同一份制度稿时，约定统一使用「确认写批注」而不是各自发明同义句，便于审计对话记录。替换必须点名条目编号。另存文件名带日期与处理人缩写。提示词本身保持中性，不写个人情绪化指令，减少不同学员输出风格漂移。

## 把本库当清单而不是小说

使用方式：复制固定开场白；按场景追加一节中的一条；预览后用确认口令收束。不要一次粘贴本页全部示例，模型会在互相冲突的指令里摆荡。每次审查只激活一个主场景，需要时再开新对话切换场景。保持短、可复制、可复核，就是这份提示词库的目标。

## 输出格式约束提示词

需要更整齐的列表时，在预览口令后追加：

```
每条问题用固定字段输出：编号、原文片段、建议、理由、级别。不要合并多条，不要省略原文片段。
```

需要限制范围时追加：

```
本次只检查错别字和标点，不评价文风，不改写段落结构，不扩展内容。
```

这类约束能减少「顺便帮你润色」带来的意外写回压力。润色与校对是不同任务；本库默认只做校对审查。

## 口令与文件名对照表示例

审查开始前记下：原文件名、另存副本名、计划口令阶段。例如：原件合同-草案.docx；副本合同-草案-校对中.docx；阶段预览已完成；阶段批注待确认；阶段替换未开始。对照表写在纸上或会议纪要里即可。提示词负责驱动工具，对照表负责驱动人。两者一起用，自动审查才有审计痕迹。

处理结束后，把最终「已校对」文件名与是否执行过确认替换写一行结论。没有结论的对话记录，事后很难判断正文是否被改过。
