# 多文档交叉校对：先打开谁、怎么切换、如何避免串稿

实际工作很少只有一份稿。招标文件与投标响应、合同正文与附件清单、请示与说明材料、上一版与本版口径，都需要交叉看。Claude Code 经本机 MCP 服务 `chayuan-wps-mcp`（`http://127.0.0.1:62588/mcp`）可以调用 `document_open` / `document_ensure_open` 把指定路径的 docx 变成当前活动文档，再对活动文档做预览与批注。交叉校对的核心风险不是「模型不够聪明」，而是审着 A 却写到 B、术语表混乱、未确认就批量替换。本文给可执行的切换顺序与话术。

先确认 `http://127.0.0.1:62588/healthz` 为 online。安装接通见 [全生命周期安装与审查](./01-lifecycle-install-to-claude.md)；长文单文件分块见 [长文档分块审查](./07-long-doc-chunk-review.md)。

## 交叉校对到底在对什么

把需求拆成三类，避免一句「帮我交叉证明」让模型自由发挥。

### 术语与专名一致

同一机构名、项目名、缩写在多份材料中是否统一。例如「察元」与错误写法混用、中英文缩写两套并存。

### 数字与日期勾稽

正文金额与附表是否一致；工期起止是否互相矛盾；「附件 3」是否真有附件 3。

### 条款与响应映射

招标要求条目是否在响应文件中有对应段落。这类更偏清单核对，批注应写清「源文档条款号 → 目标文档位置」。

三类问题可以分轮次做。第一轮各文件各自错别字，第二轮术语表，第三轮数字与条款映射。混在一轮里，预览列表会难以确认。

## 关键工具：打开、确保、状态

### document_open

打开本地 `.docx` 为活动文档（可见窗口）。路径必须是本机可访问路径。打开后应用 `wps_status` 或只读询问核对文件名，防止路径写错却继续审。

### document_ensure_open

与活动文档一致则 no-op，否则打开。适合脚本式循环：「确保 A 打开 → 审 → 确保 B 打开 → 审」。

### wps_status

分层健康：sidecar、Agent、活动文档、可见窗口。交叉校对前先看活动文档名是否就是你以为的那份。Agent 离线时会出现 `WPS_AGENT_OFFLINE`，先开 WPS 与察元加载项，再刷 healthz。

## 推荐工作流（两人也能照做）

### 步骤 1：建工作目录与命名

把待审文件放进同一目录，文件名可读：

```text
01-招标文件.docx
02-投标响应.docx
03-报价表.docx
```

重要稿先复制副本再审，避免直接写回原件。

### 步骤 2：固定开场白

```text
你通过 chayuan-wps-mcp 做多文档交叉校对。
规则：
1）每次审查前用 document_open 或 document_ensure_open 固定活动文档，并回报文件名。
2）单文件先做校对预览，不要写批注、不要改正文。
3）全部单文件预览完成后，再做交叉项：术语、数字、附件引用。
4）交叉问题要写明源文件与目标文件。
5）我回复「确认写批注」后，你必须再次确认当前活动文档，再写批注。
6）没有「确认替换」禁止改正文。
表格批注钉在单元格具体错字上，不要挂整格。
```

### 步骤 3：单文件预览循环

对 Claude：

```text
打开 /path/01-招标文件.docx，确认活动文档后做错别字与标点预览，只出列表。
```

完成后再开第二份。不要在第一份尚未出列表时并行打开一堆窗口指望模型自己记清。

### 步骤 4：出交叉表

```text
基于刚才三份预览，列出交叉问题表，列：问题类型、源文件、原文、目标文件、目标原文或缺失说明、建议。
不要写批注。
```

### 步骤 5：按文件确认写回

```text
打开 02-投标响应.docx，确认是活动文档后，对交叉表中属于该文件的第 1、3、4 条确认写批注。
```

一次只写一份文件，写完保存，再切下一份。这是防止串稿的硬规矩。

## 活动文档纪律（写进科室规范）

1. 任何写操作前，对话里必须出现一次当前文件名回报。
2. 用户确认语句建议带文件名：「对 02-投标响应.docx 确认写批注」。
3. 发现批注出现在错误文件：立即停止替换，保留副本，检查最近一次 open 是否成功。
4. 不在交叉轮次使用「全部文件确认替换」这类句子。

`document_add_comment` 与 `proofread_apply_comments` 都需要确认才会落盘；但确认对象若指向错误活动文档，批注仍会写到错误文件。确认解决的是「可不可以写」，解决不了「写到谁」。活动文档纪律补的是后一问。

## 与长文、表格的组合

交叉校对的某一份经常是长文。对该文件单独套用 chunks 剧本：meta → chunks → 预览，见 [长文档分块审查](./07-long-doc-chunk-review.md)。报价表、人员表多的文件，追加表格锚点约束，见 [表格批注锚点](./06-table-comment-anchor.md)。

组合提示词示例：

```text
打开 03-报价表.docx。
document_meta 后若需分块则 chunks 阅读。
重点检查表内错别字与单位列不一致；批注钉在具体错字上。
先预览。
```

## 术语表怎么建才有用

让 Claude 在第一轮结束时产出「候选术语表」，人改一版再冻结：

```text
从已打开的文档中抽取专有名词与缩写，列出：规范写法、错误/歧义写法、出现文件。
不要写批注。等我确认术语表后再进入交叉批注。
```

冻结后的术语表作为后续指令附件：

```text
术语表以我下一条消息为准。发现冲突只批注，不自行统一替换。
```

需要统一替换时，按文件、按词条确认：

```text
在 02-投标响应.docx 中，把「永鹅」预览替换为「咏鹅」，先出命中列表。
```

确认替换话术与安全边界见 [确认策略与安全边界](./14-confirm-strategy-safety.md)。

## 常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 批注写到另一份稿 | 未重新 open / 未核对活动文档 | 写回前强制回报文件名；按文件确认 |
| 打开失败 | 路径错、文件被占用、非 docx | 核对绝对路径；关闭独占打开；另存 docx |
| WPS_AGENT_OFFLINE | WPS 或加载项未就绪 | 打开 WPS，刷 healthz |
| 交叉表很空 | 只做了单文件错别字 | 明确第二轮交叉指令 |
| 列表有、批注无 | 未确认写批注 | 用户明确确认 |
| 两份都改了同一口径 | 并行写回 | 串行按文件写回并保存 |

四级连通验证见 [healthz 与四级验证](./09-healthz-four-level-verify.md)。若工具列表都没有 `document_open`，先回到 MCP 安装验收，而不是继续叠提示词。

## 示例：请示 + 说明 + 附件清单

材料：

1. 请示正文
2. 情况说明
3. 附件清单

目标：错别字各自清理；「附件 2」在正文与清单中一致；金额三处一致。

执行提纲：

1. healthz online；Claude 已添加 `chayuan-wps-mcp`（参见 [Claude MCP 文档](https://code.claude.com/docs/en/mcp)）。
2. 依次 open 三份，各做 dryRun 预览。
3. 要交叉表：附件引用、金额、日期。
4. 人确认：说明材料第 2 条金额以请示为准；清单补附件 2 标题。
5. 对说明材料确认写批注；对清单确认写批注；请示仅保留预览中的错别字批注。
6. 各自另存。

不要让模型「直接改到一致」——一致是业务决策，批注是提示决策。签发前仍以人工为准。

## 和加载项路径怎么配合

同事只熟悉 WPS 界面时，可以每人打开一份用加载项「拼写与语法检查」做单文件硬伤，再由熟悉 Claude 的同事做交叉轮。加载项不负责自动在多份 docx 之间调度活动文档；跨文件编排是 MCP 客户端的强项。选型对比见 [加载项内置检查对比 Claude MCP](./10-addon-vs-claude-mcp.md)。

## 可复制指令包

### 只读盘点

```text
列出当前可打开的目标路径计划，不要打开文件。
我会逐条给你路径。
```

### 打开并回报

```text
document_open 路径X，回报活动文档文件名与字数，不要校对。
```

### 单文件预览

```text
对当前活动文档校对预览，出错别字与标点列表；不要写批注。
```

### 交叉

```text
比较 A 与 B 的项目名称与金额，列出不一致；注明两边原文；不要写批注。
```

### 写回

```text
确保打开 B，确认文件名后，对交叉表第 2、5 条确认写批注。
```

## 路径与权限的实际问题

### 路径写法

Windows 路径含反斜杠时，在 JSON 或某些客户端里需要转义。更稳的做法是让用户在对话里粘贴资源管理器地址栏的完整路径，Claude 再原样传给 `document_open`。路径含空格不必改名，但含未同步的网络盘字母时，WPS 进程是否看得到该盘，要以实际打开为准。

### 文件占用

「正被另一用户锁定」或本地只读会导致打开失败或保存失败。交叉写回前确认副本可写。不要在 Outlook 预览窗里打开的文件上直接审——先另存到工作目录。

### 版本混淆

`01-招标文件.docx` 与 `01-招标文件-最终版.docx` 并存时，open 错文件的概率很高。开场前先让 Claude 只读盘点路径计划，人回复「只用带最终版的那份」，再进入 open。盘点本身不写任何批注。

## 交叉表的推荐列

强制模型按下列输出，审核更快：

1. 问题类型：术语 / 数字 / 日期 / 附件引用 / 条款映射 / 其他
2. 源文件名
3. 源原文（短）
4. 目标文件名
5. 目标原文或「缺失」
6. 建议
7. 严重级别：严重 / 一般 / 建议
8. 计划写回文件（只能是其中一个）

第 8 列是防串稿关键列。确认写批注时按「计划写回文件」分组执行，而不是按严重级别跨文件乱序写。

## 三人分工怎么排

1. 甲：负责单文件错别字（可用加载项）。
2. 乙：负责在 Claude 里跑交叉表。
3. 丙：负责按文件确认写回与抽查。

甲的输出可以是批注已存在的文件；乙不要清掉甲的批注，只追加交叉问题。丙在写回前用 WPS 批注窗格过滤作者或时间，避免误删。若只有一人，也按三角色的时间盒切换，不要在同一分钟又交叉又替换。

## 数字勾稽的特殊要求

金额、税率、百分比最容易「看起来一样」。要求模型输出时保留原文中的全部数字字符，不要自行四舍五入。人用计算器核一遍严重项。对「约」「左右」类模糊表述，批注只提醒风险，不擅自改成精确值——那是业务口径。

表内数字再套用表格锚点规则：批注钉在数字本身，不要挂整格。详见表格篇。

## 失败演练（建议装机第二天做）

故意制造两次失败，确认同事会停手而不是硬推：

1. 让 Claude 在 A 文件预览后，不 open B 就对 B 的问题「确认写批注」。期望：被开场白拦截，或写前回报的文件名暴露错误。
2. 关掉 WPS 再请求预览。期望：`WPS_AGENT_OFFLINE` 或 healthz 非 online，回到开 WPS。

两次演练比再讲十分钟理论更有效。

## 与长文分块叠加时的会话预算

三份长文交叉，强行塞进一次 Claude 会话，往往会丢开场白。拆法：

1. 会话 1：文件 A chunks 预览 → 导出列表。
2. 会话 2：文件 B、C 同理。
3. 会话 3：只贴三份列表做交叉，不写回。
4. 会话 4：按文件 open + 确认写批注。

会话 3 是纯文本推理也可以，但写回必须回到 MCP 工具并核对活动文档。长文细节见长文档篇；连通验收见四级验证篇。

## 小结

多文档交叉校对的工程问题是会话状态：活动文档是唯一写回目标。`document_open` / `document_ensure_open` 把状态改正确；开场白与确认话术把人的注意力绑在文件名上；预览与「确认写批注」把写回变成受控动作。按「先单文件、后交叉、再按文件写回」走，串稿概率会明显下降。剩下的术语该统一成哪一个，交给业务，不要交给默认采样。把交叉表第 8 列「计划写回文件」变成科室模板字段，串稿问题会从「事后追责」变成「事前可见」。
