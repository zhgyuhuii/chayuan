# 2026 Agent 元年：MCP 为什么成了 AI 工具界的 USB 口

上个月帮一个写公文的朋友折腾 AI 工作流，他跟我倒苦水：想让 AI 帮忙看文档，得把文件导出来、上传到某个网页，改完再下载回来贴回去；换一个 AI 工具，整套流程又得重学一遍。我听完就想起九十年代装机的感觉——鼠标是串口的，键盘是 PS/2 的，打印机还有自己的专用卡，每接一个新设备，背后都是一套专属插口和驱动。

后来 USB 出现，事情变简单了：设备方只要造一个标准插头，电脑方只留一个标准口，即插即用。2026 年被很多人称作 Agent 元年，AI 智能体要连接的工具越来越多，大家慢慢想明白一个道理：缺的不是更聪明的模型，而是一个统一的"插口"。

这个插口，就是 MCP（Model Context Protocol）。

## 从各自为政到统一插口

在 MCP 之前，AI 接工具基本是"一事一议"：接 A 家的产品写一套胶水代码，接 B 家的再写一套，模型换一代，对接层跟着改一遍。工具方累，客户端也累，最后大家干脆只接自家生态，岛越连越多，桥却没人修。MCP 把这件事标准化了——工具方实现一次 MCP 服务，任何支持 MCP 的客户端都能连；客户端接上一次，就能使用生态里所有的 MCP 工具。

这个协议由 Anthropic 发起并开放，这两年被各家客户端快速跟进：Claude Code、OpenAI Codex CLI、Cursor、Cline……叫得出名字的 AI 智能体基本都把 MCP 当成了标配接口。生态一旦统一，就有了 USB 式的网络效应：工具方愿意做 MCP 服务，是因为客户端多；客户端愿意支持 MCP，是因为工具多。2026 年 MCP 生态的爆发，本质上就是这张网络长出了临界规模。

## 一个真实的"USB 设备"：WPS 里的文档 MCP

光讲协议有点虚，说个我手上在用的例子。察元AI文档助手（开源项目，Apache-2.0 协议，当前版本 4.1.2）是 WPS 文字的智能加载项，装好之后会在本机起一个 MCP 文档智能体服务，监听 127.0.0.1:62588，走 Streamable HTTP 传输。它对外暴露 46 个文档工具：读正文、圈错别字、写批注、批量替换、插表格行列、多文档交叉校对，都在工具目录里。

对客户端来说，这就是一个标准的"USB 设备"。以 Claude Code 为例，接上它只要一条命令：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

Cursor 里是往 `.cursor/mcp.json` 写一段 JSON；OpenAI Codex CLI 里是往 `~/.codex/config.toml` 加两行。同一个 MCP 服务端，三个客户端零改动复用——这就是标准插口的意义：工具方实现一次，处处可连。

## 判断一个 MCP 服务值不值得接，我看三点

现在 MCP 服务如雨后春笋，我的筛选标准就三条。一看传输是否标准：走 Streamable HTTP 的服务不挑客户端、不挑运行时，任何一个支持 HTTP 型 MCP 的智能体都能连；察元的 MCP 服务是单文件二进制，装完自启，连 Node.js 都不用装。二看工具目录是否清晰：职责单一、参数明确的工具，AI 才不容易用错；察元的 46 个工具按读取、写回、批注、表格、脱密分得清清楚楚。三看写操作有没有确认机制：改文档默认先出 preview 预览、确认后才落盘，误伤可挡。这三条它都占，连健康检查都有现成的 `http://127.0.0.1:62588/healthz`，返回 online 一验便知。

## 为什么"本机 MCP"值得单独一说

MCP 服务有跑在本机的，也有托管在云上的。文档类场景我更倾向本机服务，原因很直接：文档在你电脑上的 WPS 进程里，MCP 服务也在本机，AI 读完写回，数据全程在 127.0.0.1 里打转，不用把正文传到哪个远端服务器，"数据不出域"是结构保证而不是口头承诺。内网办公、信创环境对这类形态也天然友好——模型侧还能对接 Ollama、LM Studio、Xinference 这类本地推理端点，整条链路都可以不出网。

当然要把边界说清楚：MCP 解决的是"接口标准"问题，不解决"AI 一定对"的问题。它让 AI 有了规范的手，但改什么、批注什么，最终还是要人过目。这也是成熟的 MCP 文档工具会把写操作设计成"先预览、确认后才落盘"的原因——这个话题值得单独展开，后面写一篇细说。

如果你 2026 年的清单里有"让 AI 真正干活"这一条，我的建议是：挑一个顺手的 MCP 客户端，连一个解决真实痛点的小工具，从一个小场景跑通。别一上来就想搭宏大工作流。USB 口再标准，也得先插上一个你真会用的设备。
