# 答辩讲稿写得像论文：通俗化改写救场

答辩倒计时七十二小时，我把第一版讲稿发给了导师。晚上十点，微信语音一条接一条进来，就一个意思：这是论文摘要的朗读版，不是讲稿。预演的时候他当场打断了我三次："你在念论文""评委里只有一个是你的小同行""这句话你自己听得懂吗？"挂了语音我重新看那份讲稿，八千字，通篇"基于某某框架的某某方法研究"，长句套长句，术语摞术语——写得确实像论文，问题恰恰是它像论文。

答辩的本质很容易被忘掉：把两三年的工作，在十五分钟里讲给一个委员会听——主席可能是隔壁方向的专家，秘书可能完全不做你这个课题。讲稿不是论文的压缩版，是另一篇文章。那七十二小时里救我命的是 WPS 里的察元AI文档助手，内置的"通俗化改写"和"换种方式重写"两个助手，加上三步流程。

## 第一步：先理主线，别急着改句子

拿着论文乱改句子是没用的，先定主线。用"生成摘要"和"提炼关键词"两个助手把各章核心结论拉出来，然后按四问重排：

```
提炼论文各章核心结论，按"为什么做、怎么做、做出什么、意味着什么"排成答辩主线，标注每部分建议的分钟数
```

十五分钟的四问分配，我的版本是：为什么做两分钟，怎么做四分钟，做出什么七分钟，意味着什么两分钟。时间分配本身就是取舍——哪章在讲稿里只剩一句话，想清楚了再动笔，比写完再砍从容得多。

## 第二步：逐段通俗化

主线定了再改句子。选中讲稿的一段段处理：

```
把选中的讲稿段落改成口语表达，长句拆短句，专业术语后面跟一句大白话解释，先只生成结果不替换原文
```

三个要点是那晚摸出来的。一，长句必拆：论文里五十字一句的定语从句，口语里一句超过二十字就该断。二，术语后面跟一句大白话：公式讲不了，就讲它直觉上在干什么；缩写第一次出现必须给全称加解释，评委手里没有你的符号表。三，"先只生成结果"：改写版和原稿对照着看，通俗化最容易丢的是准确性，一句句对回去。

有个分寸要拿捏：学术场合的通俗化不是网文化。比喻慎用，用就必须准；"简单来说"这种口头语可以有，"绝绝子"这种没有。改完的稿子别只默读，出声念一遍，舌头打绊的地方就是还长得不像人话的地方。

## 第三步：掐表演练，预设提问

讲稿是拿来讲的，不是拿来看的。字数除以语速只是理论时长，真实节奏得开口练。察元内置了"文本转语音"助手，我让把讲稿读出来，对着听：哪一段听着走神、哪一句听完没接上，位置立即暴露，比默读改稿高效得多。最后再自己对着镜子讲两遍，两遍都超时就砍内容，别加快语速——紧张时人会不自觉加速，平时就得留余量。

问答环节是真正的生死关。用"提取结论与风险"的思路反向准备：

```
提取论文的结论与局限，帮我预设评委可能追问的问题，并给每个问题配一个三十秒的回答思路
```

被预演打断的那晚，导师补了一句很实在的话："你怕的不是不会答，是没想过会被问。"局限性、对照组设置、统计显著性和创新点与已有工作的差异，这四类问题几乎必考。每个问题三十秒的回答思路写下来，比押题背长答案可靠得多——因为三十秒思路能现场扩展，长答案背岔了就全盘崩。

## 边界

通俗化不能以牺牲准确为代价，这是底线。改写完的讲稿要和论文做一次数字核对——讲稿里说的每个数、每张 PPT 上的每个数，必须和论文正文、图表同源，这活正好用数字勾稽：

```
核对讲稿和幻灯片备注里的数字与论文正文、图表是否一致，不一致的用批注标出
```

正式答辩那天，我在"怎么做"环节看到主席点了点头。下一位同学的讲稿念到第三分钟就被打断了。答辩练的是把复杂的东西讲简单的能力，这个本事毕业以后走到哪儿都用得上——那七十二小时还让我明白一件事：能把两三年的工作讲给外行听懂，才算真的懂了。
