# 合并单元格不用鼠标拖：cell_merge 的同行同列规则

合并单元格是表格排版里的高频动作：两级表头、分组统计、报名表、组织架构图，都离不开它。以前全靠选中拖拽，现在可以把这活交给 AI，但要用好它，得先弄懂 cell_merge 的规则。这篇用问答把机制讲透，看完你就知道哪些合并一句话能办，哪些得拆步走。

## 问：cell_merge 的规则到底是什么？

就两条：选中的单元格在同一行，合并的是列，也就是横向并成一格；在同一列，合并的是行，也就是纵向并成一格。同行等于合并列，同列等于合并行，没有第三种情况。规则简单到一句话说完，但这一句话就是工具的全部行为边界。

两条规则各自对应最典型的场景：工资表表头的"工资总额"横跨"基本工资""绩效工资"两列，是同行合并；报名表最左列的组名竖跨五十行，是同列合并。拿到表格先想清楚目标长什么样，再往规则上套，指令就下得准。

## 问：为什么只设计两条规则？

这是防幻觉的取舍。"把表头合并一下"这种模糊指令，自由度太大，模型理解稍有偏差就合并错位，而表格结构一旦改错，回滚成本很高——尤其带数据的表，错一次可能整版重做。把规则收敛成同行、同列两种显式情况，AI 的发挥空间被压到最小：它只需要正确判断"这几个格子是不是同一行、同一列"，剩下的交给坐标执行。工具按显式坐标办事，出错概率随自由度一起降下来，这是显式坐标防幻觉思路在表格场景里最典型的体现。

## 问：两级表头这种复杂结构怎么办？

拆步走。比如"上半年"下面分"一月""二月"，先下第一条指令合并第一层的同行单元格，确认无误后再处理第二层。每步一条指令、每次一个动作，过程可核对。想更稳，可以让 AI 先出方案再执行：

```
先读表头，把每个单元格的行列位置列出来，标出哪些适合同行合并、哪些适合同列合并，先给方案不要执行
```

方案过了目再动手，比盲改踏实得多。复杂表头从来不是能力问题，是顺序问题。

## 问：具体指令怎么下？

两个可直接复制的例子：

```
把表头第一行的"工资总额"和它右边的空白单元格合并
```

```
把第一列的第2到第5行纵向合并成一个单元格
```

第一条是同行合并（横向），第二条是同列合并（纵向）。指令里带上"第一行""第2到第5行"这类位置信息，AI 的定位工作就越少，执行越准。拆开看，一条合格的合并指令有三个要素：对象（合并哪些格子）、位置（在第几行第几列）、方向（横向还是纵向）。三样说全，基本不会错；三样缺一，就全靠 AI 猜，猜错你还得返工。位置说清楚，是跟表格工具打交道的通用礼节。

## 问：怎么快速判断该用哪条规则？

方法很土但可靠：把要合并的格子的行列号写出来。行号全部相同，就是同行合并；列号全部相同，就是同列合并；行号列号都不齐，说明你想一次性跨行又跨列——那就拆成两步，先横后纵或先纵后横，中间核对一次再走第二步。判断成本十秒钟，返工成本半个钟头，这笔账很好算。

## 问：合并错了怎么兜底？

合并是结构性改动，我的习惯是动手前先另存一份版本，保存接口支持另存为。版本兜底比事后补救可靠——尤其是要上报的正式表格，永远别在唯一的原件上直接做结构操作。这不是对工具没信心，是对任何自动化都没信心，包括自己点鼠标的手。

## 一点延伸

cell_merge 只是表格域十二个 action 中的一个，配合插行插列、列宽调整这些结构操作，常见的表格排版活基本覆盖。再叠加上切片读的"先读表头再动手"，一套"先看清楚、再改结构"的工作流就齐了：读结构、出方案、按坐标执行、版本兜底，四步走完，表格结构活基本不用碰鼠标。

适合谁：做统计报表、申报材料、组织架构表、考勤汇总的人，尤其是表格长相有合规要求的场景。边界照例讲清：规则简单不代表可以省确认，每一步执行前扫一眼方案，正式表留好副本。把"拖拽合并"换成"坐标合并"，省的不只是鼠标移动的距离，是错位重做的整个下午。
