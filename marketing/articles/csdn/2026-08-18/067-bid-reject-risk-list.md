# 废标风险自查：格式、签字页、附件引用清单

做投标的人都知道一个残酷的事实：废标很少输在方案上，绝大多数栽在形式审查——格式不符、签字页缺失、附件引用断链这些低级错误。而形式问题的特点是：每一个单独看都查得出来，合在一起就是查不全，交标前夜人已经不是最佳状态了。这篇把我这些年攒的废标风险自查清单整理出来，七项，每一条标注"用什么工具查"。环境是 WPS 加察元AI文档助手（开源加载项加本机 MCP 文档智能体，当前版本 4.1.2），适合投标专员、商务岗在交标前两三天开始跑。

先花一分钟确认环境：浏览器访问 http://127.0.0.1:62588/healthz，返回 online 即服务在线；要让外部 Agent 进文档干活，一条命令注册：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

服务只监听 127.0.0.1，标书从头到尾不出本机。标书岗用 AI 的第一道坎往往是"文档不能出域"，标书涉密不出域是很多公司的红线，这套本机方案正好绕开这个问题，内网机配本地模型端点也能整套跑通。

## 一、编号断档与层级混乱

风险：目录跳号、条款重号、层级体例混乱，符合性审查最容易被圈的地方。

查法：内置助手「检查段落序号格式」一键扫，或者用提示词：

```
检查标题/条款序号（一、（一）、1.）是否层级混乱，批注指出
```

## 二、报价数字勾稽

风险：报价表与正文、开标一览表之间数字不一致，大小写金额对不上，这是最接近"直接出局"的一类。

查法：

```
核对数表与正文数字是否一致（合计、百分比）
```

年限、周期、"含/不含"这类口径词一并对照，问题以批注输出，人工逐条处理。

## 三、签字页与盖章位

风险：签字页漏页、盖章位缺失、授权委托书日期不在有效期内。多人分工排版的标书，这一项是重灾区。

查法：让 Agent 用 document_locate 定位全文所有"签字（盖章）""法定代表人或授权代表""日期"锚点，输出位置清单，逐处人工核对。定位类工具返回命中锚点并做校验，比人眼翻页靠谱。

## 四、附件引用断链

风险："详见附件五"实际只附了四个附件；"见下表 6"的表 6 在砍章节时被删掉了。

查法：

```
把正文里所有"详见附件X""见下表X""见第X章"的引用列成清单，逐条验证目标存在，缺失的用批注标在原句上
```

## 五、目录与题注过期

风险：中途插拔章节后目录页码没更新，图表题注编号断档——打印出来才发现，改一次重排一次。

查法：field 工具可以枚举和构造 SEQ、TOC 域，caption 工具做题注枚举；更新之后机器列清单，人抽查目录页码。这活琐碎，交给机器列、人翻页确认，比纯手工快得多。

## 六、敏感信息漏出

风险：不该出现的身份证号、银行账号、内部项目编号留在对外文件里；密级标识处理不当。

查法：内置「保密检查」助手，对密级标识、涉军涉装、单位身份、联系方式、项目编号、商业秘密分级做风险提示；配合「涉密关键词提取」，再跑一条兜底：

```
查找疑似身份证号、手机号、银行卡号并批注
```

## 七、版面垃圾

风险：空白行、未使用样式导致打印分页错乱，骑缝章位置对不上。

查法：加载项的文档批量能力——删除空白行、清理未使用样式、统计样式，一键收拾干净再重新分页检查。

跑这套清单还有个顺序讲究：先跑格式类（一、五、七），改完重新分页之后，再跑内容类（二、三、四），敏感信息扫描放最后——前面的步骤会往文档里加内容，顺序反了就得重跑一遍。

## 清单之外

七项跑完、所有批注清零，这份自查才算完事。两个边界必须说在前面：第一，各家招标文件的形式要求差异很大，这份清单是通用项，电子标书上传格式、CA 签章、份数装订这类硬性要求，必须逐条对照招标文件本身，工具管不了；第二，自查清单不替代投标负责人的最终核验——工具把"查得全"做了，"担得起"还得是人。废标风险的本质是流程风险，清单的意义就是把流程固定下来，让交标前一天不靠运气，也不靠谁的肉眼。
