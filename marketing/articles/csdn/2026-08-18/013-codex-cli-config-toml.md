# OpenAI Codex CLI 接 WPS：config.toml 三行配置实录

周末给自己派了个活：让 Codex CLI 帮我校对 WPS 里的一份标书。本以为半小时搞定，结果前二十分钟全在踩坑。这篇把坑和最终能跑的配置一起记下来，给同样在用 Codex CLI 的朋友省点时间——毕竟现在终端 Agent 一大堆，每个的 MCP 配法还都不太一样。

## 坑一：用 stdio 的思路去找启动命令

我一开始的惯性思路是：MCP 服务嘛，先找到它的可执行文件，然后在配置里写 command 加 args，用 stdio 子进程的方式拉起来。于是翻仓库找入口、盘算着要不要装 Node——全都多余了。

察元AI文档助手是"WPS 加载项 + 本机服务"的形态，安装脚本跑完之后，MCP 服务（一个单文件二进制）已经在后台运行并注册了开机自启，Windows 上写在注册表 HKCU\Run 里，全程不需要 Node.js。它对外是一个 Streamable HTTP 服务，地址固定为 `http://127.0.0.1:62588/mcp`。换句话说：不需要你去"启动"它，只需要在 Codex 的配置里给它"指个路"。HTTP 型 MCP 和 stdio 型的心智模型完全不同——前者是"服务已在，填地址即可"，后者是"客户端负责拉起进程"。拿老经验硬套，是第一个坑。多想一层就通：本机常驻服务本来就该由系统托管——开机自启、后台常驻、端口固定，客户端只管连。硬要走 stdio，等于让每个客户端各自拉起一份服务进程，反而把简单问题搞复杂。

## 坑二：改了配置不重启会话

config.toml 是 Codex 启动时读取的。改完配置在当前会话里怎么问都没反应，别怀疑人生，退出重进就行。这个低级坑我排了十分钟，写出来希望你别再排一遍。

## 坑三：服务没起来就先配客户端

还有个顺序问题：如果安装环节就没成功，healthz 都不通，客户端配置写得再对也白搭。装的时候留意脚本自带的四级体检输出——jsaddons 目录、healthz、initialize 握手、桥接工具，四步全绿再往下走，别跳过体检直接配 Codex。

## 能跑的三行配置

编辑 `~/.codex/config.toml`，追加：

```toml
# ~/.codex/config.toml
[mcp_servers.chayuan-wps-mcp]
url = "http://127.0.0.1:62588/mcp"
```

标题说的三行，连注释那行刚好三行。没有 command、没有 env、没有 Token——因为这个服务只监听本机回环地址，本机即信任边界，回环上没有"外人"。

## 验证：一条命令加一个界面

重启 Codex 会话之前，先确认服务活着：浏览器打开 `http://127.0.0.1:62588/healthz`，看到 online 即可。想验得更彻底，用官方的 MCP Inspector：

```bash
npx @modelcontextprotocol/inspector
```

传输类型选 Streamable HTTP，地址填上面那个，点 Connect，能看到 46 个文档工具的完整清单，还能手动调几个只读工具试试——比如 wps_status 看分层健康。Inspector 连得上，说明服务侧无可挑剔，剩下的问题只会在 Codex 配置那一端。

然后开 WPS、打开一份文档，回 Codex 里让它报告当前文档的段落数。这一步最容易撞上的错误码是 WPS_AGENT_OFFLINE——含义是 Codex 已经连上了 MCP 服务，但 WPS 或者加载项那一环没接上。排查顺序很简单：WPS 开了没有？加载项在不在 jsaddons 目录里？多数情况重启一下 WPS 就恢复。

## 实战：两条提示词

标书里表格多，错字藏在单元格角落最难找，这句亲测好用：

```
重点检查表格单元格里的错别字，批注必须钉在具体错字上
```

背后值得一提：察元的表格工具有 12 个 action，AI 会先用 header_read、column_read 这类切片读法摸清表头和"合计"行在哪，再把批注钉在具体错字上，而不是把一堆问题笼统汇总在文档开头让你自己找。

另一条是评审前的数字勾稽，标书里数表和正文对不上是要丢分的：

```
核对数表与正文数字是否一致（合计、百分比）
```

## 小结

Codex CLI 接 MCP 的心智负担比想象中低，前提是别拿 stdio 的老经验套 HTTP 型服务。三行配置、一次会话重启，Codex 就能在 WPS 里读文档、写批注、批量替换，终端 Agent 的活从代码一路干到了公文。另外不用担心多客户端打架：Claude Code、Cursor、Codex 在同一台机器上各配各的，互不影响，连的都是同一个本机服务，装一次全家受益。顺带一提，这个服务默认只在本机回环可达，想在别的机器上用，官方的路子是走代理，个人单机场景不用操心。当然，AI 给出的修改建议仍是辅助参考，标书这种要担责的东西，交出去之前最后一遍还得人眼过。
