# LM Studio、Xinference、OneAPI：一个网关全接住

这一年国产模型本地部署热度居高不下，但真正在单位里落过地的人都知道，模型本身从来不是最难的部分——难的是端点管理。我自己用 Ollama，同事装了 LM Studio，科室想统一推理资源，领导月底要看 Token 成本，四五个端点各配一遍，密钥表乱成一团麻，换一个供应商就得全员改配置。

察元AI文档助手在这件事上的设计很省心：离线内网优先，支持任意 OpenAI 兼容端点，Ollama、LM Studio、Xinference、OneAPI、New API 都能接；云端供应商（OpenAI、DeepSeek、阿里百炼、千帆、Gemini 等）还能并行配置。也就是说你不需要选边站，用一个 OpenAI 兼容标准把所有端点接住就行。下面按场景把这几样盘一遍。

## 一、Ollama：个人单机首选

一条命令拉模型就能跑，OpenAI 兼容层开箱即用，社区教程最多。适合个人办公机自给自足，缺点是缺少多用户管理和计量能力，人一多就撑不住了。

## 二、LM Studio：想要图形界面的选它

本地加载模型、调参数、看吞吐都有界面，对不熟悉命令行的同事最友好，同样暴露 OpenAI 兼容端点，默认地址一般是 http://127.0.0.1:1234/v1，具体以它界面里显示的为准。个人日常和给领导演示的场景很合适，缺点和 Ollama 类似，是单机形态。

## 三、Xinference：科室统一的推理底座

团队内网统一部署、集中调度模型资源，多个人共用一池显卡，起服务后自带 OpenAI 兼容接口（默认端口习惯上是 9997，以官方文档为准）。适合五到五十人规模的科室，把推理集中化之后，个人电脑不必都配独显，采购成本能省下一截。

## 四、OneAPI / New API：全接住的聚合网关

定位是把多个模型端点聚合成一个统一入口：渠道管理、密钥分发、用量统计。本地 Xinference、云端 DeepSeek、阿里百炼都挂到网关后面，察元只需要配网关一个地址。换模型、换供应商、按渠道比价路由，都不用动各人电脑上的客户端配置——这就是标题里"一个网关全接住"的字面意思。Token 成本优化也在这里做，渠道级计量直接出账，月底对账从猜谜变成查表。再送一个路由技巧：把高频低难度的校对任务指到本地渠道，云端渠道只接润色、改写这类高价值任务，账单一拉，结构一目了然。

## 接好之后：两条命令验证

先确认本机 MCP 服务在线（察元安装脚本带的单文件二进制服务，无需 Node.js，装完自动注册自启）：

```
curl http://127.0.0.1:62588/healthz
```

返回 online 即正常。再用 Claude Code 验证智能体链路：

```
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

团队统一用 Claude Code 的话，更省事的办法是发一份 `.mcp.json` 放进项目根目录：

```json
{"mcpServers":{"chayuan-wps-mcp":{"url":"http://127.0.0.1:62588/mcp"}}}
```

配置即文件，进版本库全员生效，比挨个跑命令整齐。

## 选型速查清单

- 一个人用：Ollama，十分钟起步
- 要图形界面、给同事演示：LM Studio
- 科室共用一池显卡：Xinference
- 多端点聚合加成本核算：OneAPI 或 New API
- 混合云策略：网关后面同时挂本地和云端渠道，按需路由

## 规模往上走：一套引擎四档形态

端点理顺之后，单位想整体铺开也不慌，察元是一套引擎四档形态：WPS 加载项（就是本文说的文档助手）、桌面版单机安装包、服务版 Docker 网络版全科室共用，再往上还有支撑数百到上万人浏览器工作空间的至臻版。个人起步用加载项，团队落地换服务版，模型端点这套配置思路原样复用。开源仓库在 github.com/zhgyuhuii/chayuan-wps-releases，Gitee 同步发布，Apache-2.0 协议，内网搬运没有许可障碍。

## 边界说明

网关解决的是接入和管理问题，不改变各端点本身的模型质量，弱模型挂上网关也不会变强。另外敏感内容走云端渠道之前，先过单位的保密要求——简单说，涉密内容只走本地渠道，这条没有商量余地。

我们单位最后的落法：Xinference 做底座，OneAPI 做网关，云端只挂一个备用渠道。配置从五份变成一份，月底对账从半天变成十分钟。网关化的意义就在这里——模型怎么换是后端的事，用的人无感。
