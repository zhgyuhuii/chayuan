# SEQ 题注编号与目录域：field 工具的 list 和 add

写长报告的人都有过这种经历：三十张表格手动编号"表1"到"表30"，中途在第七张前面插了一张新表，后面二十三个编号全部要手改；目录也一样，标题挪了一节，目录页码全错。这类问题的正解是域：让编号和目录由域驱动，内容怎么增删，编号自动顺延。先补一句背景，域是文档里"活的"占位符，编号和目录由域计算得出，而不是写死的文字——写死的文字插一行就得手工顺延一遍，域不需要，这是两种维护成本完全不同的东西。这篇讲怎么用察元的 field 工具和 caption 工具把这套机制用起来，按步骤走。

## 第一步：先盘点，后动手

field 工具的能力就两类：查和构造。查用 field.list，把文档里已有的域列出来——有没有残留的旧目录域、有没有别人手动插过的编号域，先看清楚；构造则负责生成 SEQ、TOC 这两类域。配套的 caption.list 负责枚举文档里现有的题注，已经有哪些"表X"、编号连不连续，一张清单看完。

```
先用 field.list 列出文档里已有的域，再用 caption.list 枚举现有题注，只盘点不要做任何改动
```

盘点这一步别省。文档里最常见的坑是手动编号和域编号混用——前七章是手写的"表3"，后两章是域生成的，直接补域必出重复编号。先清家底，再动工，是所有文档自动化的第一课。

## 第二步：给表格补 SEQ 题注

```
给所有表格补"表 X"格式的题注，编号用 SEQ 域自动生成
```

SEQ 域的题注编号由域维护：中途插入新表格，后面的编号自动顺延；删掉一张，编号自动补位。从此告别"改二十三个编号"的下午，也告别"表7"出现两次的尴尬。加载项表格批量里的"表格题注"能力可以配合着用，多表一次补齐，两条路都通。

## 第三步：插目录域

```
在文档开头插入目录，用 TOC 域，取一到三级标题
```

TOC 域按标题层级抽取目录，标题挪位置、加新章节，目录随域更新，不用手动重排。这里有个前置条件必须说：目录域认的是标题样式，标题样式乱的文档——正文段落套着"标题1"的比比皆是——先把样式捋正，否则目录抽出来的东西没法看。样式清理可以在文档批量工具里做，清理未使用样式、统计样式都是现成的能力。

## 第四步：验证收尾

题注和目录落完，再跑一次 caption.list 和 field.list，核对题注编号是否连续、域的数量是否符合预期。核对时重点看两样：一是题注编号有没有断号、重号——中间插过表又删过表的文档最容易在这里出事；二是域的数量和表格数量对不对得上，少一个域，就有一张表没被编号管住，将来它动了，目录和引用都不会知道。域是机器维护的，但"要不要编号、编号到哪个层级、目录取几级"是人的决策，最后这步核对就是把决策和执行对一遍账，对完才算收工。

## 为什么值得聊聊这个工具的设计

field 工具只有"查"和"构造"两类动作，功能清单短得近乎寒酸，但这恰恰是 MCP 生态里好工具的样子：智能体负责决定"什么时候编号、编到哪一级、目录取几层"，工具负责把域准确、可验证地放进文档。边界画得越清楚的工具，越敢放心交给智能体编排——这就是工具调用机制的基本功。功能多少是表面文章，行为可预期才是里子。

适合谁：长报告、标书、白皮书、论文式文档的作者，以及要给下属单位定文档模板的人。边界照例讲清：域编号治的是"编号维护成本"，不治"该不该有编号"——题注体例本身仍要按行文规范定；目录域的效果依赖样式规范，这两件事工具替代不了。另外，域也怕手改：有人图省事直接改域算出来的文字，一刷新就打回原形，接到这种来路不明的文档，先跑一遍 field.list 看看哪些内容其实是域，再决定怎么治。把编号交给域，把心思留给内容，这是长文档工程化最划算的一笔回报。
