# 弱网断网也能装：察元AI文档助手三源回退下载与 sha256 强校验

讲个上个月的事。我在外地出差，酒店网络烂到连图片都刷不动，同行的同事看我演示「察元AI文档助手」自动给公文挑错别字，当场要在自己的笔记本上也装一份。我本来都做好"回北京再装"的准备了，结果一行命令下去，中间卡了两下，最后居然装成了。这让我第一次认真去看它的下载机制——三源回退加 sha256 强校验，这两件事在弱网环境里是真能救命的。

## 先说弱网的问题出在哪

普通安装脚本的下载逻辑通常是单源直连：源站慢，脚本就跟着慢；源站超时，安装直接失败；最坑的是下载到一半断流，留下一个不完整的包，脚本不做校验的话还会照常解压安装，装出一个"看起来正常实际残废"的环境，后面对着诡异报错排查半天。行政岗同事的电脑环境本来就千奇百怪，再叠一层网络因素，装不上几乎等于产品不存在。

## 察元的解法：三源接力

察元的安装包下载走的是固定接力顺序：Gitee 打头，aidooo 居中，GitHub 收尾。Gitee 在国内网络环境里速度快且稳定，是主源；aidooo 是官方站兜底；GitHub 覆盖海外网络和前两者同时抽风的极端情况。任何一个源超时或校验不过，脚本自动切下一个，整个过程对用户透明。我那次酒店弱网之所以能装成，大概率就是 Gitee 断流后自动换源续上的。

命令还是那一行，macOS 和 Linux 为例：

```bash
curl -fsSL https://gitee.com/cloudshd/chayuan-wps-releases/raw/master/scripts/install-wps-skill-chayuan.sh | bash -s -- --fetch
```

Windows 用户用 PowerShell 那行等价命令，效果相同。

## 再说校验：sha256 拦住残包

多源回退解决"下得来"，sha256 强校验解决"下得对"。脚本对每个下载的包做哈希校验，差一个字节都过不了关，校验不过就换源重下，从机制上杜绝了半截包被安装的可能——在下载源质量不可控的弱网里，这道哈希是最后的防线。这个设计对内网和信创环境尤其有意义：国产化替代浪潮里，WPS 正在大批量替换 Office，随之而来的是各种离线、半离线的办公网络，工具链的每一次下载失败都要靠人工救，校验加回退等于把这类工单提前消灭了。

需要锁版本的场景也照顾到了：加 `-Version 4.1.2` 可以指定版本安装，配合多源回退，做版本回归测试不用碰运气。

## 装完之后，断网才是主场

下载阶段终究要联网，但察元真正的定位是"离线/内网优先"：装好之后接 Ollama、LM Studio、Xinference、OneAPI 这些 OpenAI 兼容的本机或内网端点，AI 能力整个搬到内网里，数据不出域。验证本机服务一条命令就够：

```bash
curl http://127.0.0.1:62588/healthz
```

返回 online，说明 MCP 服务常驻正常，接下来 Claude Code、Cursor 这些 Agent 连这个地址就能开始干活。三十台五十台机器的科室，装完之后再也没碰过外网 API，这在涉密管理要求严格的单位是硬需求而不是加分项。

内网里真正干活的提示词也顺手给两条。终检用这句，一步到位出分级摘要：

```text
帮我做发布前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

敏感信息排查用这句：`查找疑似身份证号、手机号、银行卡号并批注`。脱密那组工具默认只做预览不写盘，确认环节要显式带密码和关键词才会执行，风控上是层层设卡的。

## 两个实际建议

一是老用户别嫌麻烦，隔段时间重跑一次安装命令升级到新版，覆盖安装不动旧配置，4.1.1 之后连 `-Fetch` 的临时解压目录都会在退出时清理（老版本每次残留约 290MB，多装几次 C 盘就紧张了）；二是下载校验机制再稳，也别拿它当离线分发方案，真离线环境应该用官方提供的安装包渠道落盘再装，流程更可控。

工具好不好用是一半，装不装得上是另一半。把下载这一步做到用户无感，才是对弱网用户最基本的尊重。
