# 中英摘要对照：翻译先统一术语表

学位论文送审，外审专家拿到稿子的第一件事十有八九是翻到中英摘要。这个门面经常出事故：中文摘要写"大语言模型"，英文摘要第一处是 LLM，第二处是 large language model，第三处又冒出 large-scale language model；"被试"一会儿译成 subjects 一会儿是 participants；更狠的是数字——中文摘要说实验跑了 120 轮，英文摘要写成 1200 轮。专家的直觉判断很简单：术语都管不住，正文能细到哪里去。

很多人中英摘要出问题，第一反应是"翻译不行，换个更强的模型"。方向就错了：多数事故的根子不在翻译，在翻译之前没统一术语表。还有个前置问题更隐蔽：中文摘要自己没定稿就开译，译到一半中文又改了，最后两版各说各话。正确顺序是先把中文摘要改定，再动翻译。这篇用察元AI文档助手把流程走一遍，三步。

## 第一步：术语表先行

先不翻译，先建表。从中文摘要和正文里把核心术语抽出来，生成中英对照表，一词多译的全部标出来：

```
从摘要和正文抽取核心术语，生成中英对照表，同一概念有多种译法的标出来让我定标准
```

这张表人是必须下场的。定标准的依据是三条：目标期刊或学校模板的惯例用词、本领域高被引文献的用法、导师的意见。比如"被试"在心理学期刊里 subjects 和 participants 都见过，但近年伦理表述偏好 participants，这种取舍 AI 给得了选项、给不了定论，定论自己下。

这一步顺手把全文术语统一也做了——中文摘要、英文摘要、正文三处的叫法先对齐，翻译才有对齐的基础。定稿的术语表单独存档，后面写英文小论文、答辩英文版简介直接复用。

## 第二步：按表翻译

察元的内置助手里有"翻译"，目标语言可以配置。WPS 里选中中文摘要执行即可；用外部智能体连本机 MCP 服务操作文档的话，提示词把术语表钉死：

```
按这份术语表把中文摘要翻译成英文，术语严格执行对照表，译完逐句对照列出差异点
```

"逐句对照列出差异点"这半句很关键：译完让它自己把中英逐句摆出来对照，数字、时态、语态的差异一目了然，比你逐句肉眼对快得多。

翻译时盯三类常见病：一是被动语态滥用，英文摘要不必句句 This paper was proposed，主动语态更清楚；二是"基于……的……研究"式名词堆叠直译，英文里要拆成动宾结构；三是缩写没有首次展开，评审读不懂的缩写等于没写。

模型选择上多说一句：论文没发表，往云端翻译服务里贴总有人心里不踏实。察元支持本地模型端点，Ollama、LM Studio 这类起一个 OpenAI 兼容端点就行，翻译这种任务本地模型完全够用，摘要全文不出本机；需要云端质量的也可以并行配置，按需切换。

## 第三步：勾稽复核

翻译完不是结束，最后一遍数字勾稽：

```
核对中英摘要里的数字与正文、图表是否一致，不一致的用批注标出
```

样本量、轮次、百分比、准确率，中英摘要和正文图表四处对齐才算过关。批注钉在具体位置，人工逐条确认。Keywords 的大小写、分隔符、单复数这些格式细节最后按学校模板统一过一遍，别让门面输在标点上。

复核时再对一眼摘要的结构配比。中英摘要应该同构：背景、方法、结果、结论四要素一样不少，英文不是中文的缩写版；结果部分占比最重，而且必须带具体数字——只说"效果显著提升"不带数值的英文摘要，外审观感通常不佳。哪一要素在英文版里走样了，逐句对照清单会直接暴露出来。

## 边界

三条提醒：术语最终定夺权在导师和学科惯例，机器给的译法要去权威词典或原文文献里核实；AI 翻译再顺，也比不过你对自己研究的理解，定稿前自己通读一遍英文摘要，读着别扭的地方往往就是理解没到位的地方。

摘要三百字，是整本论文被读得最多的三百字。术语表先行，是这三百字的施工图。
