# 从浏览器插件到本机 Agent：文档 AI 三年形态演进

前几天整理浏览器，翻出一个 2023 年装的文档 AI 插件，已经吃灰两年多。从浏览器插件到今天跑在本机的 MCP 智能体，文档 AI 这三年换了三种形态。这篇不聊参数聊形态，把三种形态的差别盘一遍，顺便说说为什么 2026 年这个节点，本机 Agent 这一步走得关键。

## 形态一：浏览器插件/网页侧边栏，复制粘贴时代

最早的用法大家都熟：正文复制出去，粘进网页或插件，AI 改完再粘回来。三个硬伤：一是数据出域，整篇文档发到云端，敏感材料根本不敢碰；二是格式全丢，表格、批注、编号体系一粘就没，改完还得人工恢复排版；三是改不了"写回"这一步，AI 输出的是一段文本，落回文档靠人肉搬运。这个形态解决了"能不能"，没解决"敢不敢"和"累不累"。

## 形态二：办公软件加载项，AI 住进文档里

第二阶段，AI 以加载项形态进驻 WPS。以察元AI文档助手为例，装好后在 WPS 文字里直接用：29 个内置助手覆盖拼写语法、摘要、翻译、保密检查、AI 痕迹检查这些高频活，选中一段文字右键就能跑；写回有八式——插入到光标处、替换、添加批注、批注加替换等等，AI 的产出直接落进文档，格式和锚点都保得住。内置助手的覆盖面比想象中宽：保密检查能提示密级标识、涉军涉装、联系方式这类风险点；AI 痕迹检查保守评估文本的机器味；表单智能提取能从合同、公文里抽字段输出 JSON。还有一批批量能力——表格批量处理、图像批量处理、清理未使用样式这类文档级杂活，都是插件时代想都不敢想的操作。

更关键的是模型侧：加载项支持配置 Ollama、LM Studio、Xinference 这些本机或内网端点，推理不出机器，数据安全不出域从口号变成了配置项。这一形态解决了"敢不敢"和"累不累"，短板是能力边界固定——内置助手再多，也覆盖不了每个人的奇怪流程。

## 形态三：本机 Agent，文档变成可编程对象

第三步是 MCP 把文档彻底 API 化。察元的 sidecar 服务跑在 `http://127.0.0.1:62588/mcp`，46 个文档工具对外输出：Claude Code、Codex CLI、Cursor 这些外部智能体接上之后，读正文、圈错字、钉批注、插表格行列、多文档交叉校对，全部变成可编排的动作。助手生态也跟着长了出来：数千个察元助手可检索、可导出定义，写 agent 时不必事事从零造轮子。安全上有三道闸：dryRun 默认只出问题清单；写操作要显式 confirmed；锚点校验对不上就报 `LOCATE_MISMATCH` 拒绝落盘。批量写回一次最多 200 个操作，也是闸门之一。

注册给 Claude Code 一行命令：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

AI Agent 办公落地元年喊了一年多，我理解的落地标志恰恰是这种"文档变成智能体的操作对象"——不是聊天窗口里多了一个文档话题，而是智能体真的能在文档里动手，且每一步动手都有校验和留痕。

## 三形态对比，一张表看清

- 数据去哪：形态一全文出域；形态二可配本机模型不出域；形态三工具链全程本机，仅监听 127.0.0.1。
- 写回能力：形态一无；形态二内置写回八式；形态三 46 个工具任意编排。
- 误操作防线：形态一靠人眼；形态二写回动作可选；形态三 dryRun 加 confirmed 加锚点校验三层。
- 可扩展性：形态一和二能力固定；形态三跟着外部智能体的能力一起涨。
- 协同边界：形态一和二都是单人单工具；形态三里多个智能体可以并行干活，靠锚点校验和 confirmed 闸门维持秩序，团队审校场景里这是质变。

## 边界与收尾

要说清楚：形态二和形态三不是替代关系。改个错别字、出个摘要，内置助手点两下就完事，犯不上开智能体；跨文档交叉核对、批量流水线，才轮到 Agent 出场。工具的演进史不是淘汰史，是分工史。翻出那个旧插件那天我把它卸了，不是它不好，是这三年的问题清单，早就换了下一页。
