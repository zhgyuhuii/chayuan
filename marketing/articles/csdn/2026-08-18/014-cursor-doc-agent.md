# Cursor 写代码之余：接上 WPS MCP 摇身变成文档 Agent

Cursor 用得越久，越觉得它像个"只会写代码的实习生"：在代码仓库里横着走，一到 WPS 文档就歇菜。周报、立项书、产品说明书，照样得人工复制到聊天框，改完贴回来，格式还经常乱掉。其实 Cursor 的 Agent 模式天生就是干多步任务的料，缺的只是伸进 WPS 的那只手——一只标准的 MCP 手。Cursor Agent 这一年热度不减，但大多数人的用法还停留在写代码，文档这条线值得单独挖一挖。

## 配置：一分钟接上

前提是 WPS 里已装好察元AI文档助手加载项（安装脚本一行命令，装完本机 MCP 服务自启）。然后在 Cursor 里项目级新建 `.cursor/mcp.json`，也可以走 设置 → MCP → Add 的界面添加，两种方式等价：

```json
{
  "mcpServers": {
    "chayuan-wps-mcp": {
      "url": "http://127.0.0.1:62588/mcp"
    }
  }
}
```

重启 Cursor，Agent 模式下就能看到察元的 46 个文档工具可调。

## Agent 模式接活的方式

和"一问一答"不同，Agent 模式收到指令后会自己拆步骤：先调 document_meta 看文档多大、是否建议分块，再拉段落列表（带锚点），然后逐段检查，最后把批注钉到具体字句上。整个计划摊开在面板里，哪一步调了哪个工具一目了然，跑偏了随时可以打断，补一句"只查表格部分"，它会带着已有上下文继续，不用推倒重来。你要做的是把验收标准说清楚，而不是盯着每一步。

下面这些场景，是我接入之后挨个试过、确实能省事的。

## 场景一：全文校对钉批注

定稿前的最后一道网，一句话就够：

```
帮我检查文档中的错别字，用批注标出原文和建议改法
```

AI 会先读元信息和段落，逐段检查后把批注钉在具体错字上，每条批注写清原文和建议改法，而不是甩一份问题清单让你自己找地方。跑完顺手让它统计各章节的问题密度，重灾区一眼就能看出来。

## 场景二：表格里插行

不用记坐标，说人话就行——"在合计行上面插入一行，列结构和上一行一致"。AI 会先用 header_read、column_read 找到"合计"行的锚点，再调表格工具的 row_insert 执行。工具只按显式坐标干活，不会自作主张插歪。

## 场景三：序号体例检查

公文和制度文件最容易乱的就是序号层级，这句直接用：

```
检查标题/条款序号（一、（一）、1.）是否层级混乱，批注指出
```

序号问题机器比人敏感：一、（一）、1. 三层混着用，AI 逐段比对能全揪出来，人眼看到第三章基本就麻了。

## 场景四：多文档交叉校对

方案、合同、报价单三份文件术语对不上，是投标场景的经典事故：

```
打开目录下这几份文档，交叉检查错别字与术语是否一致
```

AI 会逐份打开、提取术语和关键表述，再输出交叉对照，哪份文档掉了队一眼看清。

## 场景五：发布前终检

把散装检查合成一套流程，一次跑完：

```
帮我做发布前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

## 场景六：敏感信息扫描

文档要外发、挂网之前，把隐私数据先扫一遍：

```
查找疑似身份证号、手机号、银行卡号并批注
```

结果也是批注形式，逐条人工确认再处理，宁可误报不可漏报。

## 一个让人放心的细节

这些场景里凡是"写"的动作，察元默认不直接落盘：改文字类的操作先返回 preview 预览，确认后才执行；写批注必须显式传 confirmed。Agent 跑得再欢，文档的最终决定权还在你手里——这对习惯在 Cursor 里放手让 Agent 跑任务的人尤其重要，毕竟幻觉还没被根治，预览就是止损阀。

## 适合谁

用 Cursor 的开发者、写技术方案和产品文档的团队。代码和文档收进同一个工作流，不用在编辑器和聊天窗口之间来回横跳；团队推广也简单，把 .cursor/mcp.json 提交进仓库，同事拉代码后重启 Cursor 就能用，不用挨个教学。白天写的接口文档，晚上让 Agent 按同一套标准过一遍体例，第二天直接评审。不装外部 Agent 的同事也有平替——WPS 界面里察元自带 29 个内置助手，不碰配置也有完整体验。边界照旧要讲：AI 校对擅长错别字、体例、前后一致性这类机械问题；定密、法务合规这类需要担责的判断，它只能提示，不能替你拍板。
