# 实验数据与正文打架：数表勾稽在论文里的用法

预答辩上最疼的一刀，是委员翻着论文问的："正文写识别率提升了 12.4%，表 4-2 里算出来是 11.8%，哪个对？"我当时站在台上，脑子里飞快过了一遍第四章的每一张表，答不上来。更糟的还在后面：他又翻到第三章，"这里样本量写 300，第四章表格分项加起来 296，少的 4 个去哪了？"全场安静了几秒，那几秒我记到现在。

事后复盘，原因很没面子：补做实验后表格更新了，正文里的引用数字没跟着改；论文改到第九稿，每处数字最早从哪来的，我自己都不记得了。这不是粗心，是流程缺陷——指望人肉记住三十万字里每一处数字的版本，本来就不现实。

从那以后我立了铁律：数据改动当天勾稽。工具是 WPS 里的察元AI文档助手，核心就一句提示词：

```
核对数表与正文数字是否一致（合计、百分比）
```

## 勾稽怎么跑

AI 做这件事的方式值得说一下细节。表格不是整块糊进去读的，它有切片读的能力：先读表头搞清结构，再按列拉数，合计行、百分比列是重点盯防对象。正文侧则把"提升了 X%""共计 N 条""平均 X"这类带数字的表述逐个定位，两边对照，对不上的用批注钉在具体位置上。批注只报告事实——"此处 12.4% 与表 4-2 的 11.8% 不一致"——不给裁决。写批注需要显式确认才落盘，清单先过目，稳当。

除了数值本身，还有两个高频雷区值得单独盯：一是单位混用，"千"和"万"、"%"和"‰"、存储单位大小写，正文和表格各写各的，数值其实没错，单位差了一档；二是有效位数，仪器精度两位的地方正文写了四位，看起来更精确，实际是伪精度，评审反而会追问。这两类属于"每个数都对、放在一起不对"的问题，机器对照着查比人眼细。

裁决是人的活，而且必须回到源头：打开实验记录，以原始数据为准。改完当天在数据记录里同步记一笔版本说明，以后哪处数字是哪一版数据的，追查有据。我的习惯是三类处理：正文错了改正文；表格错了重算表格，顺带检查是不是导出脚本的问题；两边都没错但口径不同（比如一个含验证集一个不含），加注说明口径。第三类最值得警惕，机器抓出"对不上"恰恰是在提醒你可能存在口径漂移。

学位论文比一般报告多一道坎：它通常还有一篇投稿小论文、一份开题报告，同一批数据在几个文档里各活各的。盲审前把这几个文档放一个目录，跑一遍交叉：

```
打开目录下这几份文档，交叉检查错别字与术语是否一致
```

数字相关的交叉核对同理，同一指标在论文和小论文里的数值、单位、有效位数必须同源。还有一个容易被忽略的角落：附录。原始数据表、代码清单、补充实验都堆在附录里，附录的数和正文的数不同源的案例比比皆是——正文用的是修订后的数据集，附录还挂着清洗前的版本。勾稽范围把附录算进去，别默认它是净土。

送审前一晚的终检我固定用这条：

```
帮我做盲审前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

分级摘要是为了安排最后一晚的有限精力：严重的当晚必须清零，一般的尽力，建议类的留给下一稿。

## 边界

把话说全：机器抓的是"对不上"，不是"错了"。哪个数是对的、口径怎么定、有效位数怎么处理，永远要人回到实验记录里核实，以原始数据为准。四舍五入造成的尾差该加注就加注，"因四舍五入，分项合计与总计略有出入"这一句话能挡掉评审的很多追问。

盲审老师对数字的敏感程度超出大多数人的预期，因为数字一致性是最容易检验的学术认真程度。预答辩丢的那几分，换来一条一辈子的习惯：数据动，勾稽跑。
