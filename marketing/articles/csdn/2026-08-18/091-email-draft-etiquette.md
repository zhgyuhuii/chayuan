# 邮件草稿先过一遍：敬辞、语气、错别字三查

上个月底，隔壁工位的同事被一封对外函件搞得连夜补救：发给集团客户的正式邮件里，"鉴于此"打成了"签于此"，落款的公司名少了一个字，更要命的是，正文里写的报价有效期和附件合同里的差了整整十天。客户那边没说什么，但领导在周例会上点了一句："以后对外邮件，发出去之前先过一遍。"

"先过一遍"这四个字，说出来轻巧，落地全是问题：谁来过、怎么过、过什么。文秘岗一天十几封对外邮件，全靠肉眼自查，看三遍也会疲劳——自己敲出来的字，自己最难看出毛病。这两年都在谈 AI Agent 办公落地，我的看法是，落地不必等什么大场景，就从邮件发出前的三查开始：查敬辞、查语气、查错别字。

我现在的做法是把邮件草稿先贴进 WPS 文字里，用察元AI文档助手过一遍，再复制回邮箱发送。察元是个跑在 WPS 文字里的智能加载项，装好之后侧边栏就有二十多个内置助手，不依赖外部账号，配了内网模型端点的机器照样能用。

## 第一查：错别字，先预览后写批注

错别字是最刚性的一查。草稿贴好后，我先用"纠正拼写和语法"这个内置助手，它会返回一份结构化的问题清单：哪一段、哪个词、建议改成什么，一目了然。更稳的做法是两段式——先让 AI 只跑校对不动正文，人工确认问题清单之后，再把建议写成批注。给智能体的提示词长这样：

```
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注
```

```
帮我检查文档中的错别字，用批注标出原文和建议改法
```

批注钉在原文原字上，采纳与否自己定。这个分寸对文秘岗很关键：AI 出建议，人拿主意，改动的每一步都留了痕，事后翻查有据可依。

## 第二查：语气，对照预览而不是整段覆盖

对外邮件真正容易出事的不是错字，是语气。同一句"贵司提出的要求我方无法满足"，换个写法就是"关于贵司提出的诉求，我方需进一步评估后再行答复"。我用"正式化改写"和"润色优化"两个助手处理这类句子，写回方式选"仅生成结果"，让改写稿和原文对照着看，逐句决定采纳哪句。宁可多一步手动复制，也不让 AI 整段覆盖自己斟酌过的措辞——语气这东西，责任没法外包给模型。

## 第三查：敬辞与口径，顺带把数字核了

敬辞混乱（"贵司"和"你们"混用、"我公司"和"我们"交替出现）本质是口径问题。我先用"术语统一"助手把称谓口径拉齐，再用"生成摘要"把邮件压缩成三句话。自己读一遍摘要，数字、日期、附件名有没有对上，比逐字重读全文快得多。涉及报价数字的邮件，我会再补一条核对指令：

```
核对数表与正文数字是否一致（合计、百分比）
```

让 AI 对照正文和附件表格里的数字，全部用批注输出，把"正文说十天、附件写两周"这类打架问题提前揪出来。邮件正文和附件表格各说各话，是对外函件里最伤专业感的一种错。

## 三条实操建议

第一，邮件草稿贴进 WPS 再处理，看着绕了一步，实际是把"邮箱里慌乱地改"变成了"文档里从容地核"，批注还替你留了一份检查记录。第二，正式函件三查走完再发，全程一般不超过十分钟，比出事后写情况说明便宜太多。第三，涉及未公开信息的邮件，把模型端点配到内网的 Ollama 或 LM Studio，数据不出本机，这一步配置一次，长期安心。

适用人群很具体：文秘、行政、销售支持、商务对接，所有每天替公司对外说话的岗位。边界也要说清：三查是辅助参考，正式邮件的定稿责任在人，敬辞对不对、语气合不合适，最终自己拍板。工具能兜住的是——你不会再把"签于此"发给客户了。
