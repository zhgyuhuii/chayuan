# 年终总结跑量季：摘要、行动项、风险三件套

七月底刚交完半年总结，趁着记忆还新鲜，我把这两年跑量季攒下的流水线完整复盘了一遍。年终总结的量只会更大——各科室报材料的时间会更晚、格式会更野，而交稿的时间一天不会宽。这套流水线的核心是三件套：摘要、行动项、风险。材料千头万绪，归结起来无非三问：干了什么、还要干什么、有什么要防的。

办公室综合岗、写年度总结的同行，建议在跑量季到来之前把这条流水线先空跑一遍。

## 第一步：素材归堆，先别急着动笔

各科室报上来的材料，版式五花八门：有三页纸只写了一件事的，有把全年工作台账原封不动贴上来的。我先把文件收进一个文件夹，统一过一遍"生成摘要"，每份材料先压成三百字左右的摘要。这一步的意义是快速摸底：哪几份有干货、哪几份是凑数，看摘要就够了，不用每份都精读。摸完底，心里有谱，动笔才不慌。

文件夹命名也立个规矩：科室名加报送日期。后面做多文档交叉检查时按目录批量跑，不靠肉眼满屏找文件，跑量季省下的每一分钟都是睡眠。

## 第二步：长材料分块处理

总有几份超长的台账类材料。文档超过约 80k 字符，整篇读取就该分块了——察元的 MCP 工具里有分块读取的能力，按页按块过，摘要照做。分块的好处不只是读得动，更在于每一块摘要的粒度更细，后面组装时不容易漏事。

用加载项的同事不用操心这一层，助手会自己处理；用 Claude Code 这类外部智能体连 MCP 干活的，就要有分块意识，遇到 DOCUMENT_TOO_LARGE 的报错就换分块读取，别硬来。

## 第三步：三件套逐份提取

摸完底，对有干货的材料逐一跑三件套。三个都是加载项里的现成助手：生成摘要、提取行动项、提取结论与风险。行动项我喜欢加限定，提示词这么写：

```
从这份材料中提取行动项，写明事项、责任科室和时间节点，没有写明责任主体的标注"待明确"，列表输出
```

"待明确"这个标注很关键——总结里最容易被领导挑出来的，就是"这事谁在管、什么时候办成"说不清的那些条目。提前标出来，比会上被点名强。

风险件同理，把"提取结论与风险"跑出来的条目单独放一个池子，供"存在问题与对策"板块取材。跑风险也可以在提示词里加限定：`提取材料中的结论与主要风险，逐条列出，注明出处段落`——"注明出处"这四个字很值钱，后面核实时不用满篇找原文。多数科室报材料只报喜，风险池子空着的时候，恰恰要警惕：不是没问题，是没人说。

## 第四步：组装初稿

三件套的产出按板块归拢：摘要进"工作回顾"，行动项进"下一步安排"，风险进"存在问题与对策"。这一步是人的活：顺序怎么排、哪些详哪些略、口径怎么统一，都是综合岗的判断，AI 替不了。组装完的初稿再过一遍"术语统一"，把各科室各自为政的叫法对齐——同一个平台，三个科室三种简称，领导会以为是三件事。

## 第五步：终检，然后交出去

初稿完成后，走发布前终检：

```
帮我做发布前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

总结里的数字特别要命：半年报的数、专项报的数、科室口头报的数，三个来源打架是常事。勾稽问题机器能抓出来，以哪个数为准，必须回去找业务科室核实——这一步不能省，也省不了。数字无小事，AI 辅助，人工核对，最后签字的人认账。

## 跑量季的实话

这套流水线跑下来，去年年终我从"连续一周加班到十点"变成"周三交初稿、周五定稿"。但要说清楚：省下来的是翻找、压缩、核对格式的时间，不是思考的时间。总结写得好不好，最终还是取决于对工作的了解程度——三件套只是让你把了解的东西，更快地端上桌。
