# 从零到文档 Agent：一个行政岗的三十天上手记

行政岗，不写代码，年初还焦虑"AI 会不会先替掉我"，年中想通了：与其焦虑，不如把 AI 先用成自己的手。于是给自己定了个三十天计划，把察元AI文档助手从零吃到透。这篇按时间线记叙，每天的心得都是真实的，给同岗位的同事参考。

## 第 1 天：装机，一行命令的体面

晚上九点开干。Windows 一条长命令装完，后来才知道它顺带处理了 PowerShell 5.1 按 GBK 解码 UTF-8 脚本的乱码坑。脚本自己跑完四步：加载项进 jsaddons 目录、MCP 服务注册开机自启、四级体检、技能投放。全程没装 Node.js，没配环境变量。下载源从 Gitee 一路回退到 aidooo 和 GitHub，还带 sha256 强校验，全程没让我操心中断。浏览器访问 healthz 返回 online，那一刻的成就感不亚于第一次独立做出月度报表。

## 第 3 天：29 个内置助手挨个点

加载项里二十九个内置助手，我按菜单挨个试。最惊艳的是拼写与语法检查，返回结构化的问题列表而不是一段含糊作文；最实用的是生成会议纪要和提取行动项。换种方式重写和润色优化后来成了我的常驻菜单：给领导看的版本走正式化改写，给执行层看的版本走通俗化改写，同一份底稿两副面孔。第一周的工作流很简单：粗糙的活交给助手，我只做选择。每天的提示词基本就一句：

```
帮我检查文档中的错别字，用批注标出原文和建议改法
```

## 第 7 天：学会"先预览后写回"

第一周翻车一次：让 AI 改稿，结果改动比我想的多。翻文档才知道确认机制的存在，从此固定用这个句式：

```
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注
```

dryRun 只出清单不动正文，我过目后再落批注。这周还学会一个细节：表格里的错字要加一句"批注必须钉在具体错字上"，不然批注会飘到单元格里别的位置。

## 第 12 天：保密检查成了新功课

要送审一份对外材料前，用保密检查助手跑了一遍，密级标识、单位身份、联系方式、项目编号、商业秘密分级这些风险点都会给提示。它给的是参考不是结论，定密仍然走人工流程——但至少提醒了我三处差点漏掉的敏感表述。行政岗对"辅助参考不替代人工定密"这条边界的理解，比谁都深。

## 第 18 天：接上 Claude Code，世界变大

按教程一条命令注册 MCP：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

第一次在终端里让外部 Agent 直接操作我开着的 WPS 文档，感觉像给办公软件开了个引擎盖。第二天我就把三份纪要丢给它做交叉校对：打开目录下这几份文档，交叉检查错别字与术语是否一致。术语统一这种以前靠肉眼对表的活，十分钟出批注。遇到 WPS 没开就报 WPS_AGENT_OFFLINE，让 Agent 自己 wps_launch 冷启动即可，这层链路我后来讲给好几个同事听。几百页的长材料也不再是禁区：document_meta 说建议分块，就让它带着 cursor 分页读，稳得很。

## 第 24 天：助手目录里淘宝

这周发现了 MCP 目录里的助手检索：assistants_list_domains 看领域全景，离线可用；assistants_search 关键词搜数千个助手；assistants_get 把看中的定义导出来。我导了两个公文类的助手，对照学习提示词写法，再回到加载项的自定义助手功能，把自己的系统提示、输入来源、写回动作、显示位置配好，挂进右键菜单。第一次拥有"自己造的工具"，哪怕只是组装的。写回动作有八种可选，插入到光标处、插入到每段后面、替换、添加批注、批注加替换、追加到文末等等，我给常用的两种各配了一份。

## 第 30 天：发布前终检成了部门标配

最后一天，我把这三十天攒下的提示词整理成一页纸，其中被同事抄走最多的是这条：

```
帮我做发布前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

现在部门成稿的固定节奏：AI 批注一轮、作者复核、再送审。三十天下来最大的体会：行政岗不会被 AI 替代，但会被会用 AI 的同事替代——而会用，原来门槛没有想象中高。焦虑的反义词不是躺平，是上手。
