# 三天写完标书：扩写和政策公文风格改写搭骨架

先交代背景：招标文件周三下午挂网，下周一上午开标，中间只有两个工作日加一个周末。以前这种节奏要全组连轴转，现在靠 WPS 加载项察元AI文档助手（外加本机 MCP 文档智能体）配一套固定的三段式打法，三天能压出一本结构完整的标书。前提先说透：三天成立的基础是骨架人工定、事实素材现成，AI 干的是语言层的活。适合谁看：标书编写团队里负责统稿、负责压进度的那个人。

## 第零步：装环境，十分钟

Windows 一条 PowerShell 命令，脚本自动处理 PS 5.1 的 GBK/BOM 乱码问题：

```powershell
& {[Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12;$w=New-Object Net.WebClient;$w.Encoding=[Text.Encoding]::UTF8;$s=$w.DownloadString('https://gitee.com/cloudshd/chayuan-wps-releases/raw/master/scripts/install-wps-skill-chayuan.ps1');if($s.Length -and $s[0]-eq[char]0xFEFF){$s=$s.Substring(1)};& ([scriptblock]::Create($s)) -Fetch}
```

脚本四步闭环：装加载项（jsaddons 目录加 publish.xml，WPS 打开即加载）、MCP 服务自启（单文件二进制注册开机自启，不需要 Node.js）、四级体检确认连通、往 Claude/Cursor/Codex 投放技能。当前版本 4.1.2，sidecar 全面隐藏启动，桌面右下角不再弹黑窗，关窗也不会把服务带崩。

国产模型本地部署这两年普及得很快，标书这种涉敏文档我们直接配 Ollama 本地端点，离线跑、不出域——察元对 Ollama、LM Studio、Xinference、OneAPI 这类 OpenAI 兼容端点都是原生支持，内网机也能用。

## 第一天：骨架人工定，素材各就位

骨架这一步坚决不交给 AI。目录跟着评分办法走：评分权重压在哪几项，哪几项就升为独立章节，这是投标的策略层，错一级后面全白写。半天定完目录，然后把往期项目的对应章节、厂商提供的方案素材分头贴进各章当底料。

素材就位不是无脑粘贴。往期标书的对应章节先过一遍「生成摘要」，确认结构可复用再整段搬，防止把上一个项目的特殊约定一起搬进来；厂商资料里的产品参数表原样保留——参数是事实层，一个字都不让 AI 碰，抄错一个型号就是商务偏差。这一天 AI 的存在感很低，这是故意的——策略层不外包。

## 第二天：扩写与公文体改写

这一天是语言层的主场。察元内置 29 个助手，写标最常用三个：「扩写」把只有要点的段落展开成完整表述；「政策/公文风格改写」把往期素材、厂商资料里偏营销腔的文字改成招标文件口径；「正式化改写」收拾口语化的实施说明。

用「扩写」有一条铁律：只展开已有措施和流程，不许新增事实。我固定用这条提示词：

```
把选中的实施组织方案段落扩写一倍，保持公文体，只展开已有的措施和流程，不要新增任何数字、资质和业绩描述
```

提示词还能固化：察元支持自定义智能助手，系统提示、用户模板、写回动作（插入光标处、替换、添加批注等八种写回方式）都能做成按钮。团队里每个人点同一个按钮，出来的口径就是一致的——多人合稿时代，这一点比单点文采值钱。

举个具体例子。实施组织方案一章，底料只有三行要点："成立项目组、明确职责分工、建立周例会制度"。用上面那条提示词跑扩写，输出会把三点各自展开成完整段落：项目组的构成与派驻方式、职责矩阵怎么落地、例会与汇报机制怎么运转，公文体、有骨架、不添数字。人要做的只是核对展开内容没有越出承诺边界，再往里填具体的人岗和周期——那部分是事实层，手工来。扩写的价值不是替你编，是替你把提纲变成大人能看的书面语。

第二天的收尾动作是让「检查段落序号格式」扫一遍。多人往同一本稿里灌内容，编号体系永远是最先乱的部分，当天乱当天清，别攒到合稿日。

## 第三天：校对压盘

最后一天只干一件事：把语言层的毛刺清干净。固定两条提示词：

```
帮我检查文档中的错别字，用批注标出原文和建议改法
```

```
核对数表与正文数字是否一致（合计、百分比）
```

所有问题以批注形式钉在原文上，人工逐条处理，改完销号。批注处理有优先级：错别字和数字问题当场清，措辞类的批注攒起来批量看——夜里十二点以后不要做措辞判断，这是教训换来的。长标书在 MCP 通道里先 document_meta 看段数，再 document_chunks 分块过，不会因为文档太大被卡住。

## 三天之外的话

三天能压完，是因为目录是人定的、数字是人贴的、承诺边界是人划的，AI 只负责把既定内容组织成合格的书面语。指望模型从零编一本标书，它编得出来，但那些被它顺手补全的资质和数字，评标质询的时候没有人替你担责。语言层交给机器，事实层留在人手里——这是三天工期成立的前提，也是不可让渡的底线。
