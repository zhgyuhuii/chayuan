# 县级政务离线部署：Ollama 全链路跑通记

上半年局里开会讨论政务大模型怎么用，会议室里分成两派：一派主张接大厂的云服务，功能全、上手快；另一派一句话顶回去——材料敢往外传吗？吵到最后，纪要里落下一行字：先做离线试点，数据不出域。任务落在我们信息科，也就落在了我头上。

前后折腾了两周，现在全链路跑通：本机 Ollama 跑模型，WPS 里装察元AI文档助手干活，从头到尾不依赖任何外部云服务。把过程整理出来，给同样在县级单位信息科、政数部门做试点的同行抄作业。

## 一、先把架构想清楚，再动手

很多人第一步就问"接哪家的大模型"，我的经验是先把架构定下来。这次试点我们画的是最简单的一张图：模型层用 Ollama 在本机起一个 OpenAI 兼容端点，模型选国产开源的中文模型，符合国产化替代的方向；应用层用 WPS 加载项，让 AI 直接在文档里干活，而不是把材料复制到某个网页对话框里来回倒；底座是一个本机 MCP 服务，负责把 WPS 文档的能力暴露给 AI 智能体。

这个架构最大的好处是边界清晰：模型在本机，文档在本机，中间的服务也只监听 127.0.0.1。全程没有一份材料离开这台电脑，"数据不出域"不是一句口号，是网络拓扑层面就决定了的。

## 二、第一步：把模型跑起来

在试点机上装 Ollama，拉一个中文能力过得去的开源模型。具体选多大参数的，量力而行：机器配置一般就先用小模型把链路跑通，确认流程没问题再换大的，别一上来就追求大参数，卡在显存上反而打击信心。

Ollama 起服务后，它会提供一个本地的 OpenAI 兼容接口。记下这个地址，后面要填。

## 三、第二步：一行命令装察元

Windows 机器上，PowerShell 里跑这一条：

```powershell
& {[Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12;$w=New-Object Net.WebClient;$w.Encoding=[Text.Encoding]::UTF8;$s=$w.DownloadString('https://gitee.com/cloudshd/chayuan-wps-releases/raw/master/scripts/install-wps-skill-chayuan.ps1');if($s.Length -and $s[0]-eq[char]0xFEFF){$s=$s.Substring(1)};& ([scriptblock]::Create($s)) -Fetch}
```

办公网里能访问 Gitee 的机器直接跑就行；完全隔离的机器，安装包可以先下载再拷进去用，仓库和百度网盘都有发布包。

这条脚本看着长，实际是四步闭环：装加载项到 jsaddons 目录、把 MCP 服务注册成开机自启、做一遍四级体检、往 Claude Code 和 Cursor 这类工具里投放技能文件。装完不需要装 Node.js，MCP 服务是单文件二进制，Windows 下注册到 HKCU\Run，开机自己起来。要指定版本就加 `-Version 4.1.2`。

顺带说两个版本细节：4.1.1 之后安装脚本的临时解压目录退出即清理，不再每次残留约 290MB；4.1.2 把后台服务改成隐藏启动，桌面上不再弹黑窗，误关窗口也不会把服务带崩。

## 四、第三步：把模型端点填进设置

打开 WPS 里的察元设置，模型端点指向 Ollama 那个本地地址就行。察元走的是 OpenAI 兼容协议，所以 Ollama、LM Studio、Xinference、OneAPI 都能接；内网里已经部署了统一推理网关的单位，直接指向网关地址也可以。

这一步做完，AI 用的就是你自己的模型，一个 token 都不会出网。

## 五、第四步：验证，别急着用

体检脚本其实已经自动查过一遍，但我习惯手动再确认两件事。第一件，浏览器访问 `http://127.0.0.1:62588/healthz`，返回 online 说明 MCP 服务活着。第二件，让 AI 跑一下 wps_status，看 WPS 和加载项的桥接是否正常。

这两步别省。试点环境最怕"看起来装好了"，真到领导面前演示掉链子。

## 六、第五步：拿真实材料测两个任务

第一件事测摘要。找一份上个月的局务会纪要，让加载项里的"生成摘要"助手出一段三百字摘要。本地模型的能力有上限，摘要这类任务表现稳定，适合当验收项。

第二件事测校对，用这条提示词：

```
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注
```

dryRun 模式只返回问题清单，不动正文，确认没问题再转成批注写回文档。这个"先预览后写回"的设计，在机关场景里特别重要——稿子是别人写的，AI 直接改正文，出了问题说不清楚。

## 七、踩坑记录

四条。一，PowerShell 5.1 的 GBK 乱码问题脚本已经处理了，别自己魔改脚本，用原版。二，长文档报 DOCUMENT_TOO_LARGE 时别硬来，改用分块读取，超过约 80k 字符的文档就该分页处理。三，校对报 MODEL_NOT_CONFIGURED，回去检查模型端点是不是没填或填错。四，免费额度用尽会返回 LICENSE_REQUIRED，不会弹购买窗打断你，但要知道这个错误码是什么意思。

## 八、几句边界话

这套方案解决的是"数据不出域地用上 AI 辅助"，不是保密管理的替代品。涉密材料的处理要严格遵守保密规定，该走的定密流程一步不能少，AI 工具只碰可以碰的东西。

两周跑通，信息科的成本是一台试点机加一个人力，换来的是科室里最先用起来的几位文秘开始主动来问"这个能不能也帮我弄"。试点能不能推广不好说，但至少证明了一件事：县级单位想在数据不出域的前提下用 AI 干活，这条路是通的。
