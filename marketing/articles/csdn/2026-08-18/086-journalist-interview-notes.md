# 采访记录两万字：提取行动项生成线索清单

后台收到一位都市报记者朋友的留言，问题很具体，整理成五问五答。他的处境：跑产业条线，一场两小时的深度采访，录音转文字出来两万字，当天晚上要出稿，第二天还要从这堆文字里挖后续选题。

**问：两万字 AI 读得动吗？**

答：读得动。察元AI文档助手的 MCP 工具链里有专门的长文分块读取工具，两万字离它约 80k 的大文档阈值还远，正常一次处理就行。真正要注意的是别让 AI"一口气总结全文"——信息密度高的采访记录，一段一个信息点，一口气总结必然丢细节。我的做法是按小节切开，每节单独提取，最后合并，宁可多跑几轮，不贪快。

**问：转写稿错字多怎么办？**

答：录音转写稿是错别字重灾区，人名、机构名、职务、专业词全靠语音引擎猜。先跑一遍：

```
帮我检查文档中的错别字，重点盯人名、机构名、职务、数字，用批注标出原文和建议改法
```

人名这块我的纪律是：AI 批注只做提醒，确认靠采访本和名片照片。"张力"和"张立"是两个完全合理的名字，只有你知道坐在对面的是哪一个。

**问：后续选题怎么挖？**

答：把"提取行动项"这个助手换个用法。它本来是给职场文档设计的，对采访记录同样有效——采访对象说"我们下个月要发布""这个项目年底验收""二期已经在谈"，这些都是带时间属性的钩子。我的提示词：

```
从采访记录中提取所有带时间、带承诺、带后续动作的表述，输出为线索清单：事项、涉及方、时间点、原文位置
```

这份清单就是我的追访日历。上个月从一份旧采访里翻出"预计三季度投产"这句话，做成跟踪报道，比通读回忆靠谱得多。

**问：采访前能用它做什么准备？**

答：采访前的案头工作是最容易被省掉、又最不该省的环节。我现在的做法：把受访者所在机构近两年的公开材料、上次采访的记录都丢进 WPS，先用"生成摘要"各压成半页速览，再用"提取结论与风险"看对方近期表态里的承诺和隐忧。带着一张速览表进采访间，追问的深度不一样。速览表末尾留一个"待核实清单"，采访中逐项勾。

**问：成稿环节它还能帮什么？**

答：写导语的时候把全文丢给"缩写"助手，先出一个三百字版本，再人工改成自己的语气——导语是最难下笔的一段，有个烂初稿也比对着空白页发呆强。全文写完后，用定位工具按关键词回查原文位置，核引语是否逐字准确，这比肉眼在两万字里翻快得多。标题初稿可以用"生成标题"出候选，但新闻标题的现场感和分寸，还是老编辑的活。

**问：历史采访能不能串起来用？**

答：可以，这是 RAG 的场景。察元能对接它的桌面版、网络版知识库，老采访录入后直接检索相关段落，带出处。写稿时问一句"之前哪些受访者谈过这个园区"，比翻三年的笔记本快得多。深度报道的命脉就是线索的连续性，检索比记忆可靠。做周年回顾、产业变迁这类选题时，几十份旧采访按主题检索一遍，时间线自己就浮出来了。

**问：采访记录敏感吗？敢放 AI 里吗？**

答：敢，但有前提——本地部署。信源保护是记者的职业底线，把采访记录上传第三方云服务，等于替别人保管你的信源名单。察元的路线是离线优先：模型走 Ollama 这类本机端点，MCP 服务只监听 127.0.0.1，本机即信任边界。发稿前如果要把记录给实习生或合作方看，先跑一遍脱密预览，它能提示疑似可识别身份的信息，预览不写盘，人工确认后才动。

最后一条经验：AI 处理采访记录，位置是助理，不是作者。它提取、聚拢、提醒，但成稿的事实核对、信源判断、哪句能引哪句不能引，必须记者自己来。工具越快，把关的手越要稳——这是这个行当在 AI 时代没变过的部分。
