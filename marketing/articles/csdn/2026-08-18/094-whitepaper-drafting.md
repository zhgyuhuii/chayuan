# 白皮书起草：扩写加段落结构优化组合拳

白皮书是最考验"初稿到成稿"距离的文体：大纲开会定了三周，正文憋不出来；好不容易写完，领导说"第三节太薄、逻辑有点乱"。这篇按步骤讲我用察元AI文档助手起草白皮书的组合拳——扩写管"写不长"，段落结构优化管"理不顺"，两个助手接力，中间夹人工确认，一步都不跳。

先说前提。白皮书里有未发布的产品参数和客户案例，公司规定这类内容不能上公有云。察元支持把模型端点配到本机的 Ollama 或 LM Studio，跑内网部署的开源模型，全程数据不出域，这是这套流程能在我这落地的前置条件，也是这两年国产模型本地部署热潮最实在的收益之一。

## 第一步：搭骨架

大纲先用"生成标题"助手把各级标题的措辞过一遍，再用"生成摘要"对大纲做一次反向压缩——如果三句话讲不清这份白皮书要说什么，说明大纲本身有问题，先改大纲再动笔。标题这一步别嫌麻烦：标题定了，后面的术语口径和章节结构都跟着标题走，这里省下的十分钟，后面要拿一小时来还。骨架不牢，后面扩写越多，返工越多。

## 第二步：初稿扩写，锁定选区

初稿阶段最忌讳把全文丢给 AI 让它"看着办"。我的做法是逐节处理：选中一节，把助手的输入来源设成"仅选区"，然后下指令：

```
把选中的这一节扩写到六百字左右，保持已有术语和口径，不要新增数据和案例
```

"不要新增数据"这半句是重点。扩写助手擅长把干瘪的骨架写丰满，但数据和案例必须由人提供——AI 补出来的数字看着像模像样，来源没人说得清。写回方式选"插入到光标处"，扩写结果落在指定位置，前后衔接自己掂量。

## 第三步：段落结构优化，先建议后动手

初稿写完，全文逻辑再过一遍。"段落结构优化"这个助手，我坚持两段式用法：

```
对全文做段落结构优化：先给出调整建议列表，我确认后再动正文
```

让它先输出"第二节应拆分为两段""结论段建议前移"这类建议清单，我勾选认可的项，再让它执行。看建议清单时我主要盯三样：段落顺序合不合论证逻辑、长段该不该拆、过渡缺位导致的意思跳跃。整段重排这种事，直接让 AI 一把梭，改完你都不记得原来写了什么，风险全在后头。

## 第四步：压缩与提炼

配套动作：摘要页用"缩写"助手把每章压成一段；"提炼关键词"抽出的词表顺手检查术语有没有飘——白皮书最怕核心概念前后不同名，读者一旦起疑，整份文档的可信度都要打折。

## 第五步：术语统一

```
全文把"智能体/Agent/代理"统一为"智能体"，先列出所有出现位置，确认后再替换
```

先列位置再替换，替换范围一目了然，也避免误伤引用原文里必须保留的英文表述。制度类白皮书还要加一条行文风格检查，口径统一是底线。

## 第六步：发布前两道安检

对外发布前过两个助手：AI 痕迹检查做保守评估，提示哪些段落机器味偏重，人工再顺一遍——注意它是保守评估，宁可多提示不少提示，结果仅作参考，别被它牵着全文重写。保密检查按密级标识、单位身份、联系方式、项目编号这些维度给风险提示，商业秘密还有分级提示。白皮书尤其要防客户案例里的可识别信息：那段"某华南头部客户上线三个月"写得越生动，泄露风险越具体，这一步就是最后一道闸。案例过不了保密检查的，该脱敏脱敏，该删就删，别心存侥幸。

适用人群：市场、行业研究、解决方案、标准编制这些常年写长文档的岗位。边界说两句：扩写内容中所有数据和事实必须回溯到人给的来源，AI 痕迹检查是保守评估、仅供参考。组合拳的核心不是让 AI 替你写，是让它把你在"写不长"和"理不顺"上耗的时间收回来，把精力留给观点本身。
