# 无需 Node.js 的 MCP 服务：察元AI文档助手单文件二进制的开机自启方案

聊一个偏架构但很实际的话题：为什么「察元AI文档助手」的 MCP 服务敢说"无需 Node.js"。

先摆背景。MCP 协议这两年成了 AI Agent 接工具的事实标准，但你去翻社区里的 MCP 服务实现，一大半是 Node.js 写的，启动方式清一色 `npx` 拉起。这在开发者自己机器上没问题，一旦要落到普通办公电脑上，坑就全冒出来了：得先装 Node 运行时、得处理版本兼容、终端窗口一关服务就没了、开机还得手动拉起来。给行政同事的电脑装这套，运维成本直接爆炸。

察元的做法是另一条路：MCP 服务 chayuan-mcp 编译成单文件二进制，安装脚本下载下来直接跑，机器上有没有 Node.js、Python 完全无所谓。这带来三个直接的好处。

## 好处一：依赖归零，部署就是拷文件

一行命令装完（Windows 用 PowerShell 那行，macOS 和 Linux 用 curl 那行），安装脚本把二进制放好、注册自启、跑完四级体检就收工。没有 node_modules、没有版本地狱、没有"我这里明明能跑"的经典对线。单位里批量装机也好办，同一行命令挨台跑就行。

```bash
curl -fsSL https://gitee.com/cloudshd/chayuan-wps-releases/raw/master/scripts/install-wps-skill-chayuan.sh | bash -s -- --fetch
```

## 好处二：真正的开机自启

常驻服务的价值在"随叫随到"。你早上开机，打开 Claude Code 或 Cursor 让它改文档，如果 MCP 服务还得手动起，体验就断了一截。察元按平台注册自启：Windows 写注册表 `HKCU\Run`，macOS 用 LaunchAgent，Linux 走 systemd --user。用户登录，服务就在，AI 工具连 `http://127.0.0.1:62588/mcp` 永远有人应答。

4.1.2 版还把 sidecar 改成全面隐藏启动——以前后台服务起来会闪一个控制台黑窗，不懂的同事还以为中了病毒，现在完全静默，关窗也不会把服务带停。这种细节说明作者真的在办公场景里滚过。

## 好处三：边界清晰，安全好交代

这个服务只监听 127.0.0.1，不监听外网地址，无需 Token，因为信任边界就是本机：能碰到这个端口的进程，本来就能直接读你的文件了，加 Token 属于表演。远程访问的场景官方态度也明确——走代理或者改 `CHAYUAN_MCP_PORT` 环境变量自己规划。对数据安全敏感的单位，"服务不出本机"这四个字比一页安全白皮书都好使，配合 Ollama 这类本机模型端点，整条 AI 链路的数据都不出域。

## 接入侧同样是轻量的

服务端零依赖，客户端接入也是一行的事。Claude Code 用户：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

它走的是 Streamable HTTP 而不是 stdio——这个选择也和"无需 Node"一脉相承：stdio 模式每个客户端都要自己拉起服务进程，HTTP 模式一个常驻服务多方共用，Claude Code、Cursor、Codex 同时连也互不干扰。

## 维护成本也一起降下来了

零依赖带来的另一个隐性收益是升级路径干净。重跑一遍安装命令就是覆盖升级，旧配置原样保留，不用先卸运行时再装运行时；需要回退就用 `-Version` 参数锁旧版本。细节上 4.1.1 修了 `-Fetch` 临时解压目录不清理的问题，此前每次安装残留约 290MB，批量给几十台机器装的时候这笔账很可观。再加上 4.1.2 的隐藏启动和掉线自愈，整个服务在用户眼里的存在感被压到最低——这是常驻软件该有的样子：你感觉不到它，它一直在。

验证也不用记复杂命令，浏览器开一下健康检查地址，看到返回 online，整条链路的心跳就确认了。给同事做培训时我就教这一招，十秒钟教会，人人能自查。

## 该说的边界

单文件二进制不等于万能：它是文档智能体服务，管的是 WPS 里那 46 个文档工具的读写和校对，不是通用 Agent 框架；校对、脱密预览的产出仍是辅助参考，定密、发文签字这些责任环节还是人的事。另外二进制升级靠重跑安装命令覆盖，想锁旧版本用 `-Version` 参数指定即可，不适合当成包管理器来理解的场景。

架构上做减法，把运行时依赖砍到零，把常驻和静默做到位，这类"无聊但可靠"的工程决策，恰恰是 AI 工具能不能进办公室的分水岭。
