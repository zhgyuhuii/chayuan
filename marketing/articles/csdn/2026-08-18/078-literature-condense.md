# 文献综述瘦身：缩写助手保留关键信息

开学交初稿的死线前，师弟发来微信：综述章节两万三千字，学校模板上限一万五，导师批了六个字"砍三分之一，别堆文献"。他对着屏幕坐了一下午，删删改改，字数纹丝不动——每篇文献都觉得重要，每句话都像花了力气写的。

这是文献综述最常见的病：写的时候怕漏，一路做加法，最后胖成文献罗列。瘦身不是删字，是改组织方式。这篇盘一盘综述里的四刀，再说怎么用察元AI文档助手的"缩写"助手把这四刀下得准一些。

## 第一刀：复述刀，砍流水账

病症：一篇文献一段，作者、年份、方法、结论依次报菜名，三十段排下来就是三十篇的读后感连播。这一刀的方向是按主题归并：同一问题的几项研究合并成一段比较着写，方法异同、结论分歧才是综述该有的信息。缩写助手处理这种段落很合适：

```
把选中的综述段落压缩一半篇幅，保留每项研究的方法、数据和结论，删掉评价性空话，先只生成结果不替换原文
```

注意最后那半句：先只生成结果。压缩版和原文并排对照，人工决定取舍，原稿一个字没被动。压缩强度可以分档试：先压到七成，狠得下手再压五成、三成，一段一段选档，比一刀切留的余地大。

## 第二刀：空话刀，砍无信息量表述

病症："具有重要意义""得到了广泛应用""引起了国内外学者的广泛关注""奠定了坚实基础"。这些句子删掉之后信息量零损失，是最先该砍的。让 AI 批注全找出来：

```
找出综述中"具有重要意义、得到了广泛应用"这类无信息量表述，用批注逐处标出
```

批注出来通常自己都会吓一跳：原来这种句子攒了这么多。判断标准其实很简单——把这句话删掉，读者损失了什么信息？答案是什么都没损失，那就是空话。

## 第三刀：重复刀，砍反复展开

病症：同一个结论在综述里被展开论述了两三遍，因为写的时候前后隔了一个月，忘了前面写过。让 AI 交叉排查：

```
检查同一结论或同一文献是否在综述里被重复展开论述，列出重复位置
```

保留论证最充分的一处，其余并入引用即可。

## 第四刀：关联刀，砍无关文献

病症：为了凑"阅读量"，把和研究问题只有点头之交的文献也拉进来两段。这一刀必须说明白：AI 不能替你决定。一篇文献该不该留，标准只有一条——它和你研究问题的关系。这个判断只有做了这个课题的人做得出来，机器给的只是"这段与上下文主题相关度较低"之类的提示，最终取舍是作者的活，这也是综述的学术价值所在。

## 两个配套技巧

配置上，频繁做段落级压缩的话，建议用察元的自定义智能助手配一个专属的：输入来源选"仅选区"，输出格式选对照式，写回动作选"仅生成结果"。配置一次，后面在综述里选中一段点一下就行，压缩稿永远不直接覆盖原稿。内置的"缩写"助手本身也能直接用在选区上，两条路都通。

验收上，砍完做一次反向核对：让 AI 数一遍压缩前后的字数和引用条目数，引用编号有没有因为删段而错位是重点——综述瘦身最容易翻车的不是字数没达标，是参考文献列表被改乱。真有砍过头、论证变薄的地方，内置的"扩写"助手是反向工具，可以把关键段落的论据补回来，同样先出结果再定。

## 边界

压缩不等于删证据：奠基性文献该单列就单列，砍到只剩观点没有文献支撑，比胖更糟。动正文前让 AI 走预览确认再执行。导师那六个字的后半句"别堆文献"其实是方法提示：堆是加法的病，瘦是减法治不了根，下一次写综述从主题提纲起笔，一路做减法，初稿就不会胖到哪里去。综述瘦下来留下的每一句，都应该是在为你的研究问题搭台子——这句话是导师说的，比我总结得好。
