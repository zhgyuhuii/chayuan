# 固定流程固化：任务清单与任务编排

每个做编务的人都有一套念了几百遍的口头禅：错别字过一遍、标点统一、数字前后对一下、表格和正文核一下……问题在于这套话术只存在于老师傅脑子里，新人接手就断档；就算记得住，每次手敲一遍提示词，写到一半就开始偷工减料。

我的解法是把固定流程固化成任务清单，让 AI 按清单编排执行。用的工具是察元AI文档助手——WPS 加载项加本机 MCP 服务的组合，当前 4.1.2 版本，Apache-2.0 开源；Claude Code 这类外部智能体也能经 MCP 直连它干活。下面按步骤走一遍完整流程。

## 第一步：把口头禅写成清单式提示词

```
帮我做发布前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

关键在结构：任务逐项列出来、输出方式规定死（全部批注）、结尾要一份分级摘要。清单式提示词的好处是模型不容易漏项，你检查它有没有偷懒也有了对照标准。

## 第二步：先预览，后写回

```
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注
```

对应到工具层，`proofread_run` 默认 dryRun，只返回问题列表不动文档；写操作不传 confirmed:true 的话，`document_replace`、`document_insert` 也只会返回 preview 不写盘。这个默认设计救过我很多次——先看清单再动手，永远比先动手再后悔便宜。

## 第三步：批量落批注

问题多的时候逐条手工确认不现实。`document_apply_ops` 支持批量写回，replace、comment、comment-replace、insert-after 可以混着提交，单次上限 200 ops。长任务走异步，用 `proofread_job_poll` 轮询结果，界面不卡，人可以去干别的。

## 表格任务的编排细节

清单里有表格项时，别让智能体瞎猜坐标。比如插行这件事：

```
在"合计"行上面插入一行，列结构和上一行一致
```

智能体会先用 header_read、column_read 这类表格动作把结构读清、找到"合计"行的位置，再执行 row_insert——工具只按显式坐标执行，定位这一步交给读取动作完成。如果定位失败，会拿到 LOCATE_MISMATCH 或 LOCATE_NOT_FOUND，说明锚点校验没过，这时回去把位置描述得更具体，比硬重试有效得多。察元的表格动作共 12 种，切片读、插行插列、合并单元格、列宽、重复表头都在内，清单里能排进去的表格活比想象中多。

## 第四步：固化成自定义助手

清单跑顺之后，别再每次粘贴提示词。察元的自定义智能助手支持系统提示加用户模板，再配上模型类型、输入来源、输出格式、写回动作和显示位置，把这个终检清单做成一个助手钉在菜单里，下次一键调用。口头禅从此有了载体，老师傅的经验也就留下来了。

## 清单粒度：一屏能读完为限

清单不是越长越好。我踩过的坑是把二十多个检查项塞进一条提示词，模型跑到后半程开始丢项，人工核对清单本身也累。现在的粒度控制在八到十项、一屏能读完；更多的项拆成两个助手，比如"文字质量终检"和"数字与表格勾稽"，各跑各的，问题列表反而更清爽。自定义助手还能设显示位置——主菜单、更多菜单、右键菜单都行——按使用频率摆放，高频的放右键随手可点，低频的收进更多菜单，界面不乱。

## 第五步（进阶）：交给外部智能体编排

MCP 生态这两年爆发，Claude Code、Codex CLI、Cursor 都能直连察元，一条命令注册：

```
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

用 Codex CLI 的话，编辑 `~/.codex/config.toml` 加三行就行：

```toml
[mcp_servers.chayuan-wps-mcp]
url = "http://127.0.0.1:62588/mcp"
```

Cursor 则在项目级 `.cursor/mcp.json` 里写同样的 URL。接好后先探一下健康检查，`GET http://127.0.0.1:62588/healthz` 返回 online 再开工，省得编排到一半发现链路不通。

连上之后，多步骤流程可以让智能体自己编排，比如跨文档的一致性核查：

```
打开目录下这几份文档，交叉检查错别字与术语是否一致
```

再补两条我常挂在清单末尾的检查项：

```
检查标题/条款序号（一、（一）、1.）是否层级混乱，批注指出
```

```
核对数表与正文数字是否一致（合计、百分比）
```

## 边界说明

任务清单固化的是流程，不是责任。AI 按清单跑完只说明"查过了这些项"，不等于"这些项都没问题"，更不等于可以免掉人工终审。我们的做法是清单结果与人工签字并行留痕，谁触发、谁确认，记录都在。

流程固化的真正价值在于稳定：同一份清单，谁触发都跑同样的一百多步，不依赖某个老师傅当天的心情和记性。省下来的注意力，留给真正需要判断力的地方——比如那份分级摘要里标成"严重"的问题，值不值得改、怎么改，永远是人的决定。
