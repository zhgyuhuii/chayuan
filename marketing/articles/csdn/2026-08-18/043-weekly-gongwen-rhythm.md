# 收文、办文、发文：一周五天的 AI 辅助节奏表

都说今年是 AI Agent 办公落地元年，但对文秘来说，落地不落地不看发布会，看周一早上签收单上那摞文件处理得完不完。我这一年把察元AI文档助手当成文档岗的常驻工具，慢慢攒出一张按天分的节奏表：哪天哪个环节、用哪个功能、注意什么，一条条列出来，办公室文秘、综合岗的同行可以直接对照着试。

## 周一：收文高峰，先校后办

周一上午签收的文件最多，转发件、代拟件、会签件一堆。凡是要我们转出去或者接着办的稿子，进门前先过一遍校对。

用加载项里的校对助手跑 dryRun，只出问题清单不动正文；确认后转成批注，让承办人自己看着改。提示词直接用这条：

```
帮我检查文档中的错别字，用批注标出原文和建议改法
```

注意分寸：别人单位的来文，批注是提意见，不是替人家改稿。涉及口径的问题写成批注说明，电话沟通确认，别自作主张做替换。

来文里还有一类是扫描转版的旧文件，格式乱、空行成片，先做一遍批量清理——空白行删掉、未使用样式清掉——再校对，效率高一截，承办人拿到手也不至于先皱眉头。

## 周二：办文拟稿，先糙后精

周二通常留给拟稿。我的习惯是先把意思写糙——第一稿允许口水话，把事情说清楚就行；然后让 AI 做第二遍：口语的段落用"正式化改写"过一遍，结构散的用"段落结构优化"理一遍。

关键设置在输入来源：自定义助手可以选"仅选区"，写回动作用"添加批注"。也就是说，我选中哪段它处理哪段，改法以批注形式贴在旁边，采不采纳我说了算。第一稿的意思是我定的，第二稿的体面让它提建议，这个分工踩下来最稳。

## 周三：会议日，纪要当天出

周三固定有会。散会后把录音转写的粗稿贴进 WPS，先手工删掉明显跑题的部分，再交给"生成会议纪要"的助手出框架，最后跑一遍提取行动项：

```
从会议记录中提取行动项，写明事项、责任单位（人）和完成时限，列表输出
```

纪要能不能当天出，考验的就是行动项这块——议定事项列清楚了，领导一眼能签；列不清，来回扯皮一个星期。提醒一句：转写稿里的责任科室和人名容易混，提取结果务必人工核一遍再发。"生成会议纪要""提取行动项"都是加载项内置的助手，一共 29 个，配上本地模型不连外网也能跑，会议材料不用出这台电脑。

## 周四：上报材料，数字过秤

周四常是各种材料的上报口。凡带数表的稿子，上报前必跑数字勾稽：

```
核对数表与正文数字是否一致（合计、百分比）
```

再配一条序号体例检查：

```
检查标题/条款序号（一、（一）、1.）是否层级混乱，批注指出
```

要是上报的稿子由几份材料拼成，再加一条多文档交叉：

```
打开目录下这几份文档，交叉检查错别字与术语是否一致
```

这三条跑完，材料被退回的概率明显下降。但要强调一句：勾稽是 AI 辅助，哪个数是对的、口径以哪个为准，还得人工去核，统计口径的事机器替不了你。

## 周五：整理归档，顺手为下周铺路

周五下午留半小时收尾。本周各事项的进展材料丢给"生成摘要"出周报底稿；文档做批量清理——空白行删掉、没用的样式清掉；最后把下周要跟的事项提取成行动项清单，贴在下周一的第一页。

这一步还有个隐性好处：周报从"周五晚上苦思"变成"材料堆里捞要点"，写周报这件事的心理负担基本消失了。

## 写在节奏表之外

这张表用了一年，最大的变化不是省了多少小时，而是心态：格式和校对的焦虑基本消失了，注意力能放到内容本身。当然，节奏表也不是死的——迎检周、跑会周会整段打乱，但按环节配工具的思路不变：收文配校对，办文配改写，发文配终检。

更要紧的是，节奏表里每一环的"确认"动作一个没少——AI 出清单，人拍板，这个顺序在任何一天都不能反。工具再顺，签字盖章的那个人，永远是你。
