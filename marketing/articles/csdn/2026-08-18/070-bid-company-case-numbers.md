# 资质、案例、数字：权威版本粘贴，机器只做整理

标书里最容易出事的部分，恰恰是最不该让 AI 发挥的部分：资质、案例、数字。模型最擅长的动作之一，是给你补全一份"看起来完全合理"的资质清单——ISO9001、ISO27001、CMMI3，念着都顺，但那是行业常见配置，不是你家的现实。案例更危险，让它"帮我写三个类似项目业绩"，它写出来的项目名称、合同金额、验收时间个个像真的，一个都经不起查证。AI 幻觉治理在投标场景里不是理论问题，是废标和评标质询的直接来源。我们组因此立了一条铁律：权威版本粘贴，机器只做整理。这篇讲这条规矩的具体执行，适合所有管资质册和案例库的商务、标书岗。

## 为什么粘贴这条土规矩比提示词管用

提示词工程解决不了幻觉，只能降低频率。资质等级、有效期、案例金额这类事实，模型没有可靠来源，它要么照抄你给的，要么编一个像的。与其费劲调教提示词防它编，不如从源头断掉：证书原文复制、合同关键页复制、审计报告数字复制，粘贴进文档的内容就是唯一事实源。剩下的问题只有一个——把这些素材整理成格式统一、前后一致、可核对的样子，而这恰恰是机器擅长的。事实层断供，语言层才有得用。

## 粘贴之后，机器做三件事

第一件，格式与术语统一。案例表里"合同金额"和"中标金额"字段混用、日期格式五花八门，交给内置的「术语统一」助手统一字段名；有效期统一成一种日期写法，评审专家翻起来看着专业——细节观感就是可信度。格式统一还有个更实际的作用：同一字段五种写法，人眼核对时会自动跳过差异，这是录入风险的放大器；统一之后，机器勾稽和人工核对都省力，两头的账都划算。

第二件，数字勾稽。案例汇总表的合计、正文里引用的"近三年累计合同额"，和粘贴进来的原始数字逐一核对：

```
核对数表与正文数字是否一致（合计、百分比）
```

第三件，批注核对。让 AI 把关键字段用批注列出来待人工复核：

```
把资质表和案例表里的证书编号、有效期、合同金额逐项用批注标出，我需要逐条对照原件
```

批注模式的意义就在这里：机器负责"列得全"，人拿着原件"对得准"，判断权始终在人。批量整理动作走 document_apply_ops，一次最多 200 条操作，先预览再确认落盘，每一步留痕。

## 从合同原件直接抽字段

做案例汇总表还有个更顺的路子：察元的「表单智能提取」助手，专门对合同、公文这类结构化文本抽取字段、输出 JSON。合同关键页粘贴进来，项目名称、甲方名称、合同金额、签订日期直接抽出来填进案例表骨架，再人工比对一遍原件。抄写录入这个环节被消灭了，抄错数字的可能性也就被消灭了——录入错误是案例表最常见的隐性风险，没有之一。

## 收尾的一道敏感信息扫描

资质册里藏着不少个人信息：授权代表的身份证号、保证金缴纳的银行账号、联系人手机号。定稿前固定跑一条：

```
查找疑似身份证号、手机号、银行卡号并批注
```

批注出来之后逐条确认：该在的核对无误，不该出现在这一册里的立刻处理。这类信息漏出去，轻则尴尬，重则违反保密约定，一次都不该赌。

## 边界的话说到死

资质的真实性、案例的可查证性、数字的准确性，责任永远在人，机器只做整理、核对、列表这类语言层和格式层的活。签字盖章前的那一版，必须有人拿着原件逐字过一遍——这不是对工具不信任，是对流程的尊重。评标质询的时候，没有人关心你的标书是哪个 AI 整理的，评委只关心那些证书和数字是不是真的。把"权威版本粘贴"焊死在流程里，AI 才帮得上忙而不添乱。
