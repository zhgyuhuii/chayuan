# 会议纪要十分钟出稿：转写稿整理流水线

以前我最怕下午的会。散会时办公室主任一句"纪要明早要"，就意味着那天晚上交代了：两个小时的会，录音转写出来两万字，口语、重复、跑题全在里面，得先花一晚上把它读薄，再撑着眼皮按"会议概况—议定事项—责任分工"搭架子。

现在这套活我跑出了流水线，从转写稿贴进 WPS 到能交给领导改的纪要初稿，十分钟上下。工具是 WPS 里的察元加载项加本机模型，全程离线，录音稿不用传到任何外部服务。经常被会议纪要追着跑的办公室文秘、会议记录员可以照着搭一遍。

## 第一步：粗清理，先做减法

转写稿贴进文档，先手工删三样：寒暄客套、明显跑题的段落、重复表述。这一步看似手工，其实很快——扫读删段比逐字改写快得多，五分钟能砍掉一半篇幅。这一步不交给 AI 的原因很简单：哪些算跑题，得参加过会的人才知道。

顺手用"文档批量"里的删除空白行，把转写稿带的成片空行清掉，版面干净了后面好操作。版式也顺手统一：转写工具导出的文件常带一堆杂乱样式，批量清理未使用样式处理掉，后面拼议题小结时不会格式打架。

## 第二步：分块喂给纪要助手

清完的稿子还是长。加载项里的"生成会议纪要"助手会处理长文；如果你像我一样用 Claude Code 连着察元的 MCP 干活，就要有分块意识——超过约 80k 字符的文档改用分块读取，不然会收到 DOCUMENT_TOO_LARGE 的报错。分块跑纪要有个技巧：按议题分，一块出一个议题的小结，最后拼起来，比整篇一口气生成稳得多，也方便会后按议题增删。

## 第三步：提取行动项，这是纪要的命门

纪要的核心不是记录谁说了什么，是议定事项谁来办、何时办结。用提取行动项：

```
从会议记录中提取行动项，写明事项、责任单位（人）和完成时限，列表输出
```

输出拿回来必须人工过一遍，重点是两处：责任主体写混的（"会上商定由甲科室牵头"，转写稿里几个科室名字常常前后打架），和时限模糊的（"尽快""近期"要回填成明确时点）。这一遍人工核对不能省——纪要一发出去就是派活依据，写错了得罪人，追责的时候还说不清。拿不准的条目，钉一条批注"与录音稿核对"，散会后找主持人确认一句再定稿；纪要的权威性，就是这么一条条抠出来的。

## 第四步：术语与人名统一

转写稿的人名、机构名是重灾区，同音字一堆。用"术语统一"把机构叫法对齐，人名逐个肉眼核——本地模型对常见同音字有帮助，但人名这东西，宁可多花两分钟自己过一遍，也不要信机器。有个土办法：把与会名单放在手边，纪要里出现的每个人名对着名单核一遍。

## 第五步：终检后交付

成稿前跑一遍精简版终检：

```
帮我做发布前终检：错别字、标点、数字前后一致性；全部用批注输出
```

会议纪要里的数字（金额、时限、指标）前后不一致是高频翻车点，正文写"两周内"，行动项表里变成"月底前"，这遍检查专门兜这个底。批注清完，存盘交付。

## 十分钟能出什么、出不了什么

再补一句流水线的门槛。察元在 Windows 上一行命令就能装：PowerShell 跑安装脚本，四步闭环——装加载项、注册 MCP 服务开机自启、四级体检、投放技能文件；模型端点指向本机 Ollama，全程离线。装完 WPS 打开就能用，不需要装 Node.js，也不需要会写代码。会议纪要这种时效强的活，工具的维护成本必须低到可以忽略，流水线才立得住。

说句实在话：十分钟出的是"能改的初稿"，不是"能发的定稿"。流水线省掉的是读薄、搭架、誊清这些机械劳动；议题的轻重取舍、表述的分寸拿捏，还是开会的人来定。

但对比以前"一晚上对录音"的日子，这十分钟已经把纪要从负担变成了散会即办的日常活——上次会开完二十分钟，纪要已经在领导邮箱里了。第二天早上他回了一句"以后都按这个来"，这流水线就算站住了。
