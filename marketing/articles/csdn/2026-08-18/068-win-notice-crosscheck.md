# 中标公告与标书口径：事后勾稽别嫌晚

上个月一个项目中标公告挂网，群里在刷恭喜表情，我干了件不太合时宜的事：把公告里的关键信息和我们的标书对了一遍。对出两处差异。第一处无伤大雅：公告里的中标金额是分项汇总后四舍五入的口径，和我们报价表差在小数位。第二处把我惊出一身汗——公告工期写"360 日历天"，我们标书正文实施方案里有一处笔误写成了"36 个月"，等于把工期放大了三倍，幸好那天评标专家没较真。

有人会问：公告都挂了，事后勾稽还有什么用？用处大了——公告改不了，但下一本标书的口径库是能修的。这就是我想说的：勾稽别嫌晚，每一本标书都是下一本的底稿，中标公告是甲方免费送你的一份官方口径校验报告，不用白不用。

## 事后勾稽具体怎么做

公告一般是网页或 PDF，我的土办法是把公告文本整段复制进 WPS 建一页对照文档——察元AI文档助手是跑在 WPS 文字里的加载项，内容进了 WPS 就进了它的作业范围。然后两份文档交叉核对，走 MCP 通道让 Agent 干，先注册服务：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

然后一条提示词：

```
打开中标公告和标书两份文档，逐项核对项目名称、中标金额、工期、质保期等数字与口径；不一致的，把批注标在标书对应位置并注明公告口径
```

长标书用 document_chunks 分块读，document_locate 定位金额、日期这类关键字段。所有差异以批注形式钉在标书上，形成一份口径差异清单，批注不改正文，留痕清楚。

两个执行细节。一是批注钉在标书侧而不是公告侧：公告是外部文件、不可改，标书底稿才是要修的对象，批注钉在改动现场，处理完销号。二是勾稽清单当天归档，趁记忆新鲜把每条差异的成因写进去——"当时为什么会写错"比"错在哪"值钱，下回组内培训，这就是现成的案例素材。

## 差异分三类处理

批注出来后人工分类，这一步是勾稽的价值所在。

第一类，官方口径处理：金额四舍五入、项目名称规范化这类，记录下来，下次对外报价和摘要主动对齐官方口径，省得客户对不上号。

第二类，自己笔误：36 个月那种。除了改底稿，还要进团队的"常见坑清单"——我们组的坑清单里"年限与月数混写"已经出现过三次，出现三次就不是手滑，是系统性弱点，值得在终检清单里单独加一条口径词核对。

第三类，招标文件、标书、公告三方各执一词的：标记为不可控差异，写标时对这类字段主动做交叉引用标注，真遇到评标澄清，三十秒内能定位到原文。

还有个容易被忽略的用途：公示期和质疑窗口。公告挂网到质疑期结束通常有几天，这段时间把公告口径、开标记录、自己标书三方对一遍，如果发现评分汇总里有明显异常，质疑还是不质疑、材料怎么组织，心里是有底的。勾稽做得早，决策窗口就宽——真到质疑期最后一天才发现问题，连准备材料的时间都不够。

## 把勾稽成果沉淀进知识库

差异清单攒多了就是资产。察元支持知识库 RAG，对接察元桌面版或网络版，往期标书、口径差异清单、常见坑清单都可以入库；下次写标，Agent 通过 kb_retrieve 直接检索"上一批市政项目的工期口径怎么写的""这类项目质保期承诺过几年"，而不是靠老员工的海马体。桌面单机版走本机服务、免登录，标书资产同样不出域，这一点对涉敏项目组很重要。

投标这件事，单看一个项目是冲刺，拉长看是口径资产管理。评标专家给你挑过的错、公告替你校准过的数，都是下个项目该免费复用的东西。我们组现在的规矩是：公告挂网当天，勾稽清单必须出来——庆祝可以，先干完这半小时的活。

边界也提一句：公告口径以官方公示为准，勾稽只做内部复盘；涉密项目注意公告文本本身也要按密级管理，复盘文档别随手存到网盘上去。
