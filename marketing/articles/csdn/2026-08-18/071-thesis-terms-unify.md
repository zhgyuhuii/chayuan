# 开学前最后一周：论文术语统一交给机器

八月最后一周，师门群开始热闹了。有人晒录取通知，有人问选课，更多的是研三师兄在倒苦水：导师批注回来了，整整一页红字里最扎眼的一条是"全文术语请统一，盲审稿开学第一周交"。他打开论文一搜，同一个概念，第二章写"大语言模型"，第四章简写成 LLM，摘要里又变成"大规模语言模型"；被试一会儿叫被试，一会儿叫受试者，一会儿又叫研究对象。三十万字的学位论文，这种漂移少说几十处。

他第一反应是全局替换，试了两下就停手了。搜索替换在这种场景下根本不敢用：参考文献条目里的原文标题不能动；直接引语里别人怎么写就得怎么保留；缩写第一次出现时"大语言模型（Large Language Model, LLM）"这种定义句恰恰需要两种写法并存。同一个词，有的位置该换，有的位置换了一定出错，而全局替换不认识语境。

为什么论文写到后期一定会术语漂移？想想写作过程就明白了：各章节多半是从自己的小论文、开题报告、组会汇报里改出来的，写于不同时期，叫法跟着当时的文献走；文献是中英文混着读的，英文的表述习惯不知不觉渗进中文；如果是多人合作的课题报告，各写各的，拼起来更是南北混搭。术语漂移不是态度问题，是长周期写作的必然副产品。

这就是我劝他把这类活交给察元AI文档助手的原因。它是 WPS 文字里的加载项，装完重启 WPS 就能用，内置的二十九个助手里有一个就叫"术语统一"；如果习惯在终端里干活，也可以让 Claude Code 这类外部智能体通过 MCP 直连 WPS 文档来干，服务地址就是本机的 62588 端口，一行命令注册即可。

## 三步走，人只做中间那步

第一步，先枚举不动手。让 AI 把全文里同一概念的不同写法全部找出来，逐处列出位置和上下文，提示词直接复制：

```
找出全文里同一概念的不同写法，逐处列出位置和上下文，先不要动正文
```

这一步的产出是一张"漂移清单"：哪个概念有几种写法、各出现在哪几页。人要做的是拿着这张清单定标准——统一到哪个写法、哪几处保留。标准的依据不是个人喜好，是学科惯用叫法、导师的意见、学校论文模板，这一步机器替不了你。

第二步，按圈定执行替换，但先要预览。这类要动正文的写操作有个确认机制：没有显式确认，就只返回替换预览、不落一个字。所以可以让它放心大胆地排方案：

```
按我圈定的标准写法统一这些术语，例外清单里的位置保留，替换前先给我预览
```

例外清单要写明：参考文献条目、直接引语、缩写首次定义处。预览逐条看过去，确认没有误伤再放行。另有一类只提意见、不动正文的活，比如错别字提示，走批注输出，批注钉在原句上，改不改人定——两种方式各管各的，互不添乱。

第三步，复核。替换完再让它把全文扫一遍，确认没有漏改和误改：

```
复核一遍全文，确认术语没有漏改和误改，把结果汇总给我
```

师兄那三十万字的术语漂移，一个晚上清完。他还顺手把定稿的术语对照表单独存了一份，后面返修、写答辩材料、缩写成小论文时直接复用，不用从头再对。第二天他在群里发的截图是导师的新批注："这稿子顺眼多了。"

## 说两句边界

术语统一是典型的"标准明确、重复度高、不需要判断力"的体力活，机器干最合适；但"统一到什么标准"是学术判断，得人定。另外机器的替换结果建议抽查百分之十，尤其注意跨章节粘贴进来的段落——漂移最严重的地方，往往就是拼接痕迹最重的地方，顺手能发现别的毛病。

适合谁先试：学位论文定稿前的同学、多人分章节合写课题报告的团队、期刊论文返修时被审稿人指出术语不一致的作者。开学在即，盲审的钟声比闹钟管用，这种能一个晚上清掉的隐患，别留到答辩现场。
