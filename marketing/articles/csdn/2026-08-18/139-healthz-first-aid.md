# 连不上先打 healthz：一条命令的分诊逻辑

Claude Code、Cursor 接 MCP 的教程满天飞，但评论区翻车率最高的永远是同一类问题：工具列表里没有察元、一调用就报 WPS_AGENT_OFFLINE、Agent 干脆说连不上服务。这些问题十有八九不用重装、不用改代码，卡住的真正原因是排错没有章法，东试一下西点一下，越弄越乱。这篇给一套我自己沉淀的分诊流程，核心就一句话：连不上，先打 healthz。适合所有刚把察元AI文档助手接进智能体的同学照着走。上周团队就遇到一例：同事兴冲冲装好环境，第二天说工具全没了，报的就是 WPS_AGENT_OFFLINE，最后发现只是 WPS 没开——要么手动打开 WPS，要么让 Agent 调 wps_launch 冷启动，这种问题重装一百遍也解决不了，只能靠分诊逻辑。

## 为什么第一步永远是 healthz

排错最忌讳全线撒网。healthz 是察元本机 MCP 服务的健康检查端点，一条命令就能把故障一刀切成两半：服务侧问题和客户端侧问题。

```bash
curl http://127.0.0.1:62588/healthz
```

返回 online，说明本机服务活着，问题出在智能体那边的注册或配置；连不上或者不返回 online，说明服务本身没起来，先修服务。两半的处理路径完全不同，先分诊再动手，五秒钟省两小时。

## 第零步：确认安装没欠账

分诊的前提是东西装对了。察元的一行安装脚本自带四步体检：加载项落位、健康检查、initialize 握手、桥接工具验证，一路绿灯才算装完。如果你当时跳过了体检，或者用了别的路子装，先把这四步补着过一遍——很多"连不上"其实是安装阶段欠的账。底账也交代一下：加载项随 WPS 自启，MCP 服务是单文件常驻，不依赖 Node.js 环境，明白这些，排错时就不会往"是不是要装 Node"上绕路。

## 分支一：返回 online，查客户端注册

服务在线但工具不出现，九成是注册问题。Claude Code 直接重跑注册命令：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

然后重开会话再看工具列表。Codex 用户检查 ~/.codex/config.toml 里的 url 字段，Cursor 用户检查项目里的 .cursor/mcp.json，最常见的低级错误是地址抄错一位数字。还不放心，用 MCP Inspector 做独立验证：

```bash
npx @modelcontextprotocol/inspector
```

选 Streamable HTTP 类型，填 http://127.0.0.1:62588/mcp，点 Connect。工具列表能拉出来，链路就是通的，问题必然在客户端配置，回去逐字核对你的配置文件。

## 分支二：连不上，先把服务拉起来

服务不在线，先重启 WPS——加载项随 WPS 启动并把本机服务带起来，4.1.2 版本对 sidecar 做了隐藏启动和掉线自愈，多数情况重开 WPS 就恢复。如果服务已经 online 但工具调用报 WPS_AGENT_OFFLINE，注意这个码的含义是 WPS 或加载项没连上 sidecar，处理办法还是同一个：重开 WPS，让加载项、sidecar、服务三者重新握手。顺带说一句服务的底细：它在三个平台分别注册到开机自启体系里，Windows 是注册表运行键，macOS 是 LaunchAgent，Linux 是 systemd 用户服务，正常情况开机即起；4.1.2 之后 sidecar 隐藏启动、掉线自愈，比早期版本稳了不少。

## 第三步：链路通了，按错误码对症下药

链路通了但具体调用失败，看返回的错误码，逐个对号：DOCUMENT_TOO_LARGE 是文档超过约 80k 文本阈值，改用 chunks 分块读取或者加 force:true；LOCATE_MISMATCH、LOCATE_NOT_FOUND 是锚点校验失败或未找到，让 Agent 重新定位原文再操作；MODEL_NOT_CONFIGURED 是还没配置校对模型，先把模型端点配好；LICENSE_REQUIRED 是免费额度用尽，这个码不会弹购买窗，看到它别以为程序死了；CONFIRMATION_REQUIRED 则根本不算错误，是写操作在等你传 confirmed:true，属于设计如此，确认后重发即可。错误码分诊的价值，在于把一句"不行"翻译成"为什么不行"：没有错误码的排错是玄学，有错误码的排错是查表。建议把这张对照表贴进团队 wiki，新人接手 MCP 环境先读它，能省掉一半求助消息。

## 三条心法收尾

一，只监听 127.0.0.1 是刻意设计，本机即信任边界，所以不存在 Token 配错这类问题，别在找密钥上浪费时间。二，远程访问场景需要代理或者用 CHAYUAN_MCP_PORT 调整端口，那是另一个专题，下一篇细说。三，重装永远是最后一个选项，绝大多数"连不上"停在 healthz 这一步就能定位。四，排错要留痕：healthz 的返回原文、错误码、当时的操作，随手贴进工单或群消息，下一个人接手时不必从零复现，你自己复盘时也有据可依。

排错和看病一个道理，先验血再拍片——healthz 就是那次验血，别一上来就推手术室。
