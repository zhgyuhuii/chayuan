# MODEL_NOT_CONFIGURED：校对模型配置排错记

上周一位新同事装好察元AI文档助手，兴冲冲点校对，界面回了一个 MODEL_NOT_CONFIGURED。他的第一反应是"软件坏了"，差点卸载重装。其实这是最友好的报错之一——它说得明明白白：校对模型没配置。单位内网交付环境里，这个错几乎人人会撞上一次，借这个坑把排错过程记下来。

## 先读懂错误码

察元的错误码设计是能省诊断时间的那种：`WPS_AGENT_OFFLINE` 是 WPS 或加载项没连上本机服务；`MODEL_NOT_CONFIGURED` 是服务在线但没有可用的校对模型；`LICENSE_REQUIRED` 是免费额度用尽，而且不弹购买窗，很克制；`DOCUMENT_TOO_LARGE` 是文档太大需要分块；`CONFIRMATION_REQUIRED` 是写操作没带确认。五分钟记住这五个码，八成的问题不用猜。

## 我的排错顺序

**第一步，确认服务活着。**

```
curl http://127.0.0.1:62588/healthz
```

返回 online 说明本机 MCP 服务正常，端口 62588 只监听 127.0.0.1，本机即信任边界，无需 Token。这一步如果失败，你看到的报错多半是 WPS_AGENT_OFFLINE 而不是 MODEL_NOT_CONFIGURED——所以这步更多是建立基线，排除最底层的故障。多说一句，察元的一键安装脚本自带四级体检，从 jsaddons 注册、/healthz、initialize 握手到工具桥接逐层验证，装完的终端输出里哪层亮红灯一目了然，排错时先把这份输出翻出来，能省一半时间。

**第二步，检查模型配置。** MODEL_NOT_CONFIGURED 的直接原因就是校对模型一栏空着。察元支持任意 OpenAI 兼容端点，Ollama、LM Studio、Xinference、OneAPI、New API 都行。以 Ollama 默认配置为例，地址填它自带的 OpenAI 兼容层 http://127.0.0.1:11434/v1，模型名写你拉下来的那个标签，一项都不能少。

**第三步，验证端点本身可达。** 配置填了不代表通了，直接探一下推理端点（仍以 Ollama 为例）：

```
curl http://127.0.0.1:11434/v1/models
```

能列出模型说明推理端点没问题；列不出来就去查 Ollama 服务起没起、地址端口对不对、模型拉没拉。同事那次就是配置填了但 Ollama 根本没启动，端点一探，真相大白，跟察元半点关系没有。

**第四步，重新发起校对。** 配置保存后重跑，MODEL_NOT_CONFIGURED 应声消失。如果换了别的报错，按上面的错误码表对症处理，思路不变。

错误码表里还有一对定位类错误值得顺手记：LOCATE_MISMATCH 是锚点校验失败，LOCATE_NOT_FOUND 是没找到锚点。遇到它们别急着重试，先把位置描述改具体——"合计行上面那行"就比"表格里加一行"好定位得多。

## 排错时的两个好习惯

**隔离变量。** 一次只改一个地方：先证明服务在线，再证明端点可达，最后证明配置正确，三步都过了再怀疑软件本身。同事那次如果先探端点，五分钟就能定位，坏就坏在把"配置填了"当成了"配置通了"。

**留一个图形化验证工具。** 命令行不直观的时候，用 MCP Inspector 连上去看：`npx @modelcontextprotocol/inspector`，类型选 Streamable HTTP，地址填 http://127.0.0.1:62588/mcp，点 Connect 能看到工具清单和调用结果，给同事演示或者自查都好用。

## 顺手记下两个相邻的坑

一是 DOCUMENT_TOO_LARGE：改用 `document_chunks` 分页分块，或对 `document_get_text` 传 force:true（阈值约 80k），别跟长文档死磕。二是 CONFIRMATION_REQUIRED：`document_add_comment`、`proofread_apply_comments` 这类写操作必须显式传 confirmed:true 才执行。这不是 bug 是安全设计，批注落盘前多问一句，对文档场景来说是优点，我把最初的烦躁收回了。至于 LICENSE_REQUIRED，遇到了说明免费额度用尽，它安静报错、不弹购买窗，处理完额度问题再继续即可。

## 复盘结论

这次排错总共六分钟，其中五分钟花在"读懂报错在说什么"上。内网环境里，报错信息就是最好的文档——前提是你肯读，而不是先怀疑软件坏了。我后来在科室群里立了个规矩：装完先跑一遍 healthz 确认返回 online，再配模型端点，最后拿一小段文本试校对，三步走完，后面基本太平。事后我把这次排错记进了科室的内部文档：错误码、原因、解法一张表，第二次撞上的人五分钟自救——排错经验不沉淀，等于每个人都要重新踩一遍坑。排错这件事，顺序对了就是体力活。
