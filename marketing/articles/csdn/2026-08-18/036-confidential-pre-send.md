# 材料外发前十分钟：保密检查助手的分级风险提示

上个月一个周四，下午四点五十，兄弟单位来电话，五点整要一份项目情况材料。材料在，但经办人请假了。我接手的第一件事不是点发送，是把文档拖开做保密检查——外发前十分钟是保密事故的高发时段：人急着交差，眼睛只看内容顺不顺，不看里面藏了什么。

以前也吃过亏。同事把内部台账直接外发，表格第三列带着几十个手机号，对方一句"你们这份数据我先删了啊"，让人后背发凉。从那以后我们科室立了规矩：凡外发，先过检查。过去靠肉眼，现在多了一道机器筛查——察元AI文档助手里有个"保密检查"助手，它不定密，干的是把风险点亮出来的活：密级标识有没有、涉军涉装表述、单位身份信息、联系方式、项目编号、商业秘密，按类别给出分级风险提示。

具体流程四步，十分钟内能走完。

第一步，全文跑保密检查。在 WPS 加载项里点开助手跑全文，输出一份按类别归组的风险列表。重点看分级提示——哪些是"疑似涉密表述"，哪些是"一般身份信息"，提示级别不一样，处理方式也不一样，不是见红就删。

第二步，敏感信息定位。光有列表不够，要落到位置。我配的提示词是：

```
查找疑似身份证号、手机号、银行卡号并批注
```

批注直接钉在具体位置上，点开批注就能跳过去看上下文，比对着列表在文档里搜快得多。

第三步，人工判断。这一步机器替代不了：这些手机号要不要留，涉军表述是不是公开口径，项目编号外不外露，得按保密要求和业务口径定。涉密不涉密，定密有法定程序，AI 的提示只是辅助参考，不替代定密程序和人工保密审查——这句话我建议原样写进每个科室的操作规程。

第四步，删改后复跑。改完再跑一次检查，确认风险清了再外发。两分钟的事，图的是心里有底。

分级风险提示怎么用，展开说两句。几类线索里，密级标识和涉军涉装属于高优先级——一旦疑似，宁严勿宽，先按流程核实清楚再说；联系方式和项目编号属于看场景的：对外联系卡上的电话本来就该留，名单附表里的电话就该处理，同一个提示级别、两种处置方式；商业秘密类提示要结合业务判断，合作单位的名称在协作材料里出现是正常的。分级的价值就在这里：让你先处理要命的，再处理要紧的，而不是被一张平铺的问题清单淹没。

这套检查现在也成了我们科室交接材料的规矩：经办人请假，接手的人第一件事跑保密检查，第二件事看历史批注。口头交接靠记忆，机器交接靠留痕，后者靠谱得多——那天的材料如果经办人在，他可能十分钟就发出去了，但流程就是流程，赶时间不是省步骤的理由。

再说我最看重的一点：材料不出域。察元的架构是 WPS 加载项加本机 MCP 服务，服务只监听 127.0.0.1 的 62588 端口，模型端点可以配内网部署的开源模型，整个检查过程文档不离开这台机器。数据安全不出域不是一句口号，是网络层就决定了的。对比一下就能明白：把文档粘贴到某个网页版工具里查敏感词，光"上传"这个动作本身就有合规风险——用工具防风险，结果工具先制造了风险，这个账不能这么算。

边界也得讲清楚：AI 检查会有漏报误报。生僻的化名、变形写法（比如手机号中间加横线）可能漏，正常的年份数字偶尔会被误报成疑似信息。它是把网眼织密的辅助手段，兜底的永远是人的判断和制度。但至少，那天四点五十接手的材料，我用八分钟过完检查，四点五十八分发出去，比以往任何一次手工检查都踏实。外发前十分钟这个场景，值得每个跟材料打交道的人给自己留一道机器筛。
