# 加载项内置检查还是 Claude Code：两条路径怎么选

后台被问得最多的问题，不是察元AI文档助手怎么装，而是装完之后到底走哪条路。察元的检查能力有两条相互独立的路径：一条是 WPS 加载项内置的 29 个助手，装好加载项就能在菜单里直接点，全程不碰终端；另一条是外部 MCP 智能体，Claude Code、OpenAI Codex、Cursor 这类工具通过本机 MCP 服务直连文档，能调用 46 个文档工具。今年 MCP 生态爆发，Claude Code 的热度又把第二条路推到台前，于是不少同事犯了选择困难。这篇就把两条路摆到一张桌上比一比，最后给出我自己的用法分工。

## 两条路各自的形态

内置路径的入口就在 WPS 界面里。选中一段文字，从菜单进，能看到拼写与语法检查、生成摘要、翻译、术语统一、生成会议纪要、政策/公文风格改写这一排助手，共 29 个。跑完的结果通过"写回八式"落回文档：插入到光标处、替换、添加批注、批注加替换、追加到文末，按需要挑。整个过程不需要任何外部 Agent，也不需要理解 MCP 协议是什么，会用右键就会用这条路径。

MCP 路径的入口在智能体那边。以 Claude Code 为例，一条命令完成注册：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

之后在 Claude Code 里说一句"检查这份文档的错别字"，它会自己调工具：读段落列表拿锚点、长文用 document_chunks 分块、定位用 document_locate，最后把批注钉到具体文字上。46 个工具里还有批量写回的 document_apply_ops（单次最多 200 个操作）、检索知识库的 kb_retrieve，以及 12 个表格动作。任务越复杂，这条路的编排空间越大。

## 四个维度挨个比

上手门槛，内置完胜。开箱即用，菜单点选，学习成本约等于零；MCP 路径要先装智能体 CLI、注册服务、理解工具调用的工作方式，对非技术岗是一道真实的门槛。

任务上限，MCP 赢。内置助手是单任务单文档，MCP 智能体可以做多文档交叉、批量整改、先检索知识库再动笔这类长链条任务，两边的差距在复杂度上来之后会迅速拉开。

可控性，打平，而且值得单独讲。两条路径共用同一套确认策略：MCP 侧 document_replace 不传 confirmed:true 就只返回 preview 不写盘；document_add_comment、proofread_apply_comments 必须显式 confirmed:true 才动手。内置侧同样有先出结果再写回的习惯用法，我在两条路上都用同一条提示词开场：

```
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注
```

成本与依赖，内置路径只依赖加载项和模型配置；MCP 路径要多养一个智能体环境。内网用户如果连外部智能体都不方便装，内置路径配上 Ollama 本地端点就是完整闭环，谁也不用羡慕谁。

## 两条路共用同一个地基

再补一个很多人没意识到的点：两条路径共用同一个本机服务和同一套模型配置。加载项装好后，MCP 服务就在 127.0.0.1:62588 上常驻，智能体注册时连的就是它；模型端点配一次，内置助手和外部智能体都生效。这意味着切路径没有迁移成本——今天用内置助手校对，明天想试 Claude Code，装上、注册、开聊，文档还是同一份，模型还是同一个。想确认服务状态，随时打一下健康检查：

```bash
curl http://127.0.0.1:62588/healthz
```

返回 online，说明两条路径的地基都是好的。

## 我的分工建议

日常单篇、几分钟要结果，走内置。周报、通知、会议纪要这一类，点开助手就跑，不值得为它开终端。批量与交叉，走 MCP。月份汇编十几万字、多份文档交叉核对术语、几百处问题要按严重程度分级落批注，这种活交给 Claude Code 编排，人只看最后的分级摘要。团队推广的顺序也建议先内置后 MCP：让同事先在内置助手上尝到甜头，需求长出来了再教他们接智能体，接受度高得多。

## 边界说在最后

两条路径都只是辅助：错别字和格式问题让机器兜底，事实差错、口径把握、密级判定还是人来。涉密场景先用保密检查过一遍风险提示，定密永远是人工的事，这条不因为走哪条路径而改变。

路径选择没有标准答案，但有一条经验挺标准：先用起来再优化。内置路径今天就能上手，MCP 路径等真有复杂需求再切过去，一点也不迟。
