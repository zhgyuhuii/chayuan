# 晚上十点接活：四十分钟交出十五页报告校对

晚上十点零七分，部门群里弹出领导一条消息：明天上午区里要材料，十五页的汇报报告刚定稿，"文字关你把一下，明早八点前给我"。后面跟一个抱拳表情。

做过行政或者文字岗的人都懂，这种活折磨人的地方不是难，是碎。十五页文档，通读一遍要二十分钟，逐字校对至少两小时起步，眼睛到第三页就开始跳行。我以前的笨办法是打印出来拿尺子压着逐行看，稳是稳，但熬人。今年组里用上了察元AI文档助手——一个装在 WPS 文字里的开源加载项，加一个跑在本机的 MCP 文档智能体服务——这套急活流程被压缩到四十分钟。拆开讲讲。

## 第一步：让 AI 先看，人后看

材料到手，我第一件事不是自己读，是让察元先跑一遍校对。在 WPS 侧边栏用"纠正拼写和语法"助手，或者走 MCP 的校对工具，默认 dryRun 模式只返回问题列表、不动正文。这一步的顺序很关键：校对类工具最怕上来就改，改错了还得回头找。可直接复制的提示词：

```
帮我检查文档中的错别字，用批注标出原文和建议改法
```

更稳一点的版本，先看清单再落批注：

```
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注
```

十五页一万多字，远没到它约 80k 的大文档阈值，一次吃得下。跑完返回的问题列表按类型分好：错别字、标点、疑似搭配不当，各自带原文位置，省去了我自己划线的工夫。

## 第二步：确认后转批注，逐条人工拍板

列表里明显是真错的，我确认后让助手转成批注，批注钉在原文位置上，我和领导都能看到改的理由，不是黑箱改完拉倒；拿不准的单独标出来留给自己判断。比如"截止"和"截至"这类高频混用，AI 给的建议我基本都采，但涉及行业惯用词的提示，我会先问业务同事再定。

## 第三步：发布前终检兜底

错别字只是下限，汇报材料真正的大坑是数字。终检我固定用这条：

```
帮我做发布前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

这次真抓出一处：正文写增长百分之十二点四，表格里是十二点五，两处对不上。这种问题人眼校对基本必漏——注意力在字上，不在数上。而上级看材料，偏偏最先看数。

## 第四步：人工过批注，定稿交付

批注过我一遍，真错采纳、误报忽略，改完另存交付。全程四十分钟左右，其中我的人工判断时间占一半以上。凌晨前睡觉，第二天八点材料准时到领导手里。

## 顺便回答两个常被问的问题

一是它和 WPS 自带拼写检查什么区别。自带检查管的是单字层面的明显错误，而这类汇报材料的坑更多在搭配、标点体例、数字一致性这类跨句问题上，得读上下文才看得出来，这正是接了大模型的助手擅长的。另外说明一句，察元是独立的第三方加载项，和金山自己的 WPS AI 互不干扰，装了谁都不影响谁，不存在二选一。

二是十五页算大文档吗。不算。它的工具链对超长文有专门设计：读正文前先取文档元信息，报告字数、段落数、是否建议分块；真到几十页的大部头，会自动切换分块读取，批注照写。所以这套流程从三五页的通知到几十页的总结都能套。

## 三条实战提醒

- 永远先预览后写回。写操作不传确认参数，系统只返回预览不落盘，这个安全位值得保持，别图快跳过。
- 表格里的错字单独钉。补一句"重点检查表格单元格里的错别字，批注必须钉在具体错字上"，否则批注可能飘到表格外。
- 模型可以全本地。我们组用 Ollama 挂本地模型，报告不出网，内网机器照样跑。2026 年 AI Agent 办公落地这一年，共识已经很明显：能力要进工作流，数据要留在本机。

这套流程适合谁：机关和企业的材料岗、领导身边的秘书岗、评审季的方案写作者。有人说 AI 校对迟早取代文字岗，我的体感相反：它取代的是拿尺子压纸的那个动作，拍板的还是人。急活来的时候，工具升级永远快过焦虑，先把流程跑顺比什么都实在。

想上手试试的话：察元开源（Apache-2.0 协议），WPS 加载项加本机 MCP 服务，一条命令安装，Claude Code、Cursor、Codex 都能通过 http://127.0.0.1:62588/mcp 直连。装完访问一下 healthz，看到 online 再开工。
