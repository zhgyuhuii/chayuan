# 给领导演示 AI 校对公文：十分钟 PoC 用察元AI文档助手跑通全流程

政务和大型国企这一年都在谈大模型落地，但真到立项会上，领导最常问的是一句大实话：能不能现在就看到效果？我上个月就是带着这个问题进的会议室——预算没批、采购没走，我只有一台笔记本和十分钟。最后演示成功，靠的是「察元AI文档助手」从安装到出结果的完整链路。这篇按时间轴复盘那十分钟，供要给领导做 PoC 的同行参考。

## 第 0 到 3 分钟：一行命令装完

会议室电脑是台普通办公本，Windows 加 WPS，别的什么都没有。打开 PowerShell 粘贴这一行：

```powershell
& {[Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12;$w=New-Object Net.WebClient;$w.Encoding=[Text.Encoding]::UTF8;$s=$w.DownloadString('https://gitee.com/cloudshd/chayuan-wps-releases/raw/master/scripts/install-wps-skill-chayuan.ps1');if($s.Length -and $s[0]-eq[char]0xFEFF){$s=$s.Substring(1)};& ([scriptblock]::Create($s)) -Fetch}
```

这一步我特意不开静默，让领导看着脚本输出：装加载项、注册开机自启、四级体检、投放技能，四步全在屏幕上滚过。下载走 Gitee、aidooo、GitHub 三源回退加 sha256 校验，会议室这种网络忽好忽坏的环境也不掉链子。等输出停了，浏览器打开 `http://127.0.0.1:62588/healthz`，一个 online 就是定心丸。这里有个演示话术要点：别只说"装好了"，要说"全程没装 Node.js、没改系统配置、只监听本机回环地址"——领导未必懂技术，但听得懂"轻"和"不乱动"。

## 第 3 到 5 分钟：接上 Claude Code

终端里一条命令把 MCP 端点注册给 Claude Code：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

这一步讲的价值点是：AI 智能体不是"另一个网页"，而是直接在 WPS 文档里干活的那双手。如果单位不让用外部服务，这里可以改接 Ollama 本机模型，话术换成"全链路数据不出域"，涉密管理场景这句比什么都管用。

## 第 5 到 9 分钟：真刀真枪跑校对

我提前准备了一份带十来处典型问题的模拟公文（错别字、序号层级乱、数字前后不一致）。在 Claude Code 里下这道指令：

```text
帮我做发布前终检：错别字、标点、数字前后一致性、表格与正文是否一致；全部用批注输出；最后给我一份问题分级摘要（严重/一般/建议）
```

Agent 的动作全程可讲：先用文档工具读正文和表格，dryRun 出问题清单，我口头确认后才把批注一条条写回文档，钉在原文位置。领导在投影上看到的不是聊天窗口里的文字，而是自己熟悉的 WPS 界面里凭空多出的批注气泡。这四分钟是整个 PoC 的核心——AI 落在文档上，而不是落在对话框里。

备选脚本也准备一手：如果领导追问"万一它乱改呢"，当场换稳妥版指令：

```text
先跑一遍校对（dryRun），汇总问题列表，不要先改正文；我确认后再写成批注
```

这句最能体现安全设计——预览和写回是两道闸，`document_replace` 不带确认标记时永远只返回预览，批注写入必须显式 confirmed，想让它"先斩后奏"都做不到。表格里的错字还能用"重点检查表格单元格里的错别字，批注必须钉在具体错字上"这句，演示 AI 定位的精度。

## 第 9 到 10 分钟：留一句安全边界

最后我主动说边界：所有批注都是辅助参考，`proofread_apply_comments` 必须显式确认才写盘，批量写回有上限管控，定密和发文签批仍由人负责。这话看似给演示降温，实际是加分项——政务场景里，能说清"AI 不越权"的方案才进得了下一步。

## 复盘三条经验

第一，PoC 的时间要花在结果上而不是环境上，一行安装加一条 healthz，把环境环节压缩到三分钟以内，剩下的时间全给业务效果。第二，演示材料要提前埋好典型问题，让问题清单一眼可读，领导自己就能看出 AI 找得准不准。第三，边界说明要主动讲，别等保密部门来问。

再补一条：准备好升级问题的答案。领导十有八九会追问"能不能全科室推广"，这时候把察元的四档形态一句话摆出来——个人用开源加载项起步，科室共用有服务版，要知识库接桌面版，全单位规模看至臻版，层层递进都有落点。这比一句干巴巴的"可以"有说服力得多，也顺带展示了你对路径的规划而不是头脑发热。

那次会议的结论是"先在两个科室试点"。工具能不能落地，往往就取决于第一次演示的十分钟里，领导看到的到底是炫技还是解决问题的样子。
