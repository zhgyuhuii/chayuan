# 注册表、LaunchAgent、systemd：察元AI文档助手三平台 MCP 常驻方案

AI Agent 办公要落地，一个绕不开的工程问题是：Agent 随时可能被唤起，那 Agent 依赖的本机服务凭什么是"随时在线"的？这个问题不解决，体验就是每次先开终端手动拉服务、再开 AI 工具，多两步就劝退一批用户。「察元AI文档助手」在三个平台上给出了三套常驻方案，这篇按平台逐个说清楚，顺便讲讲为什么这么设计。

## 为什么要常驻，而不是按需拉起

先看架构：察元的 MCP 服务跑在 `http://127.0.0.1:62588/mcp`（Streamable HTTP），Claude Code、Cursor、Codex 这些客户端连这个地址调用 46 个文档工具。另一种常见做法是 stdio 模式，客户端每次自己拉起服务进程——代价是每个客户端各养一个进程、状态不共享、客户端一关服务就没了。常驻 HTTP 服务则是"一个服务，多方共用"，WPS 加载项、多个 AI 工具同时连互不干扰。而常驻的前提，就是开机自启和断线自愈。

## Windows：注册表 HKCU\Run

Windows 上安装脚本把服务写进当前用户的 `HKCU\Run` 注册表项，用户登录即拉起 chayuan-mcp 单文件二进制。注意是 HKCU 不是 HKLM——用户级注册不需要管理员权限审批，也不污染系统全局，卸载跟着用户走。这是办公软件最稳妥的落点。

4.1.2 版在这条线上修了两个实际影响体验的问题：一是 sidecar 全面隐藏启动，以前服务起来会闪一个控制台黑窗，办公场景里看着像出了什么事，现在完全静默，而且关掉窗口不会把服务带停；二是「运行 Spike」掉线自愈，偶发断连不再需要人工干预。装好之后浏览器开 `http://127.0.0.1:62588/healthz` 看到返回 online，就说明自启链条通了。

## macOS：LaunchAgent

macOS 的用户级常驻标准答案是 LaunchAgent，安装脚本用的就是它，配置落在用户目录下，随登录生效，不需要 root。对开发者居多的 Mac 用户来说，这意味着察元的服务和你在 Homebrew 里管理的其他服务是同一个世界的规则，想看状态用系统自带工具就能查。安装还是那一行 curl：

```bash
curl -fsSL https://gitee.com/cloudshd/chayuan-wps-releases/raw/master/scripts/install-wps-skill-chayuan.sh | bash -s -- --fetch
```

## Linux：systemd --user

Linux 桌面和服务器场景走 systemd 的用户实例（`--user`），同样不碰系统级配置。服务跟随用户会话管理，登录即起，这套机制 systemd 原生支持，不需要额外造轮子。服务器上挂 WPS 的场景不多，但 Linux 桌面用户跑 WPS 并不少见，国产信创终端大量就是 Linux 桌面环境，这条路径的完整支持对国产化替代浪潮里的单位是有实际意义的。

## 三条通用规则

平台机制虽然不同，但有三条规则是跨平台一致的。第一，服务只监听 127.0.0.1，信任边界就是本机，无需 Token，远程访问要走代理或改 `CHAYUAN_MCP_PORT` 环境变量自己规划；第二，服务是单文件二进制，不依赖 Node.js，三平台上都没有运行时安装负担；第三，升级就是重跑安装命令，覆盖安装且旧配置保留，4.1.1 之后临时解压目录退出即清理，不会每次残留约 290MB。

顺带交代一个自启失效时的典型表现：AI 工具报 `WPS_AGENT_OFFLINE`，说明 WPS 或加载项没连上服务端。排查顺序照旧从下往上——先浏览器开 `http://127.0.0.1:62588/healthz` 看 online 与否，服务不在就查自启项是否被安全软件或系统策略禁了，服务在而桥不通就重启 WPS 让加载项重连。三个平台这套流程完全一样，运维同事学一次就能管三套系统。

## 接入侧一行命令

服务常驻就位后，客户端接入是分钟级的。Claude Code 一条命令注册：

```bash
claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp
```

Cursor 用户写 `.cursor/mcp.json`，Codex 用户在 `~/.codex/config.toml` 里加三行，都是填同一个 URL，这里不展开。接好之后建议拿一句提示词立刻试水，比如"帮我检查文档中的错别字，用批注标出原文和建议改法"，批注能不能钉到原文位置，一测便知链路全通。

最后照例说边界：常驻服务管的是"随时能干"，不包办"干得对"——批量写回单次上限 200 条操作、写批注必须显式确认，这些闸门就是为自动化留的安全垫，重大修改前还是该人过一遍 preview。让服务像水电一样存在，让每一次落笔前有人工确认，这才是 Agent 进办公室该有的样子。
