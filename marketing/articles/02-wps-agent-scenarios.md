标题：用 Claude Code、OpenClaw 审 WPS 文件：预览、批注、改正文

概要：说明 Claude Code、OpenClaw、Codex 等如何对本机 WPS 做自动审查，能查错别字、标点、公文体例和表格，以及确认写回卡在哪一步。面向编校与办公读者。

平台建议：公众号、办公软件专栏、单位内网知识库。本稿少命令、多说法与批注截图，突出「智能体审文件」而不是空谈概念。

正文：

自动审查这两个字，容易让人以为按一下就改完全文。用 Claude Code、OpenClaw 或 Codex 审 WPS 文件时，更稳的做法是把「查出问题」和「改动文件」拆开：智能体先给出问题清单，你再决定写成批注还是改正正文。察元在本机把文档工具暴露给这些客户端，加载项里也能点「拼写与语法检查」，两边是同一类能力。下面按审查对象、写回方式、场景说法、人工把关来写，并留下贴图位置。

一、智能体自动审查到底审查什么

结构化校对面向的是相对可核实的问题：错别字、同音别字、明显病句、标点混用、固定搭配错误等。它适合作为长文初筛，不适合当成终审盖章。产品里还有纠正拼写语法一类更偏「整段改写」的路径，和「检查问题列表再批注」不是同一条。编校时建议默认走检查加批注，需要统一用词时再走确认后的替换。

对 Claude Code、OpenClaw、Codex 下指令时，你不必背工具名，但要记住结果形态：一份可逐条定位的问题列表，每条尽量带原文、建议和位置。加载项侧入口包括拼写与语法检查、文本分析里的纠正拼写和语法、以及自定义助手，适合不想打开外部客户端时使用。

二、三条写回路：只预览、写批注、改正文

第一条路，只预览。说法可以是：先跑一遍校对，汇总问题列表，不要改正文，也不要写批注。适合你还没决定这稿能不能动，或需要先拿列表开会。

第二条路，写批注。说法：确认写批注，批注里写清原文和建议改法，尽量钉在具体文字上。这是公文和会签场景最常用的路。批注留在 WPS 里，别人还能继续改、还能回复批注。

第三条路，改正文。说法：确认替换，或按清单直接改正。务必先有预览清单。没有确认就改字，后续追责时说不清是人改的还是机器改的。

【贴图3：同一段文字，左侧仅问题列表，中间批注气泡，右侧已替换正文，三栏对比。】

技术上，未确认的写操作常常只返回预览；写批注、脱密应用等会明确要求确认。把这个习惯写进你的开场白，比依赖某个客户端的默认安全策略更稳。

三、错别字与同音字：审查里最稳的一层

可直接用的说法：

帮我检查文档中的错别字，用批注标出原文和建议改法。

只检查当前选区的错别字，写成批注。

排查同音别字，例如的地得、象像、做作，批注说明理由。

检查成语是否写错或误用，批注纠正。

核对文中人名、地名、单位名是否前后一致，不一致处批注。

这些任务对模型要求相对直观，也容易人工抽查。抽查时不要只看对话总结「已检查完毕」，要点开几条批注，看锚点是否落在错字上。

四、标点、序号与公文体例

标点单独成任务往往比和错别字捆在一起更清楚：

帮我检查标点符号是否正确，包括中英文标点混用、引号和书名号是否配对，用批注标出。

把误用的英文逗号句号改成中文标点，先预览。

检查标题和条款序号层级是否混乱，批注指出。

按公文习惯检查标题、主送、落款、附件说明是否缺项。

体例类问题有时不是「对错」而是「体例偏好」，批注比直接改更适合讨论。合同类可以另开任务：检查是否缺主体、金额、期限、违约责任，列风险清单批注。这已经接近业务审查，模型可能漏项，必须人工复核。

五、病句、逻辑与「正确性总检」

可以说：

帮我检查病句、成分残缺、搭配不当，用批注给出改法。

检查文中数据、时间、称谓是否前后矛盾。

核对数表与正文数字是否一致。

帮我核对这篇文章的正确性：错别字、标点、语法、前后矛盾一并查，结果用批注。

正确性总检适合定稿前一夜的粗筛。问题一多，建议要求智能体按严重、一般、建议三级汇总，你先处理严重项。逻辑漏洞、论证跳跃类输出主观性更强，把它当提示，不当判决。

六、表格：自动审查里最容易翻车的地方

表格单元格里的错字，批注一旦挂到整格或行尾，审稿人会对产品失去信任。下指令时写死：

重点检查表格单元格里的错别字，批注必须钉在具体错字上，不要挂到整格。

还可以让它标空单元格、核同一列单位是否一致，或把表意概括成一段说明插到表前。插入类动作同样先预览。

人工验收表格审查时，随机点开三处批注：错字是否高亮正确、建议是否合理、有没有整格误挂。任一失败，先别批量确认替换。

七、Claude Code、OpenClaw、Codex 与加载项怎么选

不离开 WPS、操作路径短：用加载项自带检查和写回动作条。要组合多步、多文档、边聊边改，或已经泡在 Claude Code、OpenClaw、Codex 里办公：通过 chayuan-wps-mcp 让智能体审当前文件。三条客户端加加载项，背后都是当前文档和本机服务，不是两套互相打架的引擎。助手页若开启文档智能体，也可能走同一本机 MCP。

配置前提仍然是：WPS 打开、加载项在线、本机 62588 健康、校对模型已配置。模型可以是内网兼容端点。没配模型时，审查入口会明确失败，这比默默给出空结果更好。对 OpenClaw、Codex 下的中文指令，与对 Claude Code 可以相同，不必为每个壳子重写一套话术。

八、多文档与交叉检查

打开目录下几份相关稿，交叉检查错别字与术语是否一致。先让智能体打开指定路径并确认活动文档，再开校对。例如：打开某份 docx，确认是活动文档后，做错别字批注，并另存一份带已校对后缀的副本。串行处理两份文件时，每份都重复「预览、确认、写回」，不要假设它记得上一份的确认。

九、敏感信息与脱密：审查的另一条线

可以说：检查是否像身份证号、手机号、银行卡号这类字段，用批注标出。这只是辅助扫描，不是定密结论。脱密预览、带确认和密码的脱密应用，走产品既有流程，对话里不要省略确认。涉密岗位请按单位制度执行，工具不能代替审批。

十、一段可反复使用的审查开场白

你是 WPS 文档校对助手，通过 chayuan-wps-mcp 操作当前文档。先做校对预览，检查错别字、标点和明显病句。汇总问题列表给我确认。我回复确认写批注后，再写成 WPS 批注，钉在具体文字上，尤其是表格。不要擅自改正文，除非我明确说确认替换。最后给我一份问题分级摘要。

把这段存成客户端的项目说明或 Hermes、OpenClaw 的常用任务模板，比每次现场发挥稳定。

十一、预期管理：什么叫「审查完了」

长文会分段处理，耗时与字数、模型速度有关。智能体口头保证查完，不等于每条批注都落对。你的完成标准建议写成：严重问题已处理或已批注、抽查锚点正确、需要改字的条目已人工确认。自动审查提高的是初筛效率，不是取消核稿岗。

也要承认边界。复杂版式、文本框、扫描件转成的假文本、纯图片文字，能力会下降。极个别生僻专名，模型可能误报。把误报当成可关闭的批注即可，不必因此否定整条链路。

十二、一套可落地的「自动审查作业流程」

下面这套流程适合科室里固定下来，避免每人一套说法。

收件：作者交稿，编辑另存为「文件名-送审」副本，打开 WPS。  
初筛：运行拼写与语法检查，或让已接通的智能体做校对预览。只要列表，不写回。  
分流：编辑把问题分成必须改、建议改、误报。误报直接忽略或删批注。  
落笔：必须改的条目，优先确认写批注，退回作者；若编辑有改稿权且条目无争议，再按条确认替换。  
复核：作者或二审只看批注窗格与修订，不再让模型「再全改一遍」掩盖痕迹。  
归档：保留带批注的中间稿一份，定稿另存。需要统计时，可让智能体按严重级别再出一页摘要插入文首，插入前同样预览。

十三、不同文种的审查侧重点

汇报材料：错别字、数据前后矛盾、序号层级、口头语是否过重。  
制度办法：用语是否前后一致、条款序号、禁止性表述是否完整，慎用「直接改正文」。  
合同协议：主体、金额、期限、违约责任、管辖，输出当风险提示，法务仍要看。  
讲话稿：同音词、姓名职务、敏感提法，批注后人工定夺。  
表格统计：单位列、空单元格、表内错字锚点，表意概括可单独要一段说明。

同一套工具，文种不同，指令要换。把文种写进第一句，例如「这是制度征求意见稿，只批注不改字」，模型越界的概率会下降。

十四、和「AI 润色」按钮的区别

市面上很多一键润色，输出是整段新文本，好看，但难审计。察元自动审查强调结构化问题列表和批注落点，牺牲一点「焕然一新」的感觉，换来可核对。若你确实需要润色，单独立任务，并要求改动处批注说明，不要和错别字检查混成一次点击。混做的结果往往是：错字没钉住，文风倒大变，审稿人更累。

十五、给公众号编辑的发稿提示

标题已点明 Claude Code、OpenClaw 与「审 WPS 文件」。正文贴图优先用批注特写和三栏对比，少贴大段配置代码。若平台要导流到安装包，文末加三句：安装察元、打开 WPS、按贵单位要求配置模型。详细接通 Claude Code、Codex 的步骤链到技术向文章。删节时先砍多文档与脱密，保留错别字、表格与三条写回路。

适用读者：要用 Claude Code、OpenClaw 或同类智能体审查 WPS 公文、制度、合同，又必须留下人工确认痕迹的人。
