标题：OpenClaw、Codex、Hermes 如何实现 WPS 文件自动审查

概要：从安装察元、配置 MCP，到用 OpenClaw、Codex、Hermes、Claude Code 对 docx 做自动审查、批注与确认替换。强调人在回路，可作培训稿。

平台建议：Agent 社群、少数派类工具频道、内部培训手册。本稿标题和正文都围绕「智能体如何审文件」，命令与界面各留截图位。

正文：

OpenClaw、Codex、Hermes、Claude Code 都能聊天生成文字，但要对着本机 WPS 文件做自动审查，还差一截：智能体得能打开文档、分段读、写批注、在你确认后改字。察元补的就是这截。安装加载项后，本机出现标准 MCP 服务，上述客户端连上本地地址，审查指令才会落在真正的 docx 上，而不是落在一段粘贴文本上。下面按安装、接通、人机分工、审查场景、排错写完，方便直接当培训稿用。

一、你要装的是什么

装的是跑在 WPS 文字里的察元加载项，以及随包带来的本机 MCP 服务。服务地址固定为：

http://127.0.0.1:62588/mcp

健康检查：

http://127.0.0.1:62588/healthz

服务名在各客户端里写成 chayuan-wps-mcp。不要求 Token。默认只监听本机，适合怕稿件外传、或本来就在内网办公的环境。4.0 起安装包内嵌 sidecar 二进制，并注册开机自启，一般不必再单独装 Node。

二、安装后五分钟验收

第一步，打开 WPS 文字，随便建一个测试文档，打几段带故意错字的句子。第二步，浏览器访问 healthz，确认在线。第三步，打开察元设置里的 MCP 服务页，刷新状态，必要时点启动本机服务。第四步，在察元里配置好你要用的模型（内网兼容端点或合规的云端）。第五步，用加载项自带的拼写与语法检查跑一下测试稿，看批注能否出现。五步里任一步失败，先不要配 OpenClaw，否则后面分不清是 Agent 问题还是本机服务问题。

【贴图3：healthz 返回在线。】

【贴图4：测试稿上成功落下的第一条批注。】

三、把 OpenClaw 接到 WPS

在 OpenClaw 里新建 MCP 服务。类型选 HTTP 或 Streamable HTTP。URL 填本机 MCP 地址。名称填 chayuan-wps-mcp。不要选 stdio，不要填一长串启动命令，也不要为了「安全」随手填一个假 Token（当前本机服务按设计不走 Token）。保存后做连通测试，能列出文档打开、读取、批注、校对等工具即成功。

【贴图5：OpenClaw 新建 MCP 的表单，类型与 URL 清晰可见。】

【贴图6：连通成功后的工具列表局部。】

第一次任务建议极短：读取当前文档标题和前两段，不要修改。成功后再上审查类任务。OpenClaw 若支持任务模板，把文末开场白存成默认说明，减少每次重复粘贴。

四、把 Hermes 接到 WPS

Hermes 同样走 HTTP MCP。界面文案可能叫 MCP Server、Tools、连接器，原则相同：URL、服务名、无 Token。配好后用同一句冒烟指令验证。若 Hermes 与 OpenClaw 同机使用，注意不要重复拉起多份冲突的 sidecar；正常应是共用本机 62588。客户端可以有多个，服务只需一份。

Claude Code、Cursor、Codex 的配置更偏文件或命令行，详细步骤适合放在技术向文章。对桌面 Agent 用户，记住「同一个本地 URL」即可。需要时再查对应客户端文档。

五、人在回路：Human 不是口号，是操作顺序

英文里常写 human in the loop。落到 WPS 里就三句话：机器提议，人点头，再动文件。对应操作顺序是预览、确认写批注、确认替换。你可以在对话里扮演这个 Human，也可以让同事在 WPS 批注里继续当 Human。不要把自动审查理解成无人值守印发。

推荐固定开场白：

你通过 chayuan-wps-mcp 操作当前 WPS 文档。先预览，不要改正文。列出问题后等我确认。我回复确认写批注后才写批注，钉在具体文字上。没有确认替换，禁止改正文。

六、日常场景一：文件自动审查与批注

这是 OpenClaw、Codex、Hermes 接通后的主场景。说法示例：

对当前 WPS 文件做自动审查，检查错别字和标点，先给问题列表。

确认写批注。

表格多的再说：批注钉在单元格具体错字上。

需要改字时：按第 3、5、7 条确认替换，其余保持批注。

这种「按条确认」比「全部自动改」更适合制度稿。Codex 与 OpenClaw、Claude Code 可以共用上述说法。审查细项（同音字、成语、公文缺项、合同要素）见编校向专文。

【贴图10：OpenClaw 或 Codex 下达审查指令与 WPS 批注窗格同屏。】

七、日常场景二：翻译、润色、摘要

分段英译：翻译成英文，并把译文插到每一段后面。先预览第一段样例，我确认风格后再全部执行。

只想看建议：译文写在批注里，不要改正文。

润色：不改变原意，改动处用批注说明。

摘要：生成三百字以内摘要，先预览，我点头再插入文首。

这些任务的分歧点是「插在哪里、是否覆盖原文」。指令写清，返工少。润色类务必抽查是否擅改数据、责任主体、时间节点。

八、日常场景三：术语统一与批量替换

找出文中所有某词，预览命中位置，确认后再改成另一词。合同里把旧公司名换成新公司名，用这条比全文重写安全。插入「已审」一类标记时，也先预览。批量写回有上限意识：一次塞太多操作，不如分批确认。

九、日常场景四：敏感信息与知识库对照

检查疑似身份证号、手机号并批注。对照知识库制度检查是否违规表述，引用条文批注。后者依赖你在察元侧已配置知识库。没有知识库时，不要指望它「凭空引用内部红头文件」。脱密相关动作带密码与确认，按产品流程走，不要在群里分享密码。

十、从安装到使用的一张清单（可打印）

1 安装察元，打开 WPS，确认加载项可见。  
2 访问 healthz，确认本机服务在线。  
3 配置校对与对话所用模型。  
4 用加载项自测一条批注。  
5 在 OpenClaw 或 Hermes 添加 chayuan-wps-mcp。  
6 冒烟：只读标题与前两段。  
7 审查：先预览，再确认写批注。  
8 抽查锚点，尤其是表格。  
9 需要改字再确认替换。  
10 定稿前人工通读严重项。

十一、为什么值得接桌面智能体，而不是只依赖网页上传

网页上传适合偶发、不怕文件出境的场景。本机 MCP 适合高频、要批注落点、要内网模型、要和现有 Agent 工作流合并的场景。OpenClaw、Hermes 本来就在调度别的工具，加上 WPS 只是多一个本地工具源。Claude Code 用户则多了「在终端里改公文」的可能。三种客户端差异在交互壳，落到文档上的动作集合一致。

也要讲边界。它不是自动排版引擎，不是司法鉴定，不是定密机关。扫描件、复杂文本框、纯图文字会削弱效果。模型会误报、会漏报。Human 的价值就是拦住这些问题，而不是给自动流程当摆设。

十二、排错时先问这四句

WPS 打开了吗？healthz 在线吗？客户端服务名和 URL 抄对了吗？模型配置好了吗？  
仍失败再看具体错误：Agent 离线、文档过大要分块、需要确认、定位失败、授权额度等。设置页若有 Spike 或自检，留给信息技术同事一张截图，比口头描述「连不上」有用。

十三、半小时培训可以怎么讲

若你要把本稿当成内训大纲，时间可以这样切。前五分钟讲清楚三块组件：WPS、察元加载项、本机 MCP。中间十分钟现场安装或演示已装环境，打开 healthz，在 OpenClaw 里点通服务。再十分钟做只读与批注两个练习。最后五分钟讲人在回路和不能做什么。培训结束不要求人人会配 Claude Code，只要求人人会说「先预览，再确认写批注」。

【贴图17：培训投影封面，标题用本稿标题即可。】

十四、和「让助手直接生成一篇新公文」有何不同

生成新稿，智能体是作者。指挥 WPS 审查与写回，智能体是编辑助理。前者怕的是空话和事实错误，后者怕的是锚点漂移和未经确认的覆盖。察元这条链路主打后者。你仍可以用同一客户端先起草、再打开 WPS 精修，但心理模型要切换：起草阶段看文采，写回阶段看落点与确认。

十五、客户端怎么选，不必纠结

已经在用 OpenClaw，就在 OpenClaw 里做文件自动审查。已经在用 Codex 或 Hermes，就在对应客户端里配同一个 chayuan-wps-mcp。开发同学更熟 Claude Code，用命令行也行。不必为了 WPS 再换一套聊天壳。真正要统一的是服务名、本地 URL、以及科室认可的确认话术。话术不统一，就会出现有人默认直接改正文、有人只敢看列表的混乱。

十六、失败案例（写进培训反而加分）

案例一：没开 WPS 就让 Agent 校对，连续报离线，误以为插件坏了。处理：先开 WPS。  
案例二：服务名写成了别的，工具列表为空。处理：改成 chayuan-wps-mcp。  
案例三：一句话「帮我改完美」，模型大段替换，领导要旧表述。处理：开场白禁止未确认替换，重要稿走批注。  
案例四：表格批注挂整格，业务部门不信。处理：指令写死钉在错字上，并抽查。  
案例五：公共电脑上配了云端密钥，人走了密钥还在。处理：公共机用内网模型或系统级密钥托管，不写个人密钥。

十七、一周试用节奏（怕一次吃不下的人）

第一天只做安装与 healthz，不配任何外部 Agent。  
第二天在加载项里完成一次批注，确认模型可用。  
第三天接通 OpenClaw 或 Hermes，只做只读。  
第四天做错别字预览加确认写批注。  
第五天加一个自己的真实小场景，比如术语统一或段后译文预览。  
周末回头看批注有没有落错、有没有误替换，把开场白改到自己顺口为止。

这样比半天塞完所有功能更不容易砸正式稿。试用期正式稿一律另存副本，这条写进科室公约也值。若第三天只读都失败，先回到加载项自测，不要继续加场景，免得问题叠在一起没法拆。

十八、三篇网文怎么错峰发

三篇标题都围绕「智能体如何做 WPS 文件自动审查」：技术平台发 Claude Code、Codex 接通篇；办公平台发审查对象与批注规范篇；Agent 社群发本稿，突出 OpenClaw、Codex、Hermes。贴图素材尽量复用：healthz、批注特写、MCP 配置页各拍一套，换平台只换封面和开头两段即可。

适用读者：已经在用 OpenClaw、Codex 或 Hermes，希望它们直接对本机 WPS 文件做自动审查，并且接受「先预览再确认」节奏的人。
