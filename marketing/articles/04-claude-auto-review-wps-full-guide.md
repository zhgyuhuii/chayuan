标题：用 Claude Code 对本机 WPS 文件做自动审查：从下载安装到提示词与结果

概要：按察元 AI 文档助手 v4.0 实际能力，写清下载安装、配置模型、加载项内自检、给 Claude Code 安装 MCP、验证是否接通、常用提示词，以及预览与批注结果长什么样。可直接当操作手册用。

正文：

要用 Claude Code 自动审查本机 WPS 里的公文或合同，本质上是三件事串起来。第一，电脑上装好察元加载项，WPS 能打开文档。第二，在察元里配好校对用的模型，本机检查能跑通。第三，把 Claude Code 接到本机 MCP 服务 chayuan-wps-mcp，用中文指令走「先预览、再确认写批注」。下面按真实产品路径逐步写，需要配图的地方留出贴图位。

零、先建立正确预期

Claude Code 负责听懂你的话、拆步骤、调用工具。察元负责在 WPS 里读段落、定位原文、写批注、在确认后替换。本机 MCP 地址是：

http://127.0.0.1:62588/mcp

健康检查是：

http://127.0.0.1:62588/healthz

服务名建议写成 chayuan-wps-mcp。默认只监听本机，不需要 Token。文档审查不是「一句话改完美」，稳妥顺序始终是预览问题列表、人工确认、再写批注或改正文。涉密与定稿以人工和单位制度为准。

按操作系统下载对应安装包。v4.0 起常见文件名形态为：

二、安装察元并确认加载项出现

Windows：双击 exe，按向导完成。装完打开 WPS 文字，看功能区或任务窗格是否出现察元相关入口。若没有，到 WPS 的加载项管理中确认已启用。

macOS：打开 pkg 完成安装。按系统提示处理权限。打开 WPS 文字，确认察元入口可见。

Linux：用 deb 安装后打开 WPS 文字，同样确认加载项在线。桌面环境差异较大，以实际能打开任务窗格为准。

装完务必真正打开一次 WPS。只装包不启动，Agent 往往未注册，后面 Claude Code 会报 WPS 离线一类错误。

三、确认本机 MCP 服务已起来

浏览器访问：

http://127.0.0.1:62588/healthz

期望看到在线或 online。再记住 MCP 入口：

http://127.0.0.1:62588/mcp

打开察元设置里的 MCP 服务页，刷新状态。若显示未启动，按界面提示启动本机服务。有 Spike 或自检的版本，可跑一遍，确认 sidecar、Agent、活动文档相关状态正常。

连不上时按顺序查：WPS 是否打开；察元是否加载；62588 是否被占用；是否误把地址写成了局域网 IP 却未做代理。默认安装只绑 127.0.0.1。

四、配置模型（自动审查能不能跑，卡在这一步的很多）

MCP 通了，不等于校对一定成功。拼写与语法检查、结构化自动审查依赖察元设置里的对话模型或校对相关模型。可走两类路：

离线或内网：Ollama、LM Studio、Xinference、OneAPI、New API 等 OpenAI 兼容端点。在设置中填基础 URL、密钥（若有）、选用对话模型。

云端：按单位合规要求配置可用供应商与 API 密钥。密钥按人按岗最小授权，公共电脑慎用个人密钥。

操作建议：

1 打开察元设置，进入模型与供应商相关页。  
2 启用至少一家供应商，保存密钥与基础 URL。  
3 选定默认对话模型，确认类型是对话，不要误选纯嵌入或图像模型当校对模型。  
4 用一小段测试文字，在加载项内先跑「拼写与语法检查」，确认能出问题列表或批注。

这一步通过后，再让 Claude Code 调校对，排错时才能分清是「模型没配」还是「MCP 没连上」。

五、加载项内先做一次检查（不经过 Claude）

新建或打开一份测试稿，故意留下两三个错别字、一处中英文标点混用。在察元 AI 助手或文本分析入口执行拼写与语法检查。观察：

是否出现问题列表；  
批注是否钉在错字附近；  
表格里的错字是否挂到具体文字而不是整格。

也可以只用加载项完成日常审查，不必强行上 Claude。Claude 的价值在于多步编排、多文档、边聊边审。加载项自检通过，说明本机审查链路健康。

六、安装 Claude Code（若尚未安装）

Claude Code 是 Anthropic 的终端向编码智能体，支持 Streamable HTTP MCP。安装与登录以其官方文档为准：

https://code.claude.com/docs/en/mcp

本机需能运行 claude 命令。登录账号、权限与计费按 Anthropic 与你们单位规定处理。本文不展开 Claude 本身的安装细节，只要求终端里执行 claude 有响应。

【贴图13：终端中 claude --version 或帮助信息（可打码账号）。】

七、给 Claude Code 安装察元 MCP 服务

确认 WPS 已打开、healthz 在线后，在终端执行：

claude mcp add --transport http chayuan-wps-mcp http://127.0.0.1:62588/mcp

也可在项目根或用户级 .mcp.json 写入：

{
  "mcpServers": {
    "chayuan-wps-mcp": { "url": "http://127.0.0.1:62588/mcp" }
  }
}

说明：

服务名用 chayuan-wps-mcp，与文档一致；  
transport 用 http（streamable-http 为同义别名）；  
不要配成 stdio 去启动某条本地命令；  
不需要 Token。

保存后重启 Claude Code，或按客户端方式刷新 MCP 列表。

八、验证是否安装成功（建议按四级验收）

第一级，列表可见。  
在 Claude Code 的 MCP 列表中能看到 chayuan-wps-mcp，状态为已连接或可用。

第二级，工具可见。  
展开后应能看到与文档相关的工具，例如状态查询、打开文档、读段落或分块、定位、替换、批注、校对预览、写成批注等（具体名称以当前版本工具列表为准，大约二十余个文档智能体工具）。

第三级，只读冒烟。  
WPS 中打开测试稿，对 Claude Code 说：

通过 chayuan-wps-mcp 告诉我当前活动文档的文件名和大概字数，不要改正文，不要写批注。

若回报与标题栏一致，说明读写桥通了。

第四级，审查预览冒烟。  
再说：

对当前文档做校对预览，列出错别字和标点问题，不要写批注，不要改正文。

若返回问题列表，说明校对链路通了。若报模型未配置，回到第四节。若报 WPS 离线，回到第二、三节。

可选：用 MCP Inspector 独立验证，不依赖 IDE：

npx @modelcontextprotocol/inspector

连接 http://127.0.0.1:62588/mcp 后查看工具列表。

九、完整自动审查流程（推荐日常用法）

1 在 WPS 打开待审文件，重要稿先另存副本。  
2 确认 healthz 在线、Claude Code 已挂上 chayuan-wps-mcp。  
3 粘贴开场白（见下一节），先只要预览。  
4 人工看问题列表，标出误报与必须改。  
5 回复「确认写批注」。  
6 打开 WPS 批注窗格，抽查锚点，尤其是表格。  
7 需要改字的条目，再「确认替换」或按条确认。  
8 另存为「原名-已校对」一类文件名。

不要跳过预览直接「全部改完美」。写批注、替换、脱密类写操作在未确认时，通常会要求确认或只返回预览，这是设计，不是故障。

十、提示词（可直接复制）

10.1 固定开场白

你通过 chayuan-wps-mcp 对当前 WPS 文件做自动审查。先做校对预览，列出错别字、标点和明显病句。等我回复确认写批注后，再写批注，且尽量钉在具体文字上，尤其是表格。没有我说确认替换，不要改正文。最后按严重、一般、建议三级给我摘要。

10.2 错别字与同音字

帮我检查文档中的错别字，用批注标出原文和建议改法。

只检查当前选区的错别字，先预览不要写批注。

排查同音别字，例如的地得、象像、做作，批注说明理由。

检查成语是否写错或误用，批注纠正。

10.3 标点与公文体例

帮我检查标点符号是否正确，包括中英文标点混用、引号和书名号配对，用批注标出。

按公文习惯检查标题、主送、落款、附件说明是否缺项，只批注不改字。

检查标题和条款序号层级是否混乱，批注指出。

10.4 表格

重点检查表格单元格里的错别字，批注必须钉在具体错字上，不要挂到整格。

10.5 正确性总检

帮我核对这篇文章的正确性：错别字、标点、语法、前后矛盾一并查，先预览列表，我确认后再写批注。

10.6 多文档

打开路径某某.docx，确认它是当前活动文档后，做错别字校对预览；我确认写批注后再写批注，并另存为某某-已校对.docx。

10.7 确认写回用语

确认写批注。

确认替换。

按第 2、4、6 条确认替换，其余只保留批注。

十一、结果长什么样（如何判断「成功了」）

成功的预览结果：对话里出现条目化问题，含原文片段与建议，而不是一句「已检查完毕」却无细节。

成功的批注结果：WPS 批注窗格有多条批注，点开后高亮落在具体错字或词组上；表格内不整格误挂。

成功的替换结果：仅你确认过的条目正文变化，其余不动；可用另存对比。

不完整或失败的信号：

healthz 不在线；  
Claude 看不到 chayuan-wps-mcp；  
回报 WPS_AGENT_OFFLINE 或类似离线；  
MODEL_NOT_CONFIGURED；  
CONFIRMATION_REQUIRED（需要你补确认）；  
DOCUMENT_TOO_LARGE（应改分块读取，不要一次拉全文）；  
批注落点漂到邻句或整格。

验收标准建议写成：严重问题已处理或已批注、抽查不少于三处锚点正确、未发生未经确认的大段替换。

十二、加载项审查与 Claude 审查怎么配合

日常短文、单次检查：加载项内拼写与语法检查更快。  
长文分块、多文档串行、要边讨论边改：用 Claude Code。  
两者共用本机 sidecar 与当前文档，不是两套互相打架的引擎。助手页若开启文档智能体，也可能走同一 MCP。

十三、排错速查表

现象：MCP 列表没有服务。  
处理：检查 .mcp.json 或重新执行 claude mcp add，服务名与 URL 是否抄错。

现象：有服务但工具调用失败、Agent 离线。  
处理：打开 WPS，确认加载项加载，刷新 healthz。

现象：能读文档，校对报模型未配置。  
处理：回察元设置配对话模型，并用加载项自测一次。

现象：只要预览却被改了正文。  
处理：开场白写死禁止未确认替换；重要稿先另存。

现象：表格批注不准。  
处理：指令写死钉在单元格具体错字上；不通过则先不要确认替换。

现象：长文超时或过大。  
处理：让 Claude 按块审查，不要一次 document 全文硬拉。

十四、安全与边界（写进科室约定也值）

默认端口不面向公网。不要随手把 62588 映射到互联网。  
公共电脑注意模型密钥残留。  
自动审查是初筛，不是司法鉴定，不是定密结论。  
扫描件、纯图文字、复杂文本框能力会下降。  
Claude Code 侧的对话内容是否出境，取决于 Claude 账号与网络策略；WPS 正文经 MCP 留在本机工具调用链路，但你仍要按单位数据规定使用。

十五、一页核对清单（可打印）

1 下载并安装察元，打开 WPS，入口可见。  
2 healthz 返回在线。  
3 配置模型，加载项内检查能出批注。  
4 安装 Claude Code 并登录可用。  
5 claude mcp add 注册 chayuan-wps-mcp。  
6 MCP 列表可见，工具可展开。  
7 只读冒烟：文件名与字数正确。  
8 校对预览冒烟：有问题列表。  
9 确认写批注，抽查锚点。  
10 需要时确认替换，另存已校对副本。

十六、结语

按本文做完，你得到的不是「又一个聊天窗口」，而是 Claude Code 能直接审本机 WPS 文件的闭环：下载安装察元、配好模型、本机检查过关、给 Claude 装上 MCP、四级验证通过，再用固定提示词走预览与批注。结果以 WPS 里的批注和可控替换为准，不以智能体口头保证为准。把贴图按编号补齐后，即可作为对外教程或内部操作手册使用。

适用读者：已安装或准备安装 Claude Code，需要对本机 WPS 公文、制度、合同做自动审查，并希望步骤可复核的人。
