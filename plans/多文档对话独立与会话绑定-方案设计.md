# 多文档对话独立与会话-文档绑定 方案设计（v1 送审稿）

## 0. 需求

同时打开两个（或多个）PPT/表格/文字文档时：
1. 每个文档有**独立对话**（各自历史、各自进行中的回合）
2. 对话与文档**强绑定**：A 文档的对话绝不出现在 B 文档
3. 用户始终清楚"当前面板在服务哪个文档"

## 1. 现状与根因（代码级实证）

架构事实：
- WPS 单进程多文档；`ActivePresentation/ActiveWorkbook/ActiveDocument` 随激活窗口正确切换（实测 ppt-A↔ppt-B 切换返回正确）
- AI 面板是**应用级单例**（CreateTaskPane 同名返回同一实例；WPS 官方文档确认非文档级）
- 已有按文档分域的会话存储：scopeKey = `doc_${docLinkId}` / `path_${fullName}` / `name_${name}`，历史存 PluginStorage 键 `ai_chat_history:${scopeKey}`
- 已有切换检测：WindowActivate 事件 + 3s 轮询 → syncHistoryScopeWithActiveDocument()（保存旧→加载新）
- 已有执行侧绑定：chat_turn 携 docId，写操作前 `__expectedDocId` 校验（DOC_SWITCHED 拦截）

已定位的 4 个缺陷：

| # | 缺陷 | 证据 | 后果 |
|---|---|---|---|
| D1 | **WPP 无稳定文档ID**：`doc.Variables` 是 WPS 文字独有；Presentation 对象无该集合 → scopeKey 退化到 `path_`/`name_` | readDocumentVariable 返回 '' 的 fallback 路径 | 未保存的两个"演示文稿1"同名撞车；另存为后历史"丢失"（换了 scopeKey） |
| D2 | **面板归属不可见**：单例面板没有任何"当前服务哪个文档"的 UI 指示 | 组件无文档上下文展示 | 用户在 B 文档旁看到 A 的对话却不知原因 |
| D3 | **切档静默切换会话**：WindowActivate/轮询切 scope 是"隐式跟随"，用户点面板前 Active 已切走（如点 B 窗口标题栏再看面板） | sync 逻辑无用户确认 | 感知为"对话串台"（实际是会话被自动切到 B） |
| D4 | **浮窗模式下 3s 轮询是唯一保障**：ShowDialog 浮窗不随文档窗口激活获得事件，ApiEvent 注册可能静默失败 | 代码注释自述"安全网轮询" | 切档后最长 3s 内发送会落入旧文档会话 |

## 2. 方案设计

### 2.1 核心决策：单面板 + 会话路由中枢（方案 A）

不采用"每文档一个面板"（方案 B）：WPS taskpane 可按不同 name 多开（社区做法），但与现有单实例锁、形态记忆、远程回合路由、LLM 串行锁全部冲突，改造面 >5 文件且引入 N 份 webview 内存（每 PPT 一个 CEF 实例）。

采用 **Copilot 模式**（Office.js 生态标准形态）：单面板作为"多会话路由器"，会话与文档双向钉死。

### 2.2 四项修复

**F1 稳定文档ID（治 D1）**——三级指纹，全宿主可用：
```
scopeId = DocumentVariable(文字) 
       > Presentation.CustomDocumentProperties? (WPP 尝试)
       > 内容指纹: FullName + 保存时间戳(SavedTime/LastSaveTime) + 字节数(FileSize)
       > FullName
```
- 内容指纹解决"未保存同名文档"：新建未保存文档 FullName=''，用 `unsaved_${进程内自增}_${首次创建时刻}` 常驻内存映射
- 另存为时指纹随 FullName 变化 → 迁移旧会话到新 scopeKey（一次 PluginStorage 键重命名），历史不丢

**F2 文档上下文胶囊（治 D2）**——面板输入框上方常驻：
```
[📄 e2e-wpp2.pptx ▾]  ← 当前绑定文档；点击下拉列出全部打开文档及其未读回合数
```
- 下拉切文档 = 显式切换会话（带确认，若旧会话有进行中回合）
- 面板标题同步：`察元AI · e2e-wpp2.pptx`

**F3 显式跟随 + 发送时快照（治 D3/D4）**：
- 发送瞬间快照 `{scopeKey, docId, fullName}` 钉进该回合（turn 发起后切文档不影响该回合的归属与写保护目标）
- 隐式跟随改为"跟随+可回弹"：切档后面板顶部出现 5s 撕贴条「已切换到 B.pptx 的对话 [撤销]」
- WindowActivate 处理器里同步预读 Active 对象指纹（消除 3s 窗口）：事件 → 立即 resolve → 变更即切

**F4 回合归属回写（防串台最后闸门）**：
- 回合终态消息带 `mcpRemoteScopeKey`（已有）→ 渲染层校验：消息 scope ≠ 当前面板 scope 时**不渲染进当前视图**，转入对应文档的未读计数（F2 胶囊红点）
- 历史持久化按消息自带 scope 分库写入，而非"当前面板 scope"（现状缺陷：终态合并写的是当前面板 scope）

### 2.3 数据流（修复后）

```
用户在 B.pptx 旁的面板输入 →
  发送时快照 scope(B指纹) →
  chat_turn{scopeKey:B, docId:B, expectDocId:B} →
  基座执行(写操作钉B, 切C文档则DOC_SWITCHED拦截) →
  终态消息{scope:B} →
  渲染层: 当前面板=B? 渲染 : B胶囊+1 →
  持久化: history[B] ← 消息
```

### 2.4 兼容与迁移
- 旧 `doc_/path_/name_` scopeKey 会话：启动时按新指纹规则做一次性映射迁移（保留90天）
- PluginStorage 键格式不变（前缀+scopeKey），仅 scopeKey 生成规则升级
- 单实例锁/形态记忆/LLM 串行锁零改动

### 2.5 验收用例
1. 开 PPT-A、PPT-B → A 旁对话"给第2页加标题X" → 切 B → B 对话为空（非 A 的）
2. A 生成中（流式中）切到 B 发新指令 → A 回合继续、结果落 A；B 回合独立执行
3. 两个未保存的"演示文稿1" → 各自对话互不可见
4. A 另存为 A2.pptx → 历史跟随迁移，不丢失
5. 面板胶囊正确显示当前文档；下拉可切换且有未读红点

## 3. 双模型审核记录（2026-10-04）

审核方：qwen3.8-max（架构主审）+ qwen3.8-flash（实现层交叉复核）。
注：桌面 key 中 Kimi/GLM/DeepSeek 均欠费不可用，改用百炼双 key 双模型分工互审。

### 3.1 主审结论：修改后通过（4 项 P0）

P0-1 分离文档身份与版本：普通保存不得改 scopeId；另存/重命名才迁移；未保存文档用临时身份并标注不可靠
P0-2 发送强绑定：绑定文档≠活动文档时阻断或用户显式选择；执行前二次校验文档仍打开
P0-3 按 scope 隔离执行：会话级队列；沿用全局 LLM 串行锁时必须 UI 显示排队与错误路由到对应文档
P0-4 迁移安全：不自动合并；消息带 scope/turnId/seq 去重；备份可回滚

### 3.2 交叉复核新增（实现层 4 项）

P0-5 PluginStorage 串行写：按 scopeKey 写队列 + checksum/双键提交（防并发写坏历史 JSON）
P0-6 切换 epoch token：WindowActivate 与 3s 轮询双通道竞态 → 事件优先+代际令牌，旧解析结果一律丢弃
P0-7 Vue 按 scope reducer：消息入队前校验 scope，渲染 key=scope+turnId+seq，禁止直写当前视图
P0-8 单一状态源：浮窗只做投影，状态源锁主面板（防 ShowDialog/主面板双源分叉）

### 3.3 采纳的简化替代

- 身份：去掉"保存时间戳+文件大小"指纹 → docRegistry 路径首映射 + 未保存临时 token（更稳更简单）
- 并发：首版不做多文档并行执行，沿用全局 LLM 串行锁 + 按 scope 的 UI 排队/错误路由
- 迁移：启动只读映射不搬数据，历史按消息自带 scope 落库（永不写"当前面板 scope"）

## 4. 终稿方案（v2，已吸收全部 P0）

F1 稳定身份：docRegistry（PluginStorage 持久注册表 path→scopeId，首见即注册永不复用）+ 未保存文档临时 token（内存映射，UI 标注"未保存·会话临时"）
F2 文档胶囊：显示 名称+路径缩略+未保存标记+未读/排队数；点击下拉显式切换（进行中回合需确认）
F3 发送强绑定+epoch：发送前同步解析 scope（快照钉 turn）；与胶囊绑定不符 → 阻断+一键切换；WindowActivate 带 epoch 令牌，轮询仅健康探测
F4 回合归属：终态消息带 scope 落对应历史库（串行写队列+checksum）；渲染层 scope 不匹配 → 只进对应文档未读，不进当前视图
F5 执行隔离：全局 LLM 串行锁保留；队列按 scopeKey 分组展示；每回合写前二次校验 docId 仍打开（复用现有 __expectedDocId/DOC_SWITCHED）
F6 迁移：旧 doc_/path_/name_ scope 启动时只读映射到新 registry（不搬历史、不合并、90天后清理）

验收用例在 §2.5 基础上追加：普通保存后对话不变/另存为后历史跟随/未保存双文档互不可见/流式中切档回合不串/队列中多文档回合按序执行且错误归位。
