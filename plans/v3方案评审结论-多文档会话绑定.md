## 二、C1–C8 核心变更逐项裁决

### C1 SQLite 状态中枢 —— 方向对，选型过重，**降级为 sidecar 键值文件**
- 必要性成立：PluginStorage 不持久化是真的，而"未保存文档身份"“跨重启会话恢复"确实需要落盘（事实核查第 1 条 + Mac 锁屏 webview 全停的实测都指向 sidecar 侧兜底）。
- 但会话历史就是 JSON 数组，`chat_turn` 已走 sidecar RPC，用 ndjson/JSON 文件按 scopeKey 存即可。引入 SQLite = sqltie3 原生依赖 + schema 迁移 + 双写一致性，收益不匹配成本。
- **修订：C1 改为 sidecar 侧 `GET/PUT /session-store/:scopeKey`（JSON 文件承载，内存 LRU + 落盘），接口形状与 PluginStorage 对齐以复用懒迁移。**

### C2 路径变更检测器 —— 方向对，机制选错，**改为"身份映射表 + Writer 沿用 Variables"**
- v3 没有盘点到察元已有的 docLinkId 机制：Writer 宿主上文档变量随文档走，**另存为后 scopeKey 天然不变**（`plans/AI助手对话跟随文档-设计定稿.md` 已记录此结论，2026-09-30 真机验收）。路径变更检测器在 Writer 上是重复建设。
- 真正缺的是 ET/WPP：**推测**无 Variables（VBA COM 中该 API 为 Word 特有，待 T1 实证）→ 若证实，另存为后 path_ 变 → 会话断链；两个未保存文档靠 name_ 级勉强区分但脆弱。
- **修订：C2 改为 sidecar 侧 `path → docChatId` 映射表**（打开/激活时由 webview 上报 path+当前 id，sidecar 记忆首次见到该 path 的 id；另存后新 path 出现时按旧 path 查表继承 id）。Writer 沿用文档变量不动。事实核查第 3 条修正后，Writer 还可在 BeforeSave 里即时重绑（v3 自己否掉的手段其实有效）。

### C3 事件矩阵按宿主 —— **可采纳，但必须保留轮询双通道**
- 与察元现状（WindowActivate 事件 + 3s 轮询 syncHistoryScopeWithActiveDocument 双通道）兼容。注意：v3 若隐含"事件为主、去掉轮询"，在其自己的第 4/5 条事实核查所描述的环境（Linux 宿主不渲染标签、事件静默失败）下会全灭。**裁决：事件矩阵作为"低延迟通道"分级建设，轮询作为正确性底座保留，不可二选一。**

### C4 读写分流并发 —— 概念成立，**但察元已用更简单的模型覆盖，降为可选优化**
- 已有：LLM 全局串行锁（.llm.lock 文件锁）+ 执行侧 `__expectedDocId/DOC_SWITCHED` 写保护（切文档时拒绝陈旧回合落盘）。读写分流在"多文档同时对话"真实出现前是过度设计。裁决：P2。

### C5 未保存身份落盘 —— ✅ **正确且必要，与 C2 修订版合并实施**
- "新建演示文稿1/2" FullName 为空是实测真实场景；映射表 + 落盘正好覆盖。

### C6 token 鉴权 —— **把已有当新增**
- 察元 sidecar 已有 isTrusted/X-Chayuan-Token 鉴权（/clipboard 端点即用此）。新增 session-store 端点沿用即可，无需作为独立变更项。

### C7 懒迁移 —— ✅ **采纳**。已有 PluginStorage 键按 scopeKey 组织，懒迁移（首次读到旧键再搬）成本低、风险小。

### C8 事件健康自检 —— 观测性补充，**P3**。轮询双通道本身已是运行时自愈。

## 七、自审修正（2026-10-04 复核，本评审自身的问题）

总裁决不变（方向 75% 可采纳），但本评审初稿自身有 2 处实质缺陷 + 2 处表述需收紧，修正如下：

**D1（中）C2 修订版的"另存继承"机制欠定义。** 初稿写"另存后新 path 出现时按旧 path 查表继承 id"——sidecar 只收到 (path, docId) 报告，**无法单凭报告判定新旧 path 是同一文档**。继承判定必须发生在 webview 侧：轮询 diff（上一拍活跃 path 消失、本拍出现新 path、文档集合数量不变且时间窗 < 数秒）视为改名并继承会话；Writer 宿主可走 BeforeSave 事件精确重绑。sidecar 映射表只负责跨重启持久化，不做继承判定。初稿把判定职责错放在 sidecar。
- 佐证：`__expectedDocId` 已随每次工具调用流经 sidecar（`mcpHandler.mjs:773` → `dispatch.js:531` DOC_SWITCHED 守卫），映射表数据源成立——这半边没问题。

**D2（中）C1 修订版缺降级路径。** 会话历史若只存 sidecar，sidecar 不可用（进程挂/端口被占/锁屏期）时面板无历史可渲染。正确形态：**PluginStorage 内存副本为一层缓存（读走缓存，写穿 sidecar），sidecar 为持久层**——不是"迁移走"。懒迁移即"缓存 miss 时从 sidecar 回填"。

**D3（轻）T1"一行代码即可探测"表述乐观。** 表达式确实只有一条（`!!Application.ActiveWorkbook?.Variables` 及 `Variables.Add` 写读回验），但仓库内**没有任意 JS 执行通道**（已核查无 eval/run_script 类 action）。执行手段需三选一：① 给 dispatch 加临时 debug action；② 在 resolveHistoryStorageScope 里加临时探测日志走真机；③ 借 document_meta 若其返回对象属性。且必须**两宿主分别探测 + 存在属性 ≠ 可写**（v3 第 6 条 CDP 只读的教训同样适用于 Variables：要 Add 后读回验证）。

**D4（轻）第 ③ 条反证标注宿主边界。** 三参数实证仅在 Writer 宿主；handler 从未读取 saveAsUI 形参，反证只覆盖 cancel 对象。裁决从"伪"收紧为"**以 Writer 为准的强反证（通用性声明被单个宿主即驳倒）；ET/WPP 的事件签名列入 T4 矩阵实测**"。

**复核后仍成立的**：6 条判定方向、C3/C4/C5/C6/C7/C8 裁决、既有能力清单（全部有代码行号背书）、优先级排序、⑤"事件静默失败"与 ④"轮询底座不可去"的结论。

## 八、二轮复核修正（2026-10-04，针对转述稿）

**R1（实质）T1 必须是三维探测，不是一维。** "存在 → 可写 → **持久**"缺一不可，其中③持久（写入→保存→关闭→重开读回）才是 load-bearing：docLinkId 的全部意义是"另存后身份不变"，Variables 若只在内存会话存在、不随 xlsx/pptx 落盘，与不可写等价。D3 只补了"可写"维度，本轮补全第三维（已改第四节 T1 条目）。

**R2（设计缺口）未保存文档的映射键未定义。** "映射表含未保存文档"的表述漏了关键细节：未保存文档 FullName 为空，**path 根本不能作键**。映射表需复合键：未保存态 `(host, name)`、保存态 `(host, path)`；另存瞬间由 webview 侧把 `name→id` 记录转写为 `path→id`（转写时机与 D1 的继承判定同拍发生）。T5（同名未保存文档碰撞）同时校验该键设计。

**R3（表述）不要锚定具体百分比。** "75%/80%" 是叙事便利数字：v3 原稿与修订稿的差别不是 5 个点的可信度，而是**条件二分**——T1 三维全过则 ET/WPP 走 Variables（改动小），任一维不过则走映射表（改动中等）。结论应以条件表达，不以数字表达。

## 十二、面板级隔离真机终验与三重防线（2026-10-05，用户持续报告"多文档输出一致"后的深度修复）

### 用户场景精确复现（修复前）

d1（长江）面板发"hi"→ AI 正确答长江 → 切 d2 → **面板仍显示 d1 的"hi"会话**（scope 调试证实：`current` 停在 d1 键、`busy=true` 焊死同步）——用户在 d2 面板里看到的输入输出全是 d1 的，即"多个文档输出一致"。

### 根因链（两级）

1. **直接原因**：`syncHistoryScopeWithActiveDocument` 被 busy 一票否决——回合上下文/streaming 残留期间，无论活动文档切到哪里，面板永远渲染旧 scope 的会话。
2. **残留原因**：远程回合的 watch 循环在面板视图切换/重挂载时可能整体丢失，`activeMcpTurnContexts` 残留把 `isWindowBusy` 永久钉在 true（真机实证：回合完成 40s+ busy 不自愈）。

### 三重防线（全部落地）

1. **busy 安全切换**：busy 期间检测到文档切换 → 立即切 scope 元数据 + 清空消息视图（显示新文档的空会话/"新对话"），**绝不显示旧文档内容**；新文档历史推迟到 busy 解除后加载。此分支刻意不落盘（旧会话属旧 scope，误 save 会串键）。
2. **跨文档拒绝发送**：本地执行中发送前硬校准发现 scope 错位 → 弹窗拒绝发送并指路。
3. **孤儿回合回收**：轮询 tick 回收超过 10 分钟硬上限仍残留的回合上下文，解除 busy 钉死。
