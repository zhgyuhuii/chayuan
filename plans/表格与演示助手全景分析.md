# 表格与演示稿助手全景分析

> 2026-09-30 · 分析稿（不含实现）。文字类助手已有，本文只覆盖表格（ET）与演示稿（WPP）。
> 依据：竞品全网调研（微软 Copilot、Google Sheets Gemini、WPS AI、ChatExcel 酷表、办公小浣熊、Gamma、百度文库、讯飞智文、iSlide）+ 行业场景证据 + 本项目现有基建盘点。
> 2026-09-30 更新：§5 追问 2（配图图源）已定案，新增 §6 图源架构设计（参考 chayuan-office 已实施的 image-source 体系）。

## 0. 分析框架（连锁推论的根）

助手 ≠ 功能列表。**助手 = 「预设意图 + 工具链 + 输出形态 + 验收标准」的配方**。三条连锁推论：

1. 每个助手必须映射到已有 MCP 工具链（spreadsheet 21 actions / presentation 17 actions），否则是空头支票 → 见 §4 差口分析。
2. 助手必须按宿主分流：现有 `isChayuanToolAllowed(tool, host)` 已按宿主过滤工具，助手列表同理（et 宿主看不到文字助手）。
3. 顶部菜单（ribbon）与面板全集是**同一份助手的两种曝光**：ribbon = 跨行业高频 + 一键直达；面板 = 全集按行业分组。基建已存在：`DOMAIN_MANIFEST`/`ensureDomainLoaded`（行业懒加载）、`assistantSettings` 显示位置机制、察元AI广场（assistants_search，2.8 万+配方生态）。

## 1. 表格（ET）助手

### 1.1 通用高频 ★（跨行业共用，竞品共识）

| # | 助手 | 场景 | 工具链映射 | 竞品依据 |
|---|------|------|-----------|---------|
| ★1 | **公式生成与解释** | 大白话→公式，选中公式→人话解释 | 模型生成公式文本→range_write；解释：range_read+模型 | Copilot/Gemini/WPS AI 第一功能，无一缺席 |
| ★2 | **数据洞察** | 选中区域→趋势/异常值/TOP N/占比结论 | used_range+range_read→模型分析→对话输出（可写批注） | Copilot"instant insights"、Gemini 数据分析 |
| ★3 | **一键图表** | 一句话出图 + 图型推荐 | chart_add（已支持 5+ 图型）+ 模型推荐图型 | 各家标配 |
| ★4 | **数据清洗** | 去重/拆列/格式统一/空值/去除重复项 | range_read→模型转换→range_write | Copilot"clean messy data"、酷表主打 |
| ★5 | **排序筛选汇总** | 按维度统计/排名/分类汇总 | sort/autofilter（已有）；汇总用公式写入 | Copilot 透视表高频 |
| ★6 | **报表结论** | 数据→日报/周报文字结论（含数字依据） | range_read→模型→输出（不直接改数） | 财务/运营通用下游 |
| ★7 | **表格创建** | 描述→带表头结构+示例行的空表 | sheet_add+range_write | Gemini"Help me organize" |
| ★8 | **导出转换** | 区域→CSV/PDF、表格→Markdown/正文 | export（已有 pdf/csv） | 通用 |

> ★1–★8 = 大家共用的最高频集合，全部落在现有 21 actions 差距很小（见 §4）。

### 1.2 行业分组

**财务**（证据：DataSnipper 用户对账日省 3 小时；AI 月结/银行对账准确率 95%+）
- 发票/单据明细整理、银行流水对账、费用归类汇总、三大报表指标计算、预算 vs 实际差异表
- **配方纪律（高质量实践，非强制闸门；责任口径：损失用户自担、模型担责、产品免责）**：计算类产出优先写公式（SUM/SUMIF/VLOOKUP）让 ET 自己算，模型不写死数值；关键汇总走"写完读回校验"一步；助手说明文案含"数字请复核"提示

**电商/运营**（证据：办公小浣熊直播报表场景；Excel COPILOT() 函数做留言情绪归类；销售明细整理是酷表高频）
- 销售明细汇总（按 SKU/店铺/日期）、直播转化漏斗、竞品价格对比、客户留言情绪归类、库存进销存

**HR**（证据：excelmatic 用 AI 替代 COUNTIF 类手工公式做 HR 报表）
- 花名册统计、考勤汇总、薪酬核算、招聘漏斗

**销售**
- 业绩排名与提成计算、销售预测、客户跟进表整理、商机漏斗

**教育/个人**
- 成绩统计（及格率/排名/分数分布）、班级考勤、家庭记账预算

### 1.3 表格顶部菜单建议（常驻 4 个，全部 ★）

**公式助手 · 数据洞察 · 一键图表 · 数据清洗**

选择原则：跨行业高频 + 一次点击可完成 + 失败可重试不伤文档。这四个是微软/谷歌/WPS/酷表全部同款，用户教育成本为零。

## 3. 差口分析（助手→MCP 能力缺口，连锁核心产出）

### 表格侧
| 缺口 | 影响的助手 | 降级方案 | 建议 |
|------|-----------|---------|------|
| 透视表 pivot | ★5 汇总 | 公式汇总（SUMIF 族） | 二期加 native pivot |
| 删除重复/分列 | ★4 清洗 | range_read+write 模拟（慢） | 加 native action |
| 单元格批注写入 | ★2 洞察写回 | 只输出对话 | 加 ET comment API |
| 条件格式/迷你图 | 洞察可视化 | 图表替代 | 观望 |

### 演示侧
| 缺口 | 影响的助手 | 说明 |
|------|-----------|------|
| 演讲备注 notes 读写 | ★7 口播稿、★3 摘要页 | 讯飞智文亮点功能的硬前提，优先级最高 |
| 主题/母版/字体统一 | ★4 美化 | 美化助手的硬前提 |
| ~~配图图源~~ ✅已定案 | ★1 一句话生成 | 五值设置（网络/模型/SVG/本地/auto），见 §6——chayuan-office 已验证体系移植 |

### 架构优势（竞品没有）
**跨宿主编排**：文档转 PPT 要同时读文字宿主、写演示宿主；数据战报页要读表格写演示。我们的 chat.turn 基座编排天然跨宿主（agentHub 按方法前缀路由），Copilot/Gemini 的宿主内助手做不到。

## 5. 往死里追索的连锁问题（实现前必须逐个定案）

1. ~~**行业包的商业化边界**~~ ✅ **已定案（2026-09-30）：单层全内置**——不做用户登录、不做付费、不做广场领取分层，**全部行业包内置**随版本发布。要点：
   - 体积问题由现有懒加载基建消化：`DOMAIN_MANIFEST`/`ensureDomainLoaded` 本就是按域折叠+按需加载——"内置"指随包分发，不指首屏全展开；首屏 = 通用高频 ★15 展开 + 行业分组折叠。
   - 行业包时效性接受发版节奏（财务准则/电商节奏/政企规范随版本更新）；广场 `assistants_search` 保留为既有浏览功能，但行业包分发不依赖它。
   - license 骨架（isPaidPlan/quota）保留代码不启用；tipJar 随缘支持文化不变。
   - 连锁收官：6（ribbon 容量）——ribbon 4 常驻 + 面板折叠全集，无下拉需求，**收官**；7（模型路由）——BYOK 下不强制换模型，行业配方内写"建议高阶模型"措辞，选择权归用户，**收官**；4（政企模板合规）收窄为"内置党政风模板的内容规范自查，由我们维护、随发版更新"；8（频率验证闭环）保留为流程问题（内置包维护节奏的复审依据）。
2. ~~**配图图源策略**~~ ✅ **已定案（2026-09-30）**：设置中可配多源——模型生成 / 网络搜索 / 对话模型生成 SVG，参考 chayuan-office 已实施体系。完整设计见 §6。
3. ~~**财务数字准确性责任**~~ ✅ **已定案（2026-09-30）**：用户损失用户自己背、大模型背、**产品不背**；产品侧做正常的高质量处理即可——**不做 dispatch 层强制校验闸门**，但财务类助手的配方按高质量实践写（见 §1.2 配方纪律）。
4. **政企模板合规**：党政风配色/版式/表述规范由谁维护？模板包版权与更新机制？
5. ~~**跨宿主写保护**~~ ✅ **已定案（2026-09-30，四条）**：
   - **一回合一写宿主**＝发起回合所在宿主（用户就在那个宿主里聊），其余宿主本回合只读；"表格→战报页"＝ET 读 + WPP 写，天然覆盖头部场景。回合卡标注"本轮写入目标：xxx"。
   - **跨宿主写前自动钉身份**：首次跨宿主写前，由 skill/runner 层（不依赖模型自觉）自动向目标宿主发轻量 status 探针，取活动对象 FullName 作为 `expectDocId` 钉住整回合；后续该宿主写全部带此校验，中途激活切换 → 现有 `DOC_SWITCHED` 拦截。代价：每跨宿主回合多一次探针往返（百毫秒级）。
   - **pin 刷新只认显式意图**：模型调用激活类工具刷新对应宿主 pin；用户手动切档不刷新（首版可从"不刷新"起步，更收紧）。
   - **OCC 指纹跨宿主缺失记为已知限制**：身份校验仍在，内容指纹仅同宿主回合全量保留；写前快照/撤销卡跨宿主回合降级（与远程回合现状一致）。
   - 改动面：`agentCoreSkill` 注入从单值 `targetDocumentId` 扩为回合 pin 表（约 30–60 行）；dispatch/agentHub/sidecar 零改动。实现批次：与"后台回合挂起修复"（基座节流+LLM 超时）同批。
6. **ribbon 按钮容量**：每宿主 4 个常驻是否足够？要不要 customUI 下拉菜单收纳次高频？
7. **行业助手的模型路由**：财务类是否强制高精度模型？与用户自选模型冲突时听谁的？
8. **频率假设的验证闭环**：★标注是调研推断——上线后按助手点击埋点验证，多久复审一次？淘汰机制是什么？

> 状态（2026-09-30）：**1、2、3、5、6、7 已定案**（1 单层全内置；2 图源见 §6；3 财务责任口径；5 跨宿主写保护四条；6/7 随 1 连锁收官）。待定仅剩：**4 政企模板内容规范自查**（收窄后基本是执行事项）、**8 频率验证闭环**（内置包维护的复审节奏）。

## 6. 配图图源架构（已定案，参考 chayuan-office image-source 体系）

> chayuan-office 已实施收口的同款体系：`docs/image-source-plan.md`（三里程碑全绿：五值设置/来源解析分配/三态 spec/消毒光栅化/IPC 31 新测试；docs/sheets 兜底 generate_svg 双端；集成测试+全量回归绿）。我们不是从零设计，是**移植已验证的架构**到 WPS 加载项形态。

### 6.1 五值设置（全局默认 + 对话口头改源）

`globalSettings.settings.json` 增加 `imageSource` 键（与已验证的 modelConfigs 同一文件同一机制）：

| 值 | 行为 | 我们的能力映射 |
|----|------|--------------|
| `web` 网络搜索 | image_search 通道搜图，跨批去重 | 差口：sidecar 需搜图通道。chayuan-office `packages/ai-search` 有现成多源降级链（chatoffice → Serper → Bing → Openverse → DuckDuckGo + stock 图库），可移植最小子集 |
| `model` 模型生成 | 复用"默认模型→图像"角色 BYOK 生图，返回 URL | **现成**：面板助手列表已有"文本转图像"能力（multimodalTaskRunner） |
| `svg` 矢量图形 | 对话模型内联生成 SVG 语义单元（一页 2–8 个，单个 ≤1.5k 字符） | **零新依赖**：runner（chat.turn 基座）里对话模型直接生成；消毒（剥 script/事件属性/外链）后 webview canvas 光栅化 PNG→`picture_add` 插入 |
| `local` 本地图片池 | 选文件夹→扫描→缩略图确认→按槽位分配 | 二期（chayuan-office 也列为 v1 不做） |
| `auto` 自动 | 有已配图像模型→模型，否则→网络，再否则→SVG；本地不参与自动链 | 缺省值 |

### 6.2 降级链（资金安全铁律，照抄 chayuan-office 共识 #3）

- 任何显式来源失败/零结果 → **统一落 SVG**（零成本零依赖）；SVG 也失败 → 无图排版
- **绝不静默切到另一个可能花钱的来源**；降级原因写进生成报告（"第 3 页：图像模型欠费，已用矢量图形兜底"）
- SVG 默认跳过 web 档，不静默换源

### 6.3 WPS 形态的移植差异（与 Electron 版的三处不同）

| chayuan-office（Electron） | chayuan-wps（WPS 加载项） | 方案 |
|---------------------------|--------------------------|------|
| spec 三态（url/dataUri/svg+pngDataUri），pptx-engine 直通 | `picture_add` 只吃文件路径/URL | SVG 消毒后 **webview canvas 光栅化 PNG**（Image+canvas，零原生依赖），写临时文件→picture_add |
| 主进程 IPC 扫描文件夹 | 无主进程 | local 档二期（本就二期） |
| AiSettingsV2 设置窗口 | SettingsDialog 模型设置页加"图片来源"选择项 | globalSettings 机制现成 |

### 6.4 生效范围

- 演示：★1 一句话生成 PPT（每页配图按槽位分配）、★6 数据页装饰
- 文字（未来复用）：docs/sheets 插图同链路（chayuan-office M-B 已验证双端复用）
- 设置入口：对话内口头改源（"用网络图片"）即时生效并即存默认——与 chayuan-office"覆盖即默认"一致

### 6.5 遗留追问（✅ 已定案 2026-09-30）

- ~~搜图通道移植范围~~ → **不走云通道**。移植最小 vendor（免 key 源：Bing/Openverse），未登录零门槛可用；后续要云能力再议。
- ~~SVG 光栅化分辨率~~ → **可以**。按长边 ≤2048px 上限，动工第一天在 VM/宿主各核一次 WPS `picture_add` 对 PNG 尺寸/DPI 的接受度。
