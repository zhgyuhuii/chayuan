> 日期：2026-11-19 ｜ 上游：`genspark-ai/genoffice` @ `6b43f81b` ｜ 本项目：chayuan-wps（察元 AI Office）

本次工作两件事：**① 把 vendored 的 `src/agent-core/` 从上游合并到最新**；**② 深度分析上游技能体系并把 42 个业务技能全量收割落地**（含技能设置页、对话附加链路、中文化）。本报告是第二件事的分析与落地文档。

## 一、上游技能体系机制全解

上游仓库里存在**两套"技能"概念**，收割前必须分清：

| 概念 | 形态 | 位置 | 消费者 |
|---|---|---|---|
| **A. 分发型 SKILL.md** | 纯 Markdown + YAML frontmatter，无代码 | `skills/` 目录（1 主 CLI 技能 + 42 业务技能 + 22 语言 locales） | 外部编码 agent（Claude Code/Codex/Cursor）；上游自家 app 导入后附加到消息 |
| **B. 编译型 AgentSkill** | TS 对象：`systemPrompt + tools + executeTool` | `packages/agent-core/src/skill.ts` | app 内 AgentLoop 经 `composeSkills` 组合进 system prompt 与工具清单 |

`skills/genoffice/SKILL.md`（主技能，v2.70.1，230 行）属 A，但 app 内有它的编译孪生 `cli-skill.ts`（同样的 CLI 能力做成 `run_genoffice`/`load_guide` 工具）——**一能力两形态**是上游体系的关键设计。

### 1.1 业务技能的标准结构（42 个，已被本次收割验证）

每个目录只有一个 `SKILL.md`（无 references/、无脚本、无模板）。frontmatter 五键：

```yaml
name: weekly-report          # 英文 kebab-case，唯一 id
description: ...             # 触发匹配用（22 语言 locales 只翻这一键）
category: office             # 8 类：office/business/data/finance/hr/legal/marketing/education
scenarios: A | B | C         # 场景示例（上游当前无代码消费，纯预留）
quickPrompts: A | B          # 快捷 prompt（同上，本次已消费：面板可后续接"示例指令"）
metadata:
  version: 1.0.0             # 安装状态机与 CI 版本守卫用
```

正文是**工具无关**的角色 prompt：`You are a X specialist.` → 工作流步骤 → 交付物要求 → 防幻觉约束。工具指称刻意用泛称（"the document tools available here"），靠宿主环境落地的正是这层泛称映射。

### 1.2 注入模型：用户显式附加，别无分叉

上游技能进入模型的**唯一通道**：用户在 composer「+」菜单勾选 → 发送时 body 包成 `<skill name="…">` 块拼在该条 user message 前（`attached-skills.ts` 的 `withAttachedSkills`，并声明"技能与通用指导冲突时技能赢"）。**没有任何自动触发/自动选技能机制**——`classifySkill` 的相关性判定只影响设置页展示与否。

### 1.3 存储与安全边界（上游 Electron main 进程侧，本次未全收）

- 三处落点：仓库源 `skills/` → 打包资源 `Resources/cli/skills/` → 运行时用户区 `<userData>/skills/<name>/SKILL.md`（app 内唯一"已安装"集合）。recommended 不预装，点 Install 才拷入。
- 导入三通道（folder/md/zip）配套成套防护：拒 symlink、10MB 上限、zip-slip 检查、IPC 只传 name 不传 path、`isKnownSkillPath` 限定可读集合、`app-settings.json` 里的 ledger（path→{version, sha256}）防覆盖手工修改。
- **版本治理**：CI 有 `check:skill-version`（改 SKILL.md 必须 bump version，否则 fail）——因为技能拷进用户目录后只在版本号增长时才被替换。

### 1.4 对收割最重要的结论

- 技能正文工具无关 → 收割的主要适配面不是改写 42 篇正文，而是**宿主 system prompt 里的一次性指称映射**（本次落地选择此路，见 §4）。
- 42 篇正文全英文 → 中文产品需要中文交付版；上游 `locales/zh.json` 只翻好了 description（42 条现成），正文需自行翻译。
- 主 CLI 技能强绑定 `genoffice` 二进制 → 对本项目**不可运行时收割**（无此 CLI），只可吸收其写法（见 §6 路线图）。

## 三、42 技能 × 察元能力域匹配矩阵

分类分布：office ×5、business ×7、data ×5、education ×5、finance ×5、hr ×5、legal ×5、marketing ×5。

| 依赖能力 | 察元现状 | 受影响技能 | 收割处理 |
|---|---|---|---|
| 文档产出（Word） | ✅ document_*/format_*/style 域工具齐备，且"写回当前活动文档"纪律成熟 | 约 30 篇（交付为 Word 文档） | 直接收割；落稿句已改写为「优先写回当前活动文档；无打开文档不新建、先附全文」 |
| 表格产出（Excel） | ✅ spreadsheet(action=…) 域齐备 | data-analyst、data-cleaning、expense-report、budget-planner、sales-forecast、survey-analyst、personal-finance、kpi-dashboard、financial-statement-analysis | 直接收割；落稿句同上（写回当前工作簿） |
| 演示产出（PPT） | ✅ presentation(action=…) 域齐备 | course-slides、executive-deck、slide-planner、kpi-dashboard（部分） | 直接收割 |
| 联网搜索 | ❌ **无 web 搜索工具**（仅 image_search/assistants_search） | deep-research、business-plan、seo-content、social-media 等泛提搜索的技能 | **指称映射段兜底**：声明本环境无联网搜索 → 向用户索取资料/用 file_parse 读用户上传材料，无法核实写「未能核实」，严禁编造来源 |
| 文件读取 | ✅ file_parse | 提到"读取用户提供材料"的技能 | 直接可用 |
| 邮件/发布等外部动作 | ❌ 无邮件/社交发布工具 | email-drafter（仅起草不发送，✅）、social-media（仅产出文案，✅） | 直接收割（都是产出型而非执行型） |

**结论：42 篇全部可收割**，唯一能力缺口是联网搜索，用映射段降级方案兜住。无一篇需要砍。

## 四、落点选型：三方案评估

| 方案 | 形态 | 评估 |
|---|---|---|
| **A. 对话内附加技能**（上游 attached-skills 模型）✅ **选定** | 用户显式勾选 → `withAttachedSkills` 包进当条消息 → agent 循环执行 | 与上游同构、与现有 MCP 巨技能零冲突（`composeSkills` 都不用动）、多步工作流正是 agent 循环的主场 |
| B. 面板助手/配方（builtinAssistants 或 src/skills 插件） | 单次 LLM 调用 + 写回动作 | ❌ 形态错配：42 篇是多步工作流，一发调用扛不住"检索→起草→落稿→排版→自检" |
| C. 外部 CLI 技能（仿 skill-chayuan 投放 ~/.claude/skills） | SKILL.md 教外部 agent 调 MCP | 部分可行，但那是**分发**而非**产品功能**；列入路线图而非本次范围 |

选 A 的核心论据：上游"skills are never offered to the model on their own"的克制设计（不自动触发、不占 system prompt、零技能时零开销）恰好匹配本项目 agent 循环的 token 预算敏感场景（compaction 48KB、轮次上限）。

## 六、后续路线图（按价值排序）

1. **quickPrompts 消费**：frontmatter 里的快捷 prompt 已随库分发，面板选择器可加「示例指令」一键填输入框（上游同样未消费，做了即领先）。
2. **自动技能推荐**：按用户输入意图（ GeneratedOutputTrigger 类正则已有先例）在选择器顶部预置推荐勾选——不自动注入，只降选择成本。
3. **外部 CLI 分发**：把 42 篇中文交付版投放 `~/.claude/skills/wps-skill-chayuan-library/`（仿 skill-chayuan 安装链），外部编码 agent 也能用；需配 `check-skill-version` 式版本守卫。
