# 模板深度剖析 + 要素勾选确认 —— 方案设计 v1.1

> 版本：v1.1（2026-10-15，增补大纲确认与目录页处理）
> 触发：用户实测反馈——触发「按模板生成」后应有**提问环境**：先对模板做全面深度剖析（doc：内容/文案风格/字体/段落；Excel：表头/单元格样式；PPT：图元/背景/文案风格），把分析结果**让用户勾选**（根据模板哪些方面生成），然后才执行。
> 性质：设计方案，未写代码。

---

## 〇、大纲与目录（关键增补，用户点名）

大纲（outline）与目录（TOC）是模板生成的**骨架**，行业惯例（WPS AI/Kimi 均如此）：大纲确认是生成前的必经步骤，生成完成后需**自动生成/更新目录页**。处理方式按类型分化：

| 类型 | 大纲 | 目录 |
|------|------|------|
| doc | 章节结构 = 计划卡大纲（标题树映射到模板章节） | 目录页/目录字段：内容替换后需同步更新标题条目（docx 的 TOC 是域字段，可刷新；目录条目属于「保留型文案」） |
| slide | 大纲 = 页计划（每页标题+要点映射到模板页型） | 目录页是模板常见页型之一，直接复用 |
| sheet | 无大纲概念，数据块布局即计划 | 无 |

### 0.1 大纲确认（对齐业界，默认前置）

- 大纲是生成的**第一份产物**，必须先于内容写入被用户确认——这正是 WPS AI 的第二步（确认大纲 → 选风格 → 生成）。
- 本方案落地：**计划确认改为默认开启**（`planOnly` 默认「先出计划确认」），大纲卡片展示章节/页结构，用户可改可确认后执行。跳过确认的「直接生成」保留为快捷选项。

### 0.2 目录页处理

- **doc**：内容替换完成后，若模板含目录页/目录域，新增段落导致页码/标题变化时，提示用户刷新目录（docx 域字段可整体更新）；无法刷新时在质检报告标注「目录需手动更新」。
- **ppt**：目录页按「保留型文案 + 页型复用」处理——目录页的标题条目跟随新大纲更新，版式背景不动。
- **sheet**：无目录概念。

## 一、业界对标（全网调研）

| 产品 | 流程 | 可借鉴点 |
|------|------|----------|
| WPS AI（PPT） | 输入（主题/大纲/文档）→ **确认大纲** → **模板/主题色勾选** → 生成 → 逐页校对 → 换主题定稿 | 大纲确认与风格勾选分两步；生成后可整体换装 |
| Microsoft Copilot（Word） | 提示词/大纲/笔记/**引用文件** → 草稿 → 调整**语气**（专业/简洁）→ 复用现有格式 | 引用文件起草；语气参数化；「复用现有格式」= 我们的样式档案 |
| Copilot Tuning | 用团队样例文档训练**写作风格模仿** | 文风画像可作为长期资产（模板画像缓存复用） |
| 百度文库 AI 写作 | 预设文风勾选（专业严谨/轻松自然/依据充分/多用数据）+ 名人风格模仿 | 文风选项的**预设档位**表达方式 |
| Gamma | 提示词直达生成 → 风格后置切换 | 风格可后置，降低前置门槛 |
| Beautiful.ai | 风格前置 + 生成中布局规则锁死 | 勾选的要素=硬约束（生成时不可违背） |

**共识范式**：`引用来源 → 要素/大纲确认（勾选）→ 生成 → 校对`。差异化：我们勾选的不是内置模板库，而是**用户自带模板的剖析要素**——这是别家没有的（他们只能整库切换，我们能细粒度选择「用模板的哪些方面」）。

## 二、核心设计：模板剖析报告 → 要素勾选卡 → 生成契约

### 2.1 流程（插入现有主链路，替换扁平确认卡）

```
触发 generate-from-template
   ▼
① 模板深度剖析（文件级 templateStyleReader 扩展，纯读零崩溃面）
   ▼
② 剖析报告卡（折叠展示模板画像全文 + 结构化摘要）
   ▼
③ 要素勾选卡（分类型选项树，用户勾选「根据模板哪些方面生成」+ 参数）
   ▼
④ 生成契约（generation contract JSON = 勾选结果 + 参数）
   ▼
⑤ 管线消费：计划 prompt 注入契约 → 执行器尊重每个勾选项 → 质检按契约校验
```

### 2.2 剖析维度全集（分类型选项树）

**Word（doc）**
| 分组 | 勾选项 | 数据来源 |
|------|--------|----------|
| 结构 | [√]沿用章节骨架（标题树映射） [√]表格样式 | styles.xml + document.xml（已有，补表格样式） |
| 样式 | [√]字体字号 [√]行距缩进对齐 [√]命名样式套用 | styles.xml（已有，补表格样式解析） |
| 文案 | [√]文风跟随（语体画像） [√]固定文案保留（页眉页脚/落款清单） | 语体画像（LLM 归纳）+ 固定文案探测（新增） |
| 内容 | [ ]保留模板示例段落作为范文参照 | 段落清单（已有） |

**Excel（sheet）**
| 分组 | 勾选项 | 数据来源 |
|------|--------|----------|
| 表头 | [√]表头文字与结构 [√]表头样式（字体/填充/边框） | sheet1.xml（已有）+ styles.xml（**新增**：cellXfs/fonts/fills/borders/numFmts） |
| 数据区 | [√]列宽行高 [√]合并单元格 [√]数字格式（日期/货币/百分比） | cols/mergeCells/numFmt（已有列宽合并，补数字格式映射） |
| 逻辑 | [√]公式区自动扩展 [√]条件格式沿用 | 公式区探测（已有）+ 条件格式（**新增**，P2） |

**PPT（slide）**
| 分组 | 勾选项 | 数据来源 |
|------|--------|----------|
| 主题 | [√]配色方案（12 槽主题色） [√]字体方案（中英文标题/正文） | theme1.xml（已有） |
| 版面 | [√]背景图元沿用 [√]装饰元素复用 [√]版式角色分类（封面/目录/章节/内容/数据页） | 逐页 shape 普查（已有几何，**补**填充色/背景/占位符类型） |
| 文案 | [√]文案风格跟随 [√]保留型文案不动（口号/页脚清单） | 逐页文案（已有）+ LLM 归纳 |

### 2.3 生成契约（generation contract，新 JSON 协议）

```json
{
  "schemaVersion": "2026-10-template-contract-v1",
  "template": {"source": "附件|路径|目录|库", "path": "…", "kind": "slide", "analysisId": "…"},
  "aspects": {
    "theme": {"colors": true, "fonts": true},
    "layout": {"backgrounds": true, "decorations": false, "pageRoles": true},
    "copy": {"toneFollow": true, "keepFixedCopy": ["页脚口号…"]},
    "structure": {"skeleton": true, "tables": true}
  },
  "params": {"pageTarget": 15, "tone": "跟随模板", "qcRounds": 2, "savePath": "…", "planOnly": false}
}
```
- 契约随任务全程携带；**计划 prompt、执行器、质检器三方读取同一份**（质检新增契约符合性检查：未勾选的方面被改动 → 告警）。
- 勾选结果默认记忆为该模板的画像偏好（下次同模板预填）。

### 2.4 交互载体（两案对比，待定）

| 方案 | 形态 | 优点 | 代价 |
|------|------|------|------|
| A. 扩展现有确认卡 | `pendingWpsCapabilityForm` 动态表单新增 **checkbox/分组** 类型 | 复用现有链路（意图→卡片→参数）零新通道；勾选即参数 | 卡片较高，需滚动 |
| B. 独立剖析报告对话框 | 新路由页（模板画像全文 + 选项树 + 参数区） | 展示空间大、画像可全文呈现 | 新增对话框路由 + 数据传递通道 |

## 五、风险

- 剖析准确性依赖模型（语体/页型分类）——勾选卡本身就是纠错手段（用户过目）。
- 大模板（几十 MB pptx）剖析耗时——文件级解析为一次性成本，画像可缓存复用。
- 勾选项 × 执行分支组合爆炸——契约只携带「开/关」，执行器按开关走既有分支，不加新执行路径。

## 七、跨类型参考素材（v1.2 增补，用户点名）

「按模板生成」的输入分两种角色，能力上解耦：

| 角色 | 类型约束 | 处理方式 |
|------|----------|----------|
| **版式模板**（复制打开保样式） | 必须与目标 kind 同类（同宿主闸门） | 现有 generate-from-template 全流程 |
| **参考素材**（只提炼，不打开） | **任意类型**（txt/md/html/pdf/docx/xlsx/pptx…） | 提炼内容/文风/目录结构后喂给 LLM |

关键区分：生成 Word 时可以传 Excel（数据源）、PPT（内容结构参照）、txt/md/html（写作素材）——这些**异 kind 文件不作为版式模板**（不触发同宿主闸门、不复制打开），只做素材提炼。同 kind 文件仍是版式模板。同理，生成 PPT 时可传 Word/txt/md/html 作为参考素材。

### 7.1 提炼通道（复用现有能力）

- txt/md/html：原生文本（intake 已支持读取）→ 直接作为素材
- pdf：pdfjs-dist（已在依赖）→ 文本提取
- docx：mammoth（已在依赖）
- xlsx：SheetJS（已在依赖）
- pptx：自研 XML 解析（templateStyleReader 的 slides 文案提取可复用）

### 7.2 与版式模板的协作关系

- 一次生成可同时指定：版式模板（同 kind）+ 参考素材（任意 kind）
- 剖析器对参考素材只做**内容/文风提炼**，不涉及样式复制
- 计划 prompt 同时携带：模板画像（样式骨架）+ 参考素材摘要（内容骨架）→ LLM 按需求融合两者

## 八、全面审查与修订（v1.3）

### P0 承重级修正

1. **三重确认门合并为一张卡**：原设计 确认卡→勾选卡→计划卡 三道闸，业界无一例三连问（WPS AI 大纲+风格一屏、Gamma 零前置）。改为**单卡**：剖析摘要（折叠）+ 大纲（LLM 预出，可改）+ 要素勾选（按剖析预填智能默认）+ 参数，一次确认即执行。planOnly 参数取消（卡片即计划确认）；「直接生成」保留为卡片上的跳过勾选。
2. **契约落地映射**：每个勾选项必须映射到明确的执行器分支或质检规则，映射不到的从勾选卡移除（移入画像展示区，仅展示）。映射表：

| 勾选项 | 执行器行为 | 质检行为 |
|--------|-----------|----------|
| doc 沿用章节骨架 | 计划 ops 以标题树映射 | 语义审比对骨架 |
| doc 字体/行距（样式档案） | 新增段套命名样式/移植直接格式 | 样式漂移检测 |
| doc 文风跟随 | 计划 prompt 注入语体画像 | 语体一致性（读回比对） |
| doc 固定文案保留 | 执行器不改这些段落 | 保留型文案误改检测 |
| sheet 表头/列宽/合并 | 执行器不碰（只写数据区） | 结构完整性 |
| sheet 公式区扩展 | 插行时扩展公式（P2 前不做勾选） | 公式引用完整 |
| ppt 配色/字体方案 | 新建页按主题画像约束 | 主题一致性 |
| ppt 背景图元沿用 | duplicate 页继承；add 页不带背景 | 槽位遗漏检测 |
| ppt 装饰元素复用 | 装饰槽永不改写 | 装饰被动检测 |
| ppt 文案风格跟随 | 计划 prompt 注入语体 | 语体一致性 |

3. **智能默认预填**：基于剖析结果预勾选（语体画像置信→文风跟随预勾；模板有背景图→背景沿用预勾；无目录页→目录更新项不出现）。用户只调有异议的项。

### P1 应改进

4. **画像偏好记忆按内容 hash**：key = md5(模板文件) + 模板名，带 TTL；同文件改名/内容变更不串。
5. **剖析结果共享缓存**：附件懒提取与模板剖析按 path+mtime 共享，同一文件只解析一次。
6. **契约符合性检查收窄**：只对 LLM 驱动的方面（语体/结构映射）读回比对；执行器构造上尊重契约，无需检测执行器自身违规。
7. **TOC 域更新需真机首验**：WPS jsapi `TablesOfContents(1).Update()` 镜像 VBA 但未实证，列入 Phase 1 真机清单；失败回退「质检报告标注手动更新」。

### P2 默认值

8. 轮次耗尽照常交付+警示+继续修（沿用 v2.1）。
9. 大模板剖析后台进行，卡片显示进度。
10. 文风预设档位与「跟随模板」互斥显示：勾跟随则档位隐藏。
11. 无执行行为的勾选项（如 doc 表格样式 v1）移出勾选卡，仅在画像区展示。

### 修订后主流程

```
触发 generate-from-template
   ▼ ① 剖析（后台，纯读，画像缓存）
   ▼ ② LLM 计划（大纲/页计划，仍不开副本）
   ▼ ③ 【确认卡 v2：画像摘要 + 大纲 + 要素勾选 + 参数】用户一次确认
   ▼ ④ createFromTemplate 开副本 → 槽位填充（契约约束）→ 质检循环（含契约符合性）
   ▼ ⑤ SaveAs2 交付（TOC 提示 / 警示报告 / 继续修入口）
```

## 九、第二轮审查与修订（v1.4）

### 架构级修正

1. **复用而非拆除两段式机制**：v1.3「planOnly 取消」措辞会导致拆除昨日刚建的计划缓存/execute-template-plan 续跑管线。正确组合：触发 → 后台任务跑剖析+LLM 计划（结果进 lastPlanCache）→ 完成后从 peekLastTemplatePlan() 渲染结构化卡片 → 确认按钮调 execute-template-plan（契约随行）→ 取消清缓存。换交互皮肤，不拆管线。
2. **卡片时序倒置明确化**：单卡是「计划先行」（剖析+大纲 → 才展示），不是 params 表单先行。新组件 `pendingTemplateContractCard` 挂载在后台任务完成态；现有 pendingWpsCapabilityForm 仍服务于其他直接能力。
3. **§7 整合进单卡**：卡片增「素材区」——列出全部附件/路径，逐个带角色标识（版式模板 / 参考素材，可切换）。同 kind 多文件歧义规则：默认第一个同 kind 为版式模板，其余为参考素材，卡片上可改。

### 缺口补齐

4. **序列化约定**：勾选用扁平键（asp_<kind>_<aspect>=true/false）经 executor 组装为嵌套契约对象；buildWpsCapabilityParams 不动。
5. **后台任务生命周期**：剖析+计划任务化（进度可见、可中止）；卡片绑定 taskId；**确认时活动文档 ≠ 触发时活动文档 → 计划作废重跑**（防开错副本上下文）。
6. **降级路径**：剖析失败（损坏/加密文件）→ 任务失败并明确报错；LLM 计划失败 → 自动重试 1 次 → 报「请检查对话模型配置」。

### 一致性修正

7. `sheet 公式区扩展` 标注为 **P2 门控勾选项**（执行器就位前不出现在卡片），消除与 P2 条目的矛盾。
8. 「语体画像置信→预勾」改为「剖析器工作项：语体分类返回置信度」；就位前按「有画像即预勾」。
9. 解析器工作项清单化进差距表：TOC 域检测（docx fldSimple/instrText）、固定文案探测、ppt 目录页型分类、语体置信度。
